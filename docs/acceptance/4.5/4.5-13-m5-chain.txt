4. 可复现性：同一份内容再导一次，hash 不动、快照另起一行
────────────────────────────────────────────────────────────────────
在文档未再改动的前提下第三次调 toPdf：
  { "pages": 1, "bytes": 43871, "hash": "07000b19…", "snapshotId": "d0862c87-36a0-4062-9814-dce2fa28cdd1" }
snapshot.list('resume-0185fba4a2cc') 落库三行（新→旧）：
  d0862c87… hash 07000b19… createdAt 1790932461907
  2102b65d… hash 07000b19… createdAt 1790932125620
  97e12de8… hash 4b73d09a… createdAt 1790932077855
→ 回执里的 `hash` 是**文档内容 hash**（export-service.ts:45 的注释：回写后的文档内容 hash），
  不是 PDF 字节的 sha256。这一点必须写下来，否则后来者会拿 certutil 去核对文件（实测文件
  sha256 = 9f0a9ed0…，与两个 hash 都不同，因为 PDF 里带生成时间与对象 id）。
→ 同内容 → 同 hash、不同 snapshotId：3.7 的"投出去的到底是哪一版"因此在这条链上也是通的。

5. 4.5-01 与 4.5-12 的落点（为什么这两条现在才算过）
────────────────────────────────────────────────────────────────────
4.5-01 的两个判据分别是"校验零错误"和"渲染交 P3 成功"：
  · 前半在 4.5-b 就有单测（generate-service.test.ts:292 起，describe 标题即 spec 4.5-01 / 12）：
    view.document 过 validateDocument(...).ok === true，且 JSON 序列化一圈回来仍是合法文档。
  · 后半"渲染交 P3 成功"以前只有推测——本片是它第一次真的过 P3 的公开渲染入口并拿到 1 页 PDF。
4.5-12 要求"P3/P4 各自校验同一 JSON、不存在私有约定字段"，实测到的三件事合起来就是它：
  · P4 包内没有任何平行的文档 schema（grep z.object/z.strictObject 在 packages/resume-kb 命中的
    全是自己的配置面 / 工具入参 / 备份格式，没有一份"简历文档形状"）。
  · 单测锁住顶层键集合 === documentSchema.shape 的键集合（generate-service.test.ts:304），
    多一个约定字段就红；P3 侧 schema.test.ts:35 锁住 strictObject 拒未知键。
  · 真链路上，accept() 写盘前必经 generate-service.ts:962 的 validated() → P3 的 validateDocument，
    上面那两次"已写入工作副本"能落库，就是这道关放行的。
→ 两条都不需要新代码，只把已有断言与本次真链路读数对上，故按实勾 [x]。

6. 已知限制（不许被这份证据掩盖）
────────────────────────────────────────────────────────────────────
① 导出这一步没有界面按钮可用：ResumePanel 的 preview/export 绑死在 seed.docId（'resume-demo'），
   页面上没有 doc 选择器，所以"KB 工作副本 → 导出"在 4.5 这一版只能经白名单 bridge 调用完成。
   这与 4.5-c 记的"面板无 doc 选择器"是同一条账，收口要等对话入口（工具面产物交给导出工具）
   或补一个 doc 选择器，不在本片偷偷加。
② "PDF 截图"这一项在本机给不出光栅图：没有 pdftoppm（AGENTS.md §9 已记），
   所以沿用 3.3 的取证口径——真实内核 printToPDF 产物 + pdftotext 纯 ASCII 哨兵文本层断言
   （中文字体在打印产物里被子集化，pdftotext 读不出中文，这也是哨兵必须写成 ASCII 的原因），
   外加两张真页面截图。3.3-09 当时留的同样是回执截图，不是 PDF 光栅图。
③ fixture 的改写后缀里那串 `JD-REWRITE-MARK` 是**为这条文本层断言加的**（scripts/fixture-server.ts），
   它不带数字、不带机构名，因此不会触发数值守恒与实体回查——这是替身的一端，不是产品文案。
④ 两次接受之后，知识库的实体与检索读数已经落后于工作副本（界面上那句播报就是这件事）：
   下一轮比对与生成前要先按新内容重新同步一次。

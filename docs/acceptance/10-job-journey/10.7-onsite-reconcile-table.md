## 1. 四方对账表（一行一笔，行键 = `ledger_id`）

**真实 schema（2026-11-23 用 `PRAGMA table_info` 读出，不靠记忆）**：

| 表 | 列 | 在四方里负责 |
| --- | --- | --- |
| `usage_ledger` | `id, action, target_id, workflow_run_id, ts, source, remote_ref` | **那本账**；行键 = `id`，页面回执对比 `remote_ref` |
| `outbound_attempts` | `platform, target_id, action, resume_version, status, ledger_id, receipt_id, reason, confirmed_at` | **四元组只在这里**；用 `ledger_id` 与账本连 |
| `delivery_records` | `ledger_id, platform, job_id, snapshot_id, ts, conversation_target` | 只用来验「deliver 是否有一条对应记录」；**没有 `action` / `resume_version` 两列** |
| 页面 | 会话状态行 / 附件名 / 「已发送」状态行 | 发没发的唯一凭据，对比 `receipt_id` |

**口径（三条，现场不改）**：

1. 一行以 **`ledger_id`** 为主键：先有账行，再用 `outbound_attempts.ledger_id` 找四元组，再用 `delivery_records.ledger_id` 找投递记录（仅 deliver）；
2. **四元组不从 `delivery_records` 取**，它没有 `action`/`resume_version`；
3. 页面回执对的是 `receipt_id`（attempts）/ `remote_ref`（ledger），不是动作返回码。

| # | ledger_id | platform | target（`target_id`） | action | resume_version（从 attempts 取） | 页面回执（时间 + 原文摘录 / receipt_id） | attempts 行（存在？status / receipt_id） | delivery_records（有？行数） | 一致？ | 备注（重放被拒 / 失败未发生等） |
| - | --------- | -------- | --------------------- | ------ | -------------------------------- | ---------------------------------------- | ---------------------------------------- | --------------------------- | ------ | -------------------------------- |
| 1 |  |  |  |  |  |  |  |  |  |  |
| 2 |  |  |  |  |  |  |  |  |  |  |
| 3 |  |  |  |  |  |  |  |  |  |  |
| 4 |  |  |  |  |  |  |  |  |  |  |

**一致性判据（逐行填「一致 / 不一致 + 原因」）**：
1. 账本恰增 1 行 ⇔ 页面有对应回执（`receipt_id`/`remote_ref` 对得上）；`action='deliver'` 时另需 `delivery_records` 恰 1 行且 `ledger_id` 相同；
2. `outbound_attempts` 里同四元组的首笔早于账行、`ledger_id` 指向该账行；重放时 `OUTBOUND_ALREADY_SENT` 且**账本零增行**；
3. 后果判定只用本轮增量；累计数只作交叉核对。

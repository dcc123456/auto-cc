# 10.11-33 逐项复核（QA 独立读数，不是引用开发那轮）

构建 `64061ec`、实例 `ud-onsite4`、CDP 10410、2026-11-23 20:45–20:55 本地。
页面：应用「岗位」页（`[data-view=jobs]`），库里 65 张岗位卡（真站抓取结果，非构造数据）。
**未点投递/打招呼，只做布局读数与弹窗开关。**

## 口径说明（两条必须先说清）

1. **档位**：本机内核视图会用原生视图盖住右栏，所以「1600 / 1024 / 900」三档是用
   `Emulation.setDeviceMetricsOverride` 改**渲染层视口**造的（与开发同法）。它能验网格/弹窗/文案，
   **不能**验原生窗口拖拽（见 `10.11-31-qa-resize-blocked.txt`）。
2. **面板宽度才是断列依据**：网格是容器查询（按这一列自己的宽度断），不是按窗口宽度。
   所以同一窗口宽下，网页视图收起（面板 1342/894/770）与展开（面板 282）列数完全不同。

## ① 平铺网格

| 档 | 面板宽 | 列数 | 卡片宽 | 卡片高分布 | 横向溢出 | 判 |
| --- | --- | --- | --- | --- | --- | --- |
| 1600（视图收起） | 1342 | **4** | 330（65 张全同宽） | **129，65 张全同高** | `sw=cw=1342`，文档 `sw=cw=1600` | 通过 |
| 1024（视图收起） | 894 | **3** | 293（全同宽） | **129，65 张全同高** | `sw=cw=894`，文档 `sw=cw=1024` | 通过 |
| 900（视图收起） | 770 | **3** | 251 | **129×45 张、148×20 张** | `sw=cw=770` | **不等高** |
| 真实窗口 1200（网页视图展开） | 282 | **1** | 282（全同宽） | **129×50 张、148×15 张** | `sw=cw=282` | 1 列 ✓ / **不等高** |

- 「宽窗 3–4 列」成立；「不横向滚动」四个档都成立（`scrollWidth == clientWidth`）。
- 「等宽」成立（同一档内宽度只有一个值）。
- **「等高」不成立**：窄档下 15–20 张卡高 148px，其余 129px（148 的那批是带了额外一行标记的卡）。
  判据原话是「卡片**等宽等高**」，所以这一条按字面**没过**。改法二选一：给卡片统一固定高/行高夹紧，
  或把判据改成「同档内每行等高、跨行可不同」——但要先裁定。
- 「窄窗 1 列」只在**网页视图展开、面板 282** 时成立；窗口拉到 900 但视图收起时是 3 列。
  所以这条判据要写成按面板宽度分档（<340 一列 / <640 两列 / <900 三列 / 其余四列），否则同一份代码两种读法。

卡片内容（首卡实测文本）：`高级前端开发 ｜ -K ｜ 上海南天 ｜ 上海·浦东新区·张江 ｜ 5-10年 ｜ 本科 ｜ 已定制 ｜ 已打招呼 ｜ 已投递 ｜ 已回复 ｜ 点开看详情` —— 岗位名/公司/城市·经验·学历齐。

## ② 状态点：点是真的，但文字在骗人

- 65 张卡 × 4 个点 = **260 个点**，实测背景色只有两种：`rgb(224,220,211)` **258 个（灭）**、`rgb(47,122,91)` **2 个（亮）**。
- 但每张卡上都**恒定渲染四段文字**「已定制 / 已打招呼 / 已投递 / 已回复」（颜色统一 `rgb(125,120,113)`），
  与点的亮灭无关。
- 后果：用户扫卡片读到的是「已投递」，而点却是灭的。**这是把状态写成了标签**，属误导性呈现（P2）。
  要么只在达成时显示文字，要么把未达成的文字改写成「未投递」这类明确表述。

## ③ 弹窗（1024 档）

| 断言 | 读数 |
| --- | --- |
| 点卡片开弹窗（不是跳页/侧滑） | `opened:true`，弹窗 960×367，标题 `高级前端开发`，页面 URL 未变 |
| 三个动作入口 | 弹窗内 `data-action` 共 5 个：`jd-detail-close`、`jd-open-page`、`jd-generate-resume-row`、`greet-53f043f9…`、`deliver-53f043f9…` → 定制/打招呼/投递三个入口都在 |
| 完整 JD | 弹窗文本长度 471 字（含摘要与说明）；此库这 65 条多为「只抓到摘要」，所以「完整 JD」在这批数据上**证不了**，只能说弹窗有 JD 文本区 |
| 匹配理由 | 命中「匹配/命中/取回」字样，但读原文是「这一屏按你的筛选条件取回：…」——这是**筛选条件复述**，不是判据要的「匹配理由」。按字面未满足，需裁定：补真实理由，或把判据改成「取回条件说明」 |

## ④ 三条关闭路径 + 焦点回位

| 关闭路径 | 弹窗是否关掉 | `document.activeElement` |
| --- | --- | --- |
| `Esc` | 是 | 回到原卡片 `jd-card-53f043f9…` |
| 点遮罩（`fixed inset-0 z-40 bg-scrim`） | 是 | 回到原卡片 `jd-card-53f043f9…` |
| 关闭按钮 `data-action=jd-detail-close` | 是 | 回到原卡片 `jd-card-53f043f9…` |

- **口径提醒（不是缺陷）**：焦点回位只在「打开前卡片确实拿到焦点」时成立。纯脚本 `card.click()` 不产生焦点，
  那种驱动方式下读数会是 `BODY`；用 `card.focus()` 再点、或真实鼠标点击，三次都回到原卡片。判这条必须带聚焦动作。
- 实测序列：`preFocus=jd-card-53f043f9…` → 打开 → `Esc` → `afterEsc=jd-card-53f043f9…`。

## ⑥ i18n：**发现一处可见裸 key（P1）**

```
可见：jd.filterLabel.experience     ← 岗位页筛选输入框的 label 直接显示这串
不可见：jd.capture.run / jd.store.list  ← 在未激活视图里，mono 字体的技术名，本轮不判
```

- 成因：`packages/renderer/src/JobLabPanel.tsx:832` 用 `t(\`jd.filterLabel.${filter.dimension}\`)` **动态拼 key**，
  而 `packages/renderer/src/locales/zh-CN.json` 的 `jd.filterLabel` 只有
  `district / degree / salary / scale / jobType / stage / industry` **七个**，**没有 `experience`**（`en.json` 同缺）。
- 为什么四门禁没拦住：静态 key 校验扫不到「拼出来的 key」，而缺翻译时 i18next 原样回吐 key，
  于是一条 `jd.filterLabel.experience` 就渲染到用户眼前。10.11-20 那次判绿的扫描器只比对「文本里出现了语言包里存在的 key」，
  **缺的 key 不在语言包里，所以扫不出来**——扫描口径要补一条：「看起来像 key 但语言包里查不到」也要报。
- 同类风险（未实测、只作提示）：语言包里也没有 `city` / `position` 这两维的 label 键，服务若返回这两个 dimension 会同形。

## 逐项结论

| 子项 | 判 |
| --- | --- |
| ① 3–4 列 / 不横向滚动 / 等宽 | 通过 |
| ① 等高 | **不通过**（窄档 148×15–20 张） |
| ① 窄窗 1 列 | 口径依赖面板宽度，**需写成按面板分档** |
| ② 状态点存在 | 通过（点是真的两态） |
| ② 状态文字 | **误导**（四段恒显示） |
| ③ 三个动作入口 | 通过 |
| ③ 匹配理由 | **按字面未满足**（是筛选条件复述） |
| ④ 三条关闭路径 + 焦点回位 | 通过（带聚焦前提） |
| ⑤ 铺满 | 通过；**可滚未证** |
| ⑥ 无裸 key | **不通过**（`jd.filterLabel.experience`） |

**所以 33 本轮不能判 `[x]`**：卡在 ⑥（可见裸 key，最小修复：补 `jd.filterLabel.experience` 两语言 +
把扫描口径补成「key-like 且语言包里没有也报」）、①（等高或改判据）、③（匹配理由措辞）、⑤（可滚未证）。

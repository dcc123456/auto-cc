# 10.11-32 恢复出口复验（`2f121e6`）：两条出口都通；但**首次启动/重启后打不开网页窗口**（新 P1）

## 二、新 P1：**重启之后打不开网页窗口（首次启动同样）**

同一次启动、还没走过任何导航时的读数：

| 动作 | `visible` | `url` | `partition` | 地址栏输入框 |
| --- | --- | --- | --- | --- |
| 启动后初始态 | false | placeholder（`data:`） | `""` | 不存在 |
| 点顶栏「展开网页窗口」 | **false（没变）** | placeholder | `""` | **仍不存在** |
| 再点一次 | false | placeholder | `""` | 不存在 |

成因（代码级）：

```tsx
// packages/renderer/src/KernelCanvasSlot.tsx:200-208
onClick={() => { … 
  if (!visible) { …
    const hasView = status.value.kernelViewPartition !== '';
    await (hasView ? bridge.shell.setKernelViewVisible(true) : bridge.shell.recoverKernelView());
```

```ts
// packages/shell/src/index.ts:816-822
recoverKernelView = (): ShellStatus => {
  const url = this.lastKernelUrl;
  const partition = this.lastKernelPartition;
  if (url === '' || partition === '') { this.ctx.logger.warn('没有可回去的地址：不重建…'); return this.getStatus(); }
```

- 启动时 `kernelViewPartition` 是 `''`（占位视图不挂会话），所以走 `recoverKernelView()`；
- 而 `lastKernelUrl` / `lastKernelPartition` 是**进程内**记的，刚启动时都是空的 → 该函数直接 `return`，什么都不做；
- 于是 `visible` 永远进不去 true，`App.tsx:426` 的可见性条件不成立，**地址栏连带「输网址」那条能力一起不可达**。

**影响面**：
1. 每次启动/重启后，用户没有任何办法主动打开内嵌浏览器（除非先走抓取、打开岗位详情这类会自己导航的流程）；
2. `10.11-27/29`（无会话时手输网址、自动建 `persist:browser` 会话）那条已验证过的能力，从界面入口上被切断；
3. 上一轮修的「按钮够不着」在这一条上**换了个位置重现**：出口是常驻的，但它在「没有历史地址」这件事上不干活。

**改法（任一条，最小改动是第一条）**：
1. `KernelCanvasSlot.tsx:206` 那个分支再分一层：`partition === ''` 且 `lastKernelUrl === ''` 时**退回 `setKernelViewVisible(true)`**（显示占位视图 + 地址栏，用户就能输网址）；
2. 或让 `recoverKernelView()` 在没有历史地址时也**建一个占位视图**（`createKernelView()` 无参），把「没有可回去的地址」变成「回到空白页」；
3. 或让顶栏键在无视图时直接 `sessions.ensureBrowser()` + 打开一个默认入口页（改动更大，不推荐）。

判据：重启后点顶栏键 → `visible:true`、地址栏出现、输入 `http://127.0.0.1:10233/boss` 能导航过去。

## 三、结论

- 恢复出口：**通过**（顶栏键 + toast 按钮两条，点完回原 URL、`recoveries` 归 0、无幽灵可见态）。
- 首次启动/重启入口：**不通过（新 P1）**。

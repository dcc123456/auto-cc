## 3. 我为什么没把投递走完（如实说明，不绕过）

- 干净实例里唯一的平台是真实 BOSS（`https://www.zhipin.com/`），**未登录**。群规与 AGENTS §7.2 都要求真实平台只由用户在场手动验证，自动化不得访问；所以"按意向搜岗""搜索并入库"我**一个都没点**。
- 后果：搜岗 → 选岗 → 定制 → 授权 → 投递 → 追踪 → 统计，这五步在本次干净实例上**没有活体读数**。这不是我偷懒，是产品现状：一个没有 BOSS 账号、没有模型密钥的新用户，走到第 9 步就再也推不动，且界面上没有"接下来要登录"的指路。
- 本次能作证的是"前半程 + 各处空态 + 每一处按钮的可点/禁用状态与原因"（见 `10.9-01-readings.txt` 的机器读数）。

## 4. 做得好的地方（客观）

1. 隐私声明把"资料放哪、什么时候出网、简历什么时候才会真发"讲清了，而且和界面上的闸门口径对得上（唯一对不上的是"默认档位"那句，见 K1）。
2. 统计页明写"这段时间库里一条记录都没有……这里的 0 是「还没发生」，不是转化率为 0"——这句我会信。
3. 空状态大多带下一步（"先挑一行岗位，再生成话术""JD 库还是空的：先在上面的抓取面板跑一轮"）。
4. "这一步到底怎么走？"就地展开五步："查额度 → 等频控 → 要你点头 → 到页面上真点一次 → 记一行账"，看完我知道它在防什么。
5. "一键停用"就贴在授权卡右上角，和"收回授权"并排——这是我唯一一眼就敢点的危险动作。
6. 深色主题、中英切换是一键的，不用进设置翻。

## 5. 如果只能先改 3 条（我的排序）

1. **K3 把"读取求职意向"的缺口补成能填的中文格子**（期望岗位/城市/薪资/到岗时间 + 一键"去登录 BOSS"），否则整条主链对没有账号的人就是死的。
2. **K2 修"导入后到处看不到"**：简历导入成功即成为母版，所有面板立刻可见；禁用的按钮旁边直接写可点的下一步。
3. **K1 拆掉第一入口的三重门**：别让"聊天"先要签全自动，别把"没配模型"藏成禁用箭头——给出"先打字 → 提示配模型 → 一键去配"的顺序。

10.11-30 改造第 ③ 步（未登记来源的写动作闸口 + 来源标记）与第 ④ 步（web 模式表面退役）（2026-11-22）

背景：QA 第 ⑥ 条在 `37e3271` 上不通过——未登记来源页面上的点击真的执行了（`__qaClicks` 0→1→2），
`agent.pause.pending()` 全程 0。原因写实：第 ② 步只放开了导航，唯一的动作闸门仍是旧的
`kernelViewMode === 'web'` 只读判定，而合并分区后未登记页面归 `platform`，那道闸根本不触发。

【③ 动作闸口】
① 判据面：`platform.registry.isRegisteredOrigin(origin)`（新增）——归一化到 `URL.origin` 后
   与各适配器 `meta.origins` 比；登记表为空或地址解析不了**恒 false**（判不准就不认）。
   真源清单是知识包的 `origins`（不是 `sessions` 的 `startUrl`：一个平台常有登录域与主域两个源）。
② 闸口位置：`browser.act` 服务层，`perform()`（click / type / select）与 `upload()` 取到视图之后、
   等待与定位之前。判的是**顶层页面**的源（`contents.getURL()`）——用户眼前那块页面才是信任单元，
   已登记站点内嵌的第三方帧仍属于这次访问；未登记页面里的任何一帧都不许动手。
③ 拒绝形状：`WRITE_ORIGIN_UNREGISTERED`，details = `{ url, action, origin }`，人读原话里直接写
   「助手不在上面做「click」，一个动作都没有派发」。**拒绝时一个脚本都不发**，所以页面自记的动作计数必然为 0。
④ 覆盖范围：渲染层直调、工作流节点、外发适配器走的都是同一道闸（闸在服务里，不查「谁在调」，
   只查「脚下这块页面是谁的」）。

【③ 的行为变化：比用户裁定更严，这条要 PMO 裁】
用户裁定的口径是「未登记来源的写动作要**先问一次**，确认才做」。当前落地是**一律不执行**：
拒绝时连确认卡都不开。原因不是省事，而是**没有不可伪造的批准凭据**：
- `agent.pause` 的确认单以「run 里的某一步」为单位（载荷有 runId / planStepIndex / toolId），
  循环之外（渲染层直调、工作流节点）开不出这张单；
- 若把「已批准」做成工具入参里的一位，那它来自模型草案，等于让模型给自己放行（5.3-04 防的正是这个）；
- 若做成服务层的第二个布尔参数，任何调用方都能填 true，闸门就只剩装饰。
因此本轮选择 fail-closed，并把「确认后放行」留给一次契约决定（要么给 agent 工具调用加一层
不可伪造的执行上下文，要么给 `agent.pause` 加一个按来源记账的批准口）。QA 的负对照 ④「确认后放行」
因此**当前无法通过**，不是没跑。

【③ 来源标记（QA 第 ② 条：未登记页面的文字不得驱动已登记来源上的写动作）】
① 实施点：`agent.loop`。每步工具**成功返回**之后看读数里的地址（`url` / `frames[].url`），
   落在未登记来源上就给这条 run 打 `untrustedPageRead`。
② 生效方式：此后每一步 `effect !== 'read'` 的步骤，即便策略已经放行（`auto` 档「不再逐步确认」），
   也会被升级成一次确认（`CONFIRMATION_REQUIRED` → 既有 `agent.pause` 卡片），卡上写明
   「这条任务已经读过未登记来源页面的内容（页面里的文字不等于你的指令）」。
③ 为什么判「读过什么」而不判「此刻在哪」：注入文本可以指使助手先导航到已登记平台再动手，
   那一刻脚下页面合法、闸口放行，而驱使它的是上一页读进来的字。
④ 边界（写实）：标记只活在内存里的 run 作用域上；服务被重建（改配置 / 重启）后这条 run 本来也不在跑，
   重建出来的作用域不带标记——丢的方向是「回到普通档位规则」，不是「自动放行」。
   登记处缺席时按「判不出 ⇒ 都算未登记」处理（方向是多问一句）。

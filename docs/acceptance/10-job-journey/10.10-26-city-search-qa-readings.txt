### 窗口不可见闸 —— **在最终包上退化了（新缺陷，P1）**

同一实例把应用隐藏（`System Events … set visible … to false`）后实读 `document.visibilityState = "hidden"`，半自动档对 `1001` 调同一只口：

```
code:    OUTBOUND_NOT_DELIVERED
message: 点击后 5269ms 内状态行没有变化：请先打开附件菜单，再登记这一版简历
details: { "targetId": "1001" }
```

**没有抛 `OUTBOUND_WINDOW_NOT_VISIBLE`，并且落了一条脏行**：

```
outbound_attempts: [{ id:1, target_id:"1001", action:"deliver", status:"unknown", ledger_id:null, reason:"OUTBOUND_NOT_DELIVERED" }]
usage_ledger 1（未增） / delivery_records 0
```

根因（代码读数，`aa0da04`）：闸的条件是 `!hostStatus.windowVisible || !hostStatus.kernelViewVisible`，而 `windowVisible` 来自 `packages/shell/src/index.ts:188` 的 `win?.isVisible()`。macOS 上把应用 `hidden`（或窗口被完全遮挡）时，**`BrowserWindow.isVisible()` 仍返回 true**，而页面自己的 `document.visibilityState` 已经是 `hidden`；本实例里内核会话是开着的（`kernelViewVisible=true`），于是两个条件都不成立，闸不触发 → 页面点击不落页 → 留下 `unknown` 脏行。

这与「防脏数据」的初衷相反：旧包路径（350cfd1）在同样 hidden 场景下是拒得住的（`details {windowVisible:false,kernelViewVisible:false}`，零 attempt），因为那一次内核会话没开、`kernelViewVisible` 为 false 才拦下。**结论：闸的判据应看页面 `visibilityState`（或加内核视图可见性），不能只看 `BrowserWindow.isVisible()`。**

**关键发现：param 名与取值码在静止 DOM 里读不到（这是结论，不是没查）**

1. 筛选项全是 `li`（例如 `li[ka=sel-business-0]`），**没有 `href`、也没有 `data-value`**——只有展示文字。
2. 整页含 `/web/geek/jobs` 的锚点只有 1 个（导航「职位」）；
   城市/行业那两块的 146 / 145 个锚点是**岗位卡片**，它们的参数只有 `from / id / pcSource / recordcode / securityId / type`，
   与筛选无关（`allParamKeys` 全集就是这 6 个）。
3. 页面没有 `__INITIAL_STATE__ / __NUXT__ / __NEXT_DATA__ / __APP_STATE__` 这类初始化数据（全 `undefined`）；
   8 段内联脚本里也搜不到 `salary / experience / degree / scale / stage / jobType / industry` 的取值表。
4. 因此**要拿到 param 名与取值码，只能让 URL 变一次**（人点一下某栏某个选项）。
   点击属于「真实页面操作」，按 plan §14.19 不代做；用户当轮也未点。**所以这一列我留空，不猜。**

**顺带修掉的一处真缺陷（本轮唯一代码改动）**

`packages/platform-boss/src/adapter.ts` 的 `searchUrl()` 原先写的是「包里没登记参数名时，这一维就不进 URL」——
而真站包 `boss.json` 的 `search.params` 只有 `query` 与 `city`，于是**界面传了 `experience` 也被静默丢弃**：
界面显示「按 3-5 年筛」，页面其实没筛。这与 10.11-32 判据里那条「传 BOSS 上不存在的取值必须给结构化拒绝，
不许静默丢弃」直接冲突。改为：传了没声明的维度就抛 `SEARCH_FILTER_UNSUPPORTED`（带 `filter / value / platform`），
并且**一次导航都不发生**。新增错误码进 `AppErrorCode`；用例两条（真站包传经验 → 拒绝且零导航；只给关键词 →
仍只带 `query`）。

**门禁**：`pnpm typecheck` → `TYPECHECK_EXIT=0`；`pnpm lint` → `LINT_EXIT=0`；`pnpm format:check` → `FORMAT_EXIT=0`；
`pnpm test` → `TEST_EXIT=0`，**2806 例全过**（`@auto-cc/plugin-platform-boss` 194 例）。

**下一步要什么（交给 PMO 定）**
① 若要补齐 param 映射，需要**每栏一次**真实点击后的地址栏 URL（或同意让 QA 在只读监听下点一次，
点击仍归用户/QA 的页面操作通道，不由开发代做）；
② 在那之前，界面与入参里**只能保留已证明能发的维度**（当前是 `query`、`city`——`city` 的码表也只有上海一条），
其余维度按上面的结构化拒绝走，不做「看起来能筛」的控件。

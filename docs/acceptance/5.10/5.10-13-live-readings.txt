5.10-13（V）DAG 下重验 2.4-05/06：kill 后从中断节点继续、已完成不重放、外发幂等仍成立并留新证据 · 2026-10-05（本机 macOS，dev 实例）

一、真的 kill 过一次
  run 24ea63b2-381e-4273-b6db-aa4e5af48fd6 跑到 `flaky-3` 那一格（库里 `running` / attempts=1）时把 dev 主进程 kill 掉。
  重启后 `workflow_runs.status` 由 `[Service.init]` 的 `markInterrupted` 判成 **`interrupted`**（`node tmp/…/dump.js` 读数），
  界面上第一次读数没有把它显示成"仍在运行"。这一步是 2.4-05 那条判据在 DAG 上的重现，通过。

二、但那条被 kill 的 run 在界面上**续不起来**——这是本片取证据时撞到的真缺口（不是环境问题）
  重启后 runner 的「当前计划」回到 `config.planId`（内置那条），而画布保存过的自定义计划只有 `runner.start(planId)`
  会切换（`packages/workflow/src/index.ts:488`），那颗按钮同时**必然开一条新 run**；面板上的计划下拉只改渲染层本地
  state（`WorkflowPanel.tsx:69 / 153 / 213`），从不告诉主进程"当前计划是它"。于是 `resumable()` / `resumeRun()`
  读的是另一条计划的指纹，那条 `interrupted` 的 DAG run 在界面上没有任何入口能续。
  `resumeRun` 的注释（index.ts:703 起）写的"续自定义计划的 run，得先把当前计划换成那条（面板的下拉，5.4-b 的入口）"
  这条路径**在下拉上并不成立**——它只在"同一个进程里已经点过一次开始"之后成立。
  → 记为待裁条目 5.10-j（本 spec 的 5.10-j 小节 / 任务清单 #9），本片不自行改产品行为。

    续跑跑完    步骤 6 格已完成 + `7 · jd-list-draft-2 已跳过`；库里 `flaky-2` attempts 1→2（**被停住那一格重新执行**）

# 1.2-11 Electron 二进制就位方式（结论与上游行为变更有关，不能按原假设打勾）

## 实测事实

1. `electron@44.4.5` 的 `package.json` **没有 `install` / `postinstall` 脚本**，改为暴露一个可执行 bin：

   ```
   "bin": { "electron": "cli.js", "install-electron": "install.js" }
   ```

   即 Electron 44 起「装完自动下载二进制」不再成立，需要显式调用 `install.js`（脚本自身幂等：
   `isInstalled()` 命中就直接 `exit 0`）。
2. 因此 `onlyBuiltDependencies` 里已经列出的 `electron`（`pnpm-workspace.yaml`）**不起作用**——
   它放行的是一个已经不存在的构建脚本，不是二进制下载本身。之前把它当作根因是误判，已更正。

## 采取的项目级修复

- `package.json` → `"postinstall": "node packages/main/node_modules/electron/install.js"`
  （`packages/main` 是 electron 的唯一宿主，`.npmrc` 里的 `electron_mirror` 由 install.js 读取；
  根 `postinstall` 在本环境能跑，因为 `.npmrc` 设了 `enable-pre-post-scripts=true`）

验证：`node packages/main/node_modules/electron/install.js` 退出码 0（已就位 → 幂等 no-op），
`dist/electron.exe --version` → `v44.4.5`。

## 为什么这一项标 [!] 而不是 [x]

验收原文假设「`pnpm install` 自动就位、不需要手动 `node install.js`」。在 Electron 44 下这个假设本身
已失效，现在靠项目自己的 `postinstall` 钩子达成同等效果；但**本沙箱环境无法端到端验证这条新链路**：
`install.js` 走 `@electron/get`，除二进制 zip 外还要抓 `SHASUMS256.txt` 做校验，而该请求在这里
`TypeError: fetch failed`。当前可用的二进制是从本地缓存按 `checksums.json` 校验后手工解出的。
带网络的干净机器上（`git clone` → `pnpm install`）这条钩子应当自动完成，需要在有网环境复验一次。

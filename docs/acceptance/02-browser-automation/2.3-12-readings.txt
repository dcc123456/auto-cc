一、改动前的那条失败（用户现场）
  jd.capture.run 直接调用，内核视图为空 → NO_KERNEL_SESSION：
  「内核视图尚未挂载任何平台，先打开一个会话再操作页面」。

二、挂载前读数
  jd.capture.status() = { platform: 'boss', platforms: ['boss'], targetCount: 20, maxRounds: 8, lastRun: null }
  sessions.status()   = { activePlatform: null, platforms: ['boss'] }
  ► 只有一个可抓取平台，界面不渲染平台选择器（data-testid=jd-platform-picker 不存在）。

三、点「搜索并入库」之后
  第一次关键词「前端agent 工程师」：
    activePlatform = 'boss'                ← 自动挂载成功，未再报 NO_KERNEL_SESSION
    lastRun = { platform: 'boss', keyword: '前端agent 工程师', rounds: 1, containers: 0,
                stored: 0, stoppedBy: 'no-new-content' }
    说明：fixture 按关键词过滤，这个词在仿站里没有岗位，0 条是站点数据的结果，不是挂载失败。

四、多平台那一半的状态
  当前装配只有 boss 一家平台包（platform.registry 里就一份），多平台选择器无法在活体上取出。
  该分支由单测钉住：packages/renderer/src/platform-choice.test.ts
    - platforms.length <= 1 → 不摆选择器、直接挂载
    - platforms.length > 1  → 摆选择器；人选的优先，旧选择失效落回默认，默认也不在清单时退到第一条
  待 8.9 猎聘第二家平台包到场后，用同一脚本补一张多平台下拉的活体截图。

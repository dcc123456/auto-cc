【5】验收过程中的两处更正（都不是产品缺陷，记下来免得下次重踩）
  a) 视图切换要用 `[data-view="workflow"]` / `[data-view="diagnostics"]`：`button:nth-of-type(2)` 点得到节点但页面不换，
     于是确认单一直是 0x0 的隐藏节点，点了没反应。三个视图是 `hidden` 类切换、不卸载（App.tsx:85 注释），
     所以切走再回来时对话卡片与滚动位置都还在。
  b) 在 Git Bash 里给 harness 传 `/tool` 会被 MSYS 改成 `D:/daiwenchi/Git/tool`，
     必须 `export MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL='*'`。
     顺带反向验证了前缀规则是字面匹配：那条被改写的消息没有生成工具卡片，只走了普通回复。

【6】与 2.8-01 面板状态的关系（诚实说明）
  这一片的工具调用都不建工作流 run（`jd.capture.run` / `outbound.deliver.perform` 走的是工具面直调，
  不经过 `workflow.runner`），所以镜像位全程是「同一个 runner：未开始」——它和卡片不矛盾：
  卡片说的是**这次工具调用**的状态，面板说的是**runner**的状态。
  「对话发起 → 面板跟着动」这条判据要由 2.8-11（人工接管后重读 DOM）与 2.8-07（boss-e2e 全链路）来验，
  那两条走的是 `workflow.runner.start`，会有真正的 run 状态可对照。

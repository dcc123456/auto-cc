四条各守一种失效模式（前两条判"没扣"，第三条判"落账口是活的"，第四条判"符合配置"）：
  1) mode:'daily' 且三键上限都取 1，当天先用 gate.perform('search') 落到见底，
     gate.check('search') 读数 { allowed:false, remaining:0 } —— 此时 kb.gap.report() 仍产出
     整份报告（rows.length>0、counts.missing===rows.length、modelStatus==='unavailable'），
     且 usage_ledger 行数一分不多。**这条是正向证明**：报告路径若在任何一处问了闸门，
     就会在这里收到 QUOTA_EXCEEDED 而炸掉，比"断言源码里没写 perform"强。
  2) agent 工具面入口（tools.call('kb.gap.report')，经真注册表的 z.strictObject safeParse）同样不落账。
  3) 正向对照：同一份装配里 gate.perform('greet') 确实多出第二行（ledgerId>0），
     之后 check('greet').allowed === false —— 证明第 1/2 条的"行数不变"是没被调用，不是调用不生效。
  4) 配置语义对照：mode:'unlimited' 下 check('deliver') 恒为 { allowed:true, remaining:null, reason:null }，
     报告同样不落账。"符合配置"要有第二个配置值才成立。

账本行数是直接对共享的 node:sqlite 连接数 `SELECT COUNT(*) FROM usage_ledger`，不是读服务自报的计数。
库是空的（挂了 kb.profile 但没同步简历）：本片判的是接线，比对读数质量已由 4.4-c 的真库用例断过。

[4] §7.2 机检的运行面：harness 导航前的 loopback 守卫
----------------------------------------------------
$ cd packages/testing && npx vitest run src/cdp.test.ts

   ✓ src/cdp.test.ts (12 tests) 3ms

   Test Files  1 passed (1)
        Tests  12 passed (12)

`CdpSession.navigate(url)` 在发出第一条 CDP 命令之前判 `localTestUrlViolation(url)`，非本地即抛错
（`Page.navigate` 一旦送达，浏览器已经把请求发出去了，再判就晚）。守卫放在 `send` 之前这件事本身
也有一条结构断言兜住——顺序错就等于守卫形同虚设。
放行：127.0.0.1 / localhost / [::1] / file:（开本机产物）；大小写不敏感。
拒绝：远端主机（含 localhost.attacker.example 这类后缀混淆——判定按整个主机名而非 startsWith）、
非本地协议（javascript: / data:）、判不出主机的写法（相对地址与 //host 形态）。
用例里的"远端主机"一律取 RFC 保留名（embed.test.invalid / job.example）：它们公网不可达，
同时又能让规则三放行——保留名恰好是"既出不了网、又能被判成非本地"的那一类。
唯一调用点核对：`packages/testing/src/cli.ts:144`（harness open --to <url>）；
`packages/platform-boss` 里的 `page.navigate` 是内核页接口、属生产路径，不经这道守卫（§0 判据一）。

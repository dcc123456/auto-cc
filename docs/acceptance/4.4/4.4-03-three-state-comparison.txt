4.4-03 验收证据 · 三态比对：命中 / 部分命中 / 缺失，每项附证据实体 id（2026-10-02，切片 4.4-c）
==============================================================================

条目原文：三态比对：命中 / 部分命中 / 缺失，每项都附证据实体 id（U 类，判据"断言三态与引用"）。

结论先说：`[x]`。四类要求各用各的尺子（不是共用一个相似度），三态与证据 id 在单测与真实装配
两层都拿到读数；「今天」是显式入参，所以跨年重跑不会变结论（4.4-07 的全链判据见第 4 节）。


【0】判据一为什么是"四把尺子"而不是"一把尺子"（设计口径，写代码前定在 plan §4.4-c）
------------------------------------------------------------------------------
`coverageOf` 是 4.2-c 的分词覆盖率打分，它对"词"有效，对另外两类要求天生无效：

- `experience_years`：JD 写「3 年以上经验」，库里写「2021.07-2024.06 后端开发」，两边**零共同 token**。
  拿词面尺子量只会得到 0 分 → 假"缺失"。所以年限走**月区间合并后的算术**：
  `monthSpanOf`（4.1-a 已有的解析）→ 夹取「至今」→ 合并重叠 → 总月数 ÷ 12 与 JD 要求的年数比。
- `education`：4.2 裁定二明确"学历不产实体行"，库里那条是 `kb_chunks` 的 section 切片。
  所以学历走**档位比较**（`EDUCATION_TIERS`：大专 1 / 本科 2 · 学士 2 / 硕士 3 / 研究生 3 / 博士 4），
  证据 `origin` 是 `section_chunk` 而不是 `entity`——这条是"证据 id 指向真实存在的行"的判据要卡住的点。
- `hard_skill` / `soft_skill`：仍是 `coverageOf` 的 token 覆盖，本文件**不新增任何相似度算法**。
- 档位表外的学历 label（模型腿会产出「中专」这类）：**退回文本反查**，不猜一档。

三态的分界（全部来自 `cordis.yml` 的 `kb-gap` 段，不在代码里写死）：
`score ≥ evidenceHitMinScore(0.62)` → matched；`≥ evidencePartialMinScore(0.3)` → partial；否则 missing。
年限用 `yearsPartialRatio(0.6)`：够到要求的 60% 算 partial。
每条非 missing 的行带 `evidence[]`，元素形状是 `{ id, origin, score, matchedTokens }`，
`id` 直接是 `kb_entities.entity_id` 或 `kb_chunks.chunk_id`——4.4-05 的证据链跳转要的就是这个串。

阈值那一条是"参数进配置"的反证：同一份输入只动 `evidenceHitMinScore`，matched 全部退成 partial，
说明分界不是写在 if 里的常数。缺失那条反过来卡的是另一个方向——宁可空证据也不圆场，
因为 4.4-06 要的是"缺失项给补救建议"，而不是"给一条勉强沾边的证据把它说成部分命中"。

读数里三件事值得单独记：

1. 学历那条的证据 id 是 `kbs-` 前缀的切片 id，不是 `kb-` 开头的实体 id，`origin` 报 `section_chunk`。
   这是 4.2 裁定二（学历不产实体行）在比对层的直接体现，也是"每项都附证据实体 id"这句话
   必须按 origin 区分才能兑现的地方。
2. 年限那条的 best=0.5625 是**词面尺子的读数**（JD 与实体文本的 token 覆盖），但它判 matched
   用的是算术：64 月 ÷ 12 ≈ 5.33 年 ≥ 要求的 3 年。`score` 字段在年限行上只作展示，
   状态由 `compareByYears` 定——这正是判据一要防的"假读数"。
3. 两段经历 2021.07-2024.06 与 2024.07-至今 首尾相接，合并成一段连续区间得 64 月；
   「至今」夹到 `nowMonth`（由 `report()` 的 `nowMs` 换算，函数内部不读时钟）。
   单测里同一份区间在 `nowMonth` 换成 2026-10 与更早一个月时给出 92 / 28 两个结果，
   分别落 matched 与 missing，见「『至今』夹到入参的 nowMonth：换一个月就换一个结论，函数内部不读时钟」。

服务层还各有一条用例把这三态钉在真库上（`gap-service.test.ts`，verbose 名）：

 ✓ kb.gap.report 的三态比对与反向比对（spec 4.4-03 / 4.4-04 / 4.4-07） > 每条实体证据都能从库里原样读回，三态计数与行数对得上
 ✓ kb.gap.report 的三态比对与反向比对（spec 4.4-03 / 4.4-04 / 4.4-07） > 年限腿在真库上走算术：首尾相接的两段合并成一段，换算成年后判命中
 ✓ kb.gap.report 的三态比对与反向比对（spec 4.4-03 / 4.4-04 / 4.4-07） > 学历腿从区块切片取档位，证据 id 落在切片而不是实体上（4.2 裁定二）

第一条里"从库里原样读回"是把 `evidence.id` 逐个喂给 `kb.profile.get` / `listChunks` 结果比对文本，
不是只看 id 长得像——id 拼错、指向已删行这类问题只有这条路能发现。


【3】库缺席时的行为（与模型腿的可选形成对照）
------------------------------------------------------------------------------
 ✓ kb.gap.report 的三态比对与反向比对（spec 4.4-03 / 4.4-04 / 4.4-07） > 库里没有 kb.profile 时结构化失败：报告没有可比对象，而不是给一份全缺失的假报告

实测：`npx tsx` 装配里摘掉 `kb.profile` 后 `report()` 抛
`AppError('KB_LIBRARY_MISSING', '知识库服务 kb.profile 未装配：缺口报告没有可比的对象')`，
消息里含 JD 正文 = **false**（错误路径同样脱敏）。
模型腿缺席只降级（`unavailable`），比对腿缺席必须失败：前者没有还能出词面基线，
后者没有就没有可比对象，报一份"全缺失"是把"库里没东西"说成"你不行"。


【4】4.4-07 的全链复跑（本片新增的半边）
------------------------------------------------------------------------------
拆解腿的确定性在 4.4-a 已验（同一 JD 连跑三次 sha256 逐字相同）。本片要补的是**比对腿 + 全链**：

 ✓ 比对层的确定性（spec 4.4-07 的比对半边） > 同一输入两次运行的 hash 逐字相同
 ✓ 比对层的确定性（spec 4.4-07 的比对半边） > 与实体、学历切片的传入次序无关：证据同分时的次序由 id 定死
 ✓ 学历腿的档位比较与退回文本（spec 4.4-03） > 并列取 id 最小的那条切片：与传入顺序无关（4.4-07）
 ✓ kb.gap.report 的三态比对与反向比对（spec 4.4-03 / 4.4-04 / 4.4-07） > 同一 JD + 同一库连跑两次，整份报告的 hash 逐字相同（4.4-07 的全链判据）

  第 1 次 260f1b58202d4e44aa8e9e469a3f207b07c4e6a454e4e6bfec79ef750c25b1ff

4.4-06 验收证据 · 报告不得只输出负面结论（2026-10-02，切片 4.4-c）
==============================================================================

条目原文：报告不得只输出负面结论（缺失项必须同时给出可用证据或补救建议）（C 类，
判据"输出结构断言：缺失项必带 suggestion 字段"）。

结论：`[x]`。判据做成**结构断言**而不是内容断言：每一行 `state !== 'matched'` 的比对结果
必须带 `suggestion`，且 `suggestion` 只有 i18n key 与参数、没有拼好的中文句子。


【0】为什么做成"只有 key"（§5.5 / §5.7 在 service 层的兑现方式）
------------------------------------------------------------------------------
缺口报告是**负面结论的集中产出地**。如果服务直接把「你还缺 Flink」这种句子过 IPC 推给界面，
三件事会同时坏掉：

- §5.5：页面上出现的每一条文案都必须走 i18n。服务端拼好的中文句子是**裸文案**，
  它绕开语言包，`en` 用户拿到的是中文，而且机检脚本扫不到它（它不在 JSX 里）。
- §5.7：动态值要用插值参数，不同语言语序不同。「差 2 年」与「2 years short」不是同一套拼接。
- 4.4-05 的界面要按三态分栏渲染同一批行，若句子已经拼死，界面只能照抄，
  没法在"缺证据"和"差年限"之间用不同的视觉权重。

所以本片把补救建议做成 `{ key: GapSuggestionKey, params: Record<string, …> }`，
渲染层拿 key 去语言包取模板、用 params 填充。key 的集合是导出的常量，
下一片加文案时**必须**逐一对上，加不出来的那条会在用例里红。


【1】五个 key 与它们各自的产出条件
------------------------------------------------------------------------------
`GAP_SUGGESTION_KEYS`（packages/resume-kb/src/requirements-compare.ts:53）：

| key                | 何时给                          | params                                        |
| ------------------ | ------------------------------- | --------------------------------------------- |
| `add_evidence`     | 技能类 missing（库里没有这个词） | `label`                                       |
| `strengthen_evidence` | 技能类 partial（沾上了一部分） | `label`、`evidenceId`（用哪条证据去改写）      |
| `years_gap`        | 年限不够                        | `required`、`haveYears`；库里无时间段时 `noPeriod` |
| `education_gap`    | 学历低一档 / 低两档             | `requiredLabel`、`haveRank`（差几档由界面算） |
| `education_missing`| 库里根本没有学历区块            | `label`（"无据"而不是"差一点"）               |

两条刻意的区分：
- partial 给的是 `strengthen_evidence` 并**带 `evidenceId`**——部分命中意味着库里有可用的料，
  建议是"把它写得更实"，指向那条证据；missing 才给 `add_evidence`（真的没有）。
  这就是判据里"可用证据或补救建议"的"或"字被拆开兑现的地方。
- `education_missing` 与 `education_gap` 分开：库里没有学历区块时**不能**读成"差一点"，
  那是"没填"，用户自己去补就行，不需要产生"我不够格"的误读。

`matched` 行 `suggestion` 恒为 `null`（命中了不需要建议），这也在同一条结构断言里判。


【2】命令与用例
------------------------------------------------------------------------------
$ npx vitest run --reporter=verbose src/requirements-compare.test.ts src/gap-service.test.ts
（工作目录 packages/resume-kb，Node 24 / vitest 3.2.7；2 文件 / 49 例全绿）

 ✓ 不得只输出负面结论（spec 4.4-06） > 每一行非命中的比对都带建议，且建议只有 i18n key 与参数
   （用例体是遍历**所有**行：非 matched 且 suggestion 为 null → 失败；
    suggestion.key 不在 `GAP_SUGGESTION_KEYS` 里 → 失败；params 里出现中文句子 → 失败）
 ✓ kb.gap 的拆解入口（spec 4.4-01 / 4.4-06） > 过短的 JD 结构化失败，而不是给一份空报告
   （结构化失败也是"不只输出负面结论"的一半：宁可不给报告，不给一份"全是缺失"的报告）

真实装配上同一条判据的读数（demo 第【2】节最后一行）：

     非命中行的建议齐不齐：0 行缺建议

也就是那次跑的 6 行里 3 行 missing，每行都带 `add_evidence`，`strengthen_evidence / years_gap /
education_gap / education_missing` 四种在这份语料上没有实例，但各有一条单测钉住其产出条件。


【3】日志与播报侧的"计数可见"（同条判据的延伸，4.3-12 口径）
------------------------------------------------------------------------------
报告不能让"缺失"在日志里也变成不可见。实测日志行（demo 第【7】节原文）：

  INFO [kb-gap] 比对：要求 6 条 → 命中 3 / 部分 0 / 缺失 3 · 亮点候选 2（丢弃 0） ·
       库内实体 10 条 · 经验合计 64 月 · 截至 2026-10

对应的两条用例：

 ✓ kb.gap.report 的日志与播报（spec 4.4-06 / 4.3-12 的口径延续） > 比对日志只有计数与截止日期，查不到 JD 正文、库内正文与手机号
 ✓ kb.gap.report 的日志与播报（spec 4.4-06 / 4.3-12 的口径延续） > 整份报告一条都没命中时那一行走 warn，让「这岗位不合适」在日志里也显眼

脱敏是逐个哨兵验的，六个（`13800002222` / `星桥科技` / `抗压能力` / `订单服务重构` / `Java` / `推荐接口`）
在整份日志文本里各命中 **0 次**；真实装配那次的读数同样是各 0 次。
零命中时把级别抬到 WARN（不是 INFO）的理由：一份全是缺失的报告是产品最该显眼的时刻。


【4】这条判据没覆盖什么
------------------------------------------------------------------------------
- **语言包还没有这五个 key**。本片只产 key，`zh-CN` / `en` 的 `gap.suggestion.*` 文案与占位符实参
  齐备性校验归 4.4-d（接界面那一片）。`check-renderer-conventions` 现在扫的是"已有键在两个语言包里对齐"，
  本片没新增键所以通过；4.4-d 若只补一边会当场红——那是这条判据的机检落点，不是本片的完成度。
- 界面怎么把建议呈现成可点的"去补这条经历"是 4.4-05（V 类），归 4.4-d。
- 建议的**质量**（"该补哪条证据"是不是最优）没有验收。`strengthen_evidence` 给的是同分时按 id
  定序的第一条证据，确定性有保证、最优性没有。这与阈值未标定是同一件事，动作在 4.4-e。

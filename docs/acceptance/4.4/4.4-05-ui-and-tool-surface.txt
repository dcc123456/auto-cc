`evidenceBody` 是本片**唯一新增的公开读口**（判据三）：报告里的证据只带 id，正文按需另问，
所以打开面板不会把整本库拖进渲染层。实体与切片两类 id 走同一只手，不问前缀——
界面不需要知道"这是实体还是区块"，那是服务侧的事实。

`effect: read` + `requiresConfirmation: false` 与界面侧的只读口一致。整张注册表的效果位一并读了一遍

  sessions.open / browser.page.navigate / browser.page.snapshot / browser.locate.find   read 免确认
  browser.act.click / browser.act.type / outbound.greet.perform / outbound.deliver.perform
  jd.capture.run / kb.profile.syncVectors                                               outbound 需确认
  kb.gap.report / kb.profile.list / kb.profile.search                                   read 免确认

也就是"只读"这一位不是本片自说自话：同一张表里外发的那几只确实是 `outbound` + 需确认，
`kb.gap.report` 与 `kb.profile.list/search` 同排（§7.3 的闸门位没有被稀释）。

对话卡片标题走 `ChatPanel.TOOL_LABEL_KEY` + `agent.tool.labels.kbGapReport`（zh/en 双份），
`gap.suggestion.*` 与 `gap.model*` 全部键在两份语言包里齐全——`pnpm lint` 的渲染层规范机检

所以界面里写了 5 条字面建议调用与 5 条字面腿播报，而不是动态拼 key。


【5】本片没覆盖什么（如实记录）
------------------------------------------------------------------------------
- `merged` / `rejected` / `failed` 三种腿状态的**界面播报**没有现场图：本机 `llm` 未配 baseUrl/model/apiKey，
  而 4.4-02 的 U 半边已用契约用例钉住这五态的产出。缺的是"接上真 key 后在页面上看一眼"，
  与 4.4-02 的收口绑在同一个动作里（见 `4.4-02-model-leg-fallback.txt` 第【4】节）。
- 反向比对亮点区在本语料下 0 条，所以 `data-gap-highlight` 与"另有 N 条未展开"（`data-gap-highlight-dropped`）
  只有单测证据（4.4-c 的 `4.4-04-reverse-comparison.txt`），没有截图。
  界面代码路径是同一份 `report.highlights`，但**没有现场看过**就是没有，不写成通过。
- `modelReason` 与错误播报来自服务侧，是诊断载荷而不是界面文案，所以在英文页上仍是中文
  （例：「模型未配置，缺 baseUrl / model / apiKey」）。§5.5 管的是页面上出现的文案，
  这一条按诊断信息处理，写在 plan §4.4-d 的落地记录里，不当 i18n 违规去"顺手翻译"。
- 阈值未标定：界面上那句「各阈值当前未标定，可在 cordis.yml 的 kb-gap 段调整」是有意保留的，
  标定动作归 4.4-e（与 4.4-09 的额度/合规收口同片）。
- 导出、阈值调节 UI、从 `jobs` 表打开报告、`entitlement` 扣额度：判据里的"不做"清单，本片一条都没做。

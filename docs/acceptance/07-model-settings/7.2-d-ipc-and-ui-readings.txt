门禁第一次是红的，三处各自的真实原因（都不是"写错了"）：

1. `packages/main/src/registry.ts:81` → `TS2741: Property 'Config' is missing in type 'typeof
   LlmSettingsService' but required in type 'PluginConstructor'`。
   plan §7 决策③原本写的是"整块删掉 `static Config`"，实测**删不得**：`packages/kernel/src/index.ts:35`
   的 `PluginConstructor` 把 `Config` 列为必需成员，`schemaOf()`（同文件 :379）直接 `impl.Config as …`，
   没有缺席回落。于是这一格保留，但形状从同类插件的 `z.strictObject({})` 换成 **`z.object({})`**：
   `shellSchema` / `platformRegistrySchema` 那些没有残留的包可以严格，而 `llm-settings` 在 7.1 期间
   **真的被界面写过** `providerId` / `embedProviderId` 两格，持久层是五层合并的一层，严格形状会让每一台
   装过 7.1 的机器在挂载期就变 FAILED。`z.object` 是剥离而不是报错，因为这两格没有任何读者。
2. 同一个原因带出的第二条：`ctx.plugin(LlmSettingsService)` 直接挂载点必须交空实参，否则 cordis 拿 schema
   去解析 `undefined`，29 条用例一起报 `invalid config: Invalid input: expected object, received undefined`。
   用的是 `@auto-cc/core` 已有的 `NO_CONFIG`（`packages/core/src/index.ts:50`，它的注释登记的正是 AGENTS.md
   §9 的 1.3 类型坑），不在本包再写第二份（§2.2）。
3. `ModelSettingsPanel.tsx` 三处 TS18048/TS2345：`setForm((current) => …)` 的 `current` 是
   `ProviderForm | undefined`，展开后各键变可选；`bindingDraft` 同理。改成更新函数里先 `if (!current) return current`
   与把草稿初值定为 `{}`（"没动过的腿"本就是缺键而不是 undefined 对象），不做非空断言。

另外三条红**不是本片的**，登记下来是为了让下一次不要有人去"修"它们（共享工作树里有并行会话在同棵树提交，
AGENTS.md §9 的 5.3-a 收口那条）：`packages/preload/src/PreloadApp.tsx` 一度引用 `'settings.apply'` 与一只
没有导出的 `ModelSettingsPanel`，随后该文件从工作树上消失；`packages/testing/src/fixtures.test.ts` 的 200-vs-413、
`packages/workflow/src/runner.test.ts` 各红过一次；`packages/llm` 的池用例红过两条，**同一份代码连跑三次 35/35 全绿**。
处置一律是"复核而不是修复"：先把上面三处真实原因改掉，再整链重跑，最后用重复单文件运行证明本片自己的判定是稳定的。

# 四、渲染层三段的形状（两段实现期决策，plan §7 的原案在此被改）

**决策①：添加/编辑提供商是一张内联表单，不是第六只遮罩。**
plan §7.2-d 原案写的是"添加 `Modal`"。实现前读了 `packages/renderer/src/ui/overlays.tsx` 的纪律注释：
`Modal` 全 app 的入场条件是**不可逆或必须读完整风险**（当下只有 ConsentModal 与 PrivacyNotice 在用），
抽屉（`Drawer`）是"读与对照"容器。换一家提供商两头都不占、随时能取消，因此落到 `settings-model-form`
那一格内联展开。这条改动让 7.2-e 的取证也更简单（不需要先把遮罩打开再量几何）。

**决策②：候选值写成扁平的 `<实例 id>::<模型名>`。**
`DeskSelect` 的选项是 children（原件层没有 `<optgroup>` 先例），而 `llm_models` 的主键是
`(provider_id, model)`——同一条模型名可以在两家各存一份，只报名字挑不出"哪家的这一条"。
实例 id 是 UUID，不含这串分隔符，按第一个分隔符切开是唯一解。标签写成「显示名 · 模型名」。

三段暴露给 harness 的面（7.2-e 直接按这些凭据取数，不要再猜 testid）：

    容器    data-testid="model-settings" + data-model-encrypted + data-provider-count
    第一段  settings-model-providers（空态 -providers-empty）；每行 data-provider-id / data-provider-selected；
            行内 data-testid 读数 -provider-key（末 4 位那一句）与 -provider-count
    表单    settings-model-form；预设下拉 settings-model-form-preset、端点变体 -form-endpoint、
            显示名 -form-label、地址 -form-base-url、密钥 -form-key（type=password）、-form-save / -form-cancel
    第二段  settings-model-models（带 data-selected-provider-id）；空态 -no-provider；
            候选 -candidates（每格 DeskCheck action="settings-model-tick" + data-model-name）；
            已入库 -stored（每行 data-model-name + origin 徽标）；-already-stored
    第三段  每腿 <li data-model-leg="chat|embed">；来源读数 settings-model-leg-origin；
            密钥来源 -key-source-<leg>、缺项 -missing-<leg>；绑定/探测/清除四颗 action 都带腿名
    播报    -hot-apply-note、-check-result、-notice、-storage-encrypted；明文/解不开两条走 Banner
            （reason=STORAGE_PLAINTEXT / SECRET_UNREADABLE）

每格按不动的原因码（`data-disabled-reason` 的取值，11 只新增）：
`BRIDGE_MISSING · ACTION_BUSY · FORM_ALREADY_OPEN · NO_MODEL_STORED · FORM_INCOMPLETE · NOT_FETCHED ·
NOTHING_TICKED · MANUAL_EMPTY · MODEL_BOUND · NO_STORED_MODEL · BIND_INCOMPLETE · BIND_UNCHANGED ·
CHECK_NOT_SUPPORTED · LEG_INCOMPLETE · NO_KEY_STORED`（后四只沿用 7.1 那一格）。

# 3.2-09 超长条目的分页续排（不截断内容）+ 页数随内容增长 — 验收证据

## 判据
`spec.md 3.2-09`：模板对超长条目有确定策略（分页续排，**不截断内容**）；证据形态=构造 3 页长文档断言内容完整 + 页数增长。
状态位原先写的是「C 腿待 3.3」——U 半边（HTML 里带 `break-inside:avoid` 等护栏）早已在
`packages/resume-doc/src/print.test.ts` 里做成了永久机检，缺的正是本窗补上的 C 半边：真实内核下的页数与内容完整性读数。

## 方法（与 3.2-02 同一套 spike，见 `3.2-02-templates-pages.txt`）
文档侧埋了两类**纯 ASCII** 探针（中文经子集化后文本层不一定可读，ASCII 稳定）：

- 每条经历正文首尾各一只哨兵：`@@S{n}@@` / `@@F{n}@@`（n=1…条目数）。S 与 F 同页 → 条目未被腰斩；
  S 在页 k、F 在页 k+1 或更后 → 条目跨页续排；**F 整个产物里找不到 → 内容被截断**。
- 每条正文里每句尾随一个计数标 `[i]`（i 从 0 递增）。**实收计数标总数 == 期望总数** 就是「一个字都没丢」的指纹，
  比只看首尾更严（腰斩在中间也会露出来）。

长文档构成：8 条正常经历（每条 3 句）+ 第 9 条刻意做到**比一页还长**（90 句），共 9 条经历 + 简介 + 技能。
期望值：条目 9、计数标 `8×3 + 90 = 114`。三套模板各打一份，另各打一份 3 条经历的短文档做页数对照。

## 结果（`node .research-repos/p3-template-leg/report.mjs` 原文）
```
classic-long.pdf 页数=5 期望条目=9 实收S=9/F=9 S序=1,2,3,4,5,6,7,8,9 期望计数标=114 实收=114 超长条目#9 S页=3 F页=5 逐页=p1:6S/6F/18标/1265字 p2:2S/2F/6标/394字 p3:1S/0F/42标/2304字 p4:0S/0F/44标/2392字 p5:0S/1F/4标/240字
modern-long.pdf  页数=5 期望条目=9 实收S=9/F=9 S序=1,2,3,4,5,6,7,8,9 期望计数标=114 实收=114 超长条目#9 S页=3 F页=5 逐页=（同上，逐字节相同）
minimal-long.pdf 页数=5 期望条目=9 实收S=9/F=9 S序=1,2,3,4,5,6,7,8,9 期望计数标=114 实收=114 超长条目#9 S页=3 F页=5 逐页=（同上，逐字节相同）
classic-short.pdf 页数=1 期望条目=3 实收S=3/F=3 S序=1,2,3 期望计数标=3 实收=3 逐页=p1:3S/3F/3标/404字
modern-short.pdf / minimal-short.pdf 同上（页数=1，S/F=3/3，计数标 3/3）
```

判读：

1. **页数随内容增长**：同一模板下 `short=1 页 → long=5 页`，三套模板各自成立
   （classic 1→5、modern 1→5、minimal 1→5）。判据原文要的是「3 页长文档」，实测这份文档是 5 页，
   比要求更长，不构成降级。
2. **内容完整、没有截断**：9 只 S 与 9 只 F 全部出现在文本层里，且 **114 只计数标一只不少**；
   S 的出现顺序严格是 1…9（没有重排）。
3. **超长条目走的是「续排」而不是「整块丢弃或整块推走」**：第 9 条的 S 落在 p3、F 落在 p5，
   正文横跨 p3（42 标）→ p4（44 标）→ p5（4 标）三页连续排下去。
   同页里 `p3:1S/0F`、`p4:0S/0F`、`p5:0S/1F` 这个不对称分布，正是「有一条目跨页」的指纹——
   它是**故意造出来的那一条**，不是护栏失效。
4. **正常条目仍然不被腰斩**：能装进一页的条目在 p1（6S/6F）与 p2（2S/2F）里首尾同页，
   与 3.3-08 的 `break-inside:avoid` 结论一致（那条的 A/B 已证明：删掉护栏才会出现 `3S/2F` 的错位指纹）。

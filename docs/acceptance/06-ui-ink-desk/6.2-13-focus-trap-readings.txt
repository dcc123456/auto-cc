⑤ 实现口径（为什么是焦点陷阱而不是 `inert`）
─────────────────────────────────────────────────────────────────────────────
│ 判据给的是「`inert`（**或等价的焦点陷阱**）」。选后者的理由是第一线的结构事实：
│   `inert` 必须挂在**背景容器**上，而浮层按 §3.8 的裁定就渲染在面板里（不提到 `App.tsx`、不引 Portal），
│   因为"同一时刻 ≤1 只遮罩"正是靠 `display:none` 的祖先把 `fixed` 后代一起藏掉来保证的（第二十五片负腿）。
│   要 `inert` 就得把浮层提到顶层，那是拿一条已验收的保证去换另一条写法，不值。
│ 三条通道各自有主：鼠标 = 遮罩（`fixed inset-0`，命中测试实测）；键盘 = 本片的环；滚轮 = 弹窗那层的滚动锁。
│ 环的实现要点：
│   · Esc 与 Tab 共用**同一张层级表**（`overlayLayers`：层级 → { close, node }），toast 那一级不带节点
│     ⇒ 稿上「toast 不抢焦点」由形状自己成立，不需要额外开关。
│   · 焦点只锁**最高那一级带节点的浮层**（`topmostTrappedNode`），抽屉在下弹窗在上时 Tab 归弹窗。
│   · 一律 `preventDefault` 后自己 `focus()`：浏览器的 Tab 顺序按整份文档排，放过去就会跨出浮层。
│   · 焦点掉回文档（环内那格被卸载）时 `current=-1`，从端点重新起步而不是放任走出。
│   · 触发者在**渲染阶段**记进 ref、键在 `open` 的跳变上；归还只在 `activeElement === body` 那一刻做
│     ——这一条同时躲开 StrictMode 的假卸载（那时焦点还稳稳在弹窗里）与人已经自己走开（那时不该拽回来）。
│ 落点腿（纪律表第 2 行前半句）由调用方的 `autoFocus` 承担：`ConsentModal` 早就有（deny），
│   `PrivacyNotice` 本片补 `autoFocus={isReopened}`——**首启动那一次不给**：那一屏唯一的动作就是写下表态，
│   把焦点自动交给它等于允许一次误按 Enter 替用户点头（⑤ 的入场判据不许破）。
│ 顺带更正一处旧引用：`ConsentModal` 的注释与第二十五片记录把焦点这条写成"纪律表第 5 行"，
│   按 09 稿表格的实际行序它是**第 2 行**（1 同屏数量 / 2 焦点 / 3 滚动锁 / 4 Esc 层级 / 5 尺寸）；代码注释已改。

一、这一片要证的是什么
----------------------

判据是 6.2-14 那条总目的第二腿：**"渲染层只留一套 UI 基础设施"**。它的可信读法不是"我数了源码里有几处
`<input>`"，而是**活体页面上所有字段节点是不是算出同一个签名**——源码可以写得像一套，浏览器只认最终样式。
所以本轮取三条腿：A) 全 DOM 字段普查（同一签名 = 真统一），B) 每只原件逐件计算值（原件自己的档确实用上了），
C) 两处真实挂载的几何 + 一支 CSS 落地探针（新 utility 真的进了样式表）。

plan §3.9 定的迁移顺序原文是「先补齐 L1 缺的四件表单原件（`DeskField` / `DeskSelect` / `DeskTextarea` /
`DeskCheckbox`），再按面板分批改 54 处原生控件」。本片一次做完这两步，因为原件与调用点是同一条判据的两半：
只补原件不动面板，54 还在；只动面板不补原件，就得在面板里各写一份 `FIELD_CLASS`（§2.2 禁止的正是这个）。

四、C 腿：真实挂载的几何（把编辑态开出来量，避免只量到隐藏节点）
------------------------------------------------------------------

| 腿 | 读数 |
| --- | --- |
| 知识库新建卡（点 `[data-action=new]`） | `select[data-action=kb-edit-kind]` **60×27**、`textarea[data-action=kb-edit-payload]` **942×82**、字体 `"IBM Plex Mono"`（`className="font-mono"` 是宽度/字体档，描边仍在原件里）；两者 border/radius/bg/font/pad 与第三节同签名 → 挂进 DOM 的原件与隐藏视图里的原件是同一套档 |

八、为什么这 9 处不是"顺手一起换掉"，以及它们各自缺什么
--------------------------------------------------------

1. **`<button>` 5 处缺的是三种新形态原件**，不是缺一次 import：导航页签（`App.tsx`：选中态是下边线 + 文字提亮，
   `DeskButton` 的六档里没有"页签"这一档）、分段控件（`ChatPanel` 自治档位：三只互斥、选中实底、组内共边）、
   行内披露（`GeneratePanel` / `GapPanel` 的"看证据"：只有下划线文案，无框无底）。
   按 §2.6/§2.7 不能为了清零把它们硬塞进 `DeskButton`（那会造出"按钮长得像文字链"的第四种画法），
   也不能在各面板里继续手写（那正是本片要消掉的东西）。**下一片的落点是先补这三件原件。**
2. **`MetricsPanel` 的 4 处撞上一条已落地的机检**：`scripts/check-dashboard-readonly.ts` 判据 1 把看板组件的
   进口白名单钉成 `react / react-i18next / lucide-react / @auto-cc/shared` 四个包，引 `./ui/controls` 即红；
   判据 4 又要求该文件里 `<button` 恰好一处且 `onClick` 只能是 `void read()`。让看板吃原件需要**放宽判据 1**
   （"引不到能力包"这条最硬的防线的措辞要重写），这是裁定级的改动，**待用户表态**，本片没有自行放宽。
   看板的区间下拉与两只日期输入因此仍用手抄 `FIELD_CLASS`（活体读数已落在第六节之外的例外桶里）。
3. **`ChatPanel` 输入区**要的是另一个尺寸档（12px 正文、`8px/12px` 内边距、可自适应高度），与 `FIELD_CLASS`
   的 11px 元信息档不同族。并入还是自成一档属于设计判断，**待用户表态**。

九、还欠什么（本片不声称已完成的部分）
--------------------------------------

- **`DeskRange` 的活体几何是半腿**：真实挂载被 `NO_SEED_DOC` 挡住（第四节），只有 CSS 探针那份读数。
  补齐需要在开发档里先落一份种子文档，那会改写用户实例的状态——按 §7.2 与本窗一贯口径不做。
- **`<Controls>` 的 Tailwind 覆盖**（裁定 2）没动，画布 chrome 仍是第三方默认色。
- **机检不上**：按裁定「全换完再上机检」，`check-renderer-conventions.ts` 里"禁止 `src/ui/**` 之外的
  `<button>/<input>/<select>/<textarea>`"这条**仍未写入**，也没留基线豁免清单。所以 6.2-14 在当下**仍是
  `[纪律]`**，收尾自检的④⑤靠人工核对，不许声称"工具会拦"。
- **条件态（`:focus` / 非法环 / 勾选变色）无 DOM 测试可替代**：`packages/renderer` 里没有 jsdom/vitest 测试环境
  （无 `*.test.tsx`），这类状态只有活体一条取证路，本轮全部按 C 腿取。

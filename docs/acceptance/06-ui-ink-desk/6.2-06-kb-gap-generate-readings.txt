2. 本片抓到并修掉的一个真缺陷（活体读数抓出来的，不是单测）
--------------------------------------------------------------------
第一轮探针 `tmp/p6/kb-read.out` 得到的是这样一行：
  sync = amber / reason=DOC_ID_EMPTY / **aria=null / cursor=default / color=rgb(224,163,63)**
也就是说：按钮上挂着"为什么不能按"的理由码，但按钮本身是**能按的**，而且涂着可用的琥珀色。
原因是 `DeskButton` 的 `disabledReason` 只负责把 `data-disabled-reason` 与 `title` 渲染出来，
**它不代替 `disabled` 实参**——`disabled` 仍由调用方给。我在三块面板里只传了 reason。

修法：所有转换过的按钮补 `disabled={xReason !== undefined}`（`delete` / `new` / `save` 这三只的
理由位只有 `busy`，写成 `disabled={busy !== undefined}`）。第二轮 `kb-read2.out` 的读数就是
第 1 节那张表：aria=true、not-allowed、灰字 rgb(108,128,145) 落在 rgb(15,22,28) 上。

这条留档的意义：`[!]/[x]` 之外的第三种情况是"代码位看着齐了、活体上在说谎"。只有数色值的
单测看不到它，因为 React 的 `disabled` 与 `data-disabled-reason` 在 JSX 里是两个独立实参。

3. 形（禁用态收敛为同一档底色）
--------------------------------------------------------------------
五只禁用态按钮的 bg 全部是 rgb(15,22,28) = `ink-850`，与它们各自的语义色（amber / line）无关。
这是 `DeskButton` 的既有口径（第六片已记录过同一现象）：**语义色说"该由谁来做"，禁用态说"现在做不了"，
后者覆盖前者**。界面因此不会出现"红字但按不动"这种读不出原因的按钮。

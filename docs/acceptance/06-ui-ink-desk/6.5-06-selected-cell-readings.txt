6.5-06 活体读数：画布上被选中的那一格看得出来（第二十片，2026-10-06）
================================================================================

一、这一片是这么来的
--------------------------------------------------------------------------------
第十九片收 6.5-05 的检视器时顺手量了一条 `selectedMark`（见
`6.5-05-inspector-readings.txt` 第六节）：选中那一格的 `data-node-selected` 不存在、
计算样式 `outline: none 3px rgb(27,34,40)`——也就是**在图上看不出来是哪一格被选中**，
只有下方两张卡（参数表 + 运行读数）说明是谁。03 稿的「此刻指向」三件里当时只兑现了
「检查器同步」。这一片补的就是外圈那一支描边。

改的代码只有 `WorkflowCanvas.tsx` 四处（一行常量、`OperatorData` 一个字段、
`nodes` 那一份 memo 里现算 + 依赖补一项、卡片上两个 class/attr）：
- `SELECTED_CELL_CLASS = 'outline-solid outline-2 outline-offset-2 outline-celadon/70'`
- `data-node-selected` 与 `data-node-issue` 同口径写 `'true' / 'false'`（读数位要能说真话，
  不用「缺属性」表示 false）
- `isSelected: cell.id === selectedNodeId` 由视图层现算，**不进命令栈**——选中是镜头不是图的一部分

描边画在 `outline` 而不是 `border`：`border` 那一份是状态色（`stepStatusStyle.ts`，
与步骤行同色是 1.10-03 定的），选中如果去改它就等于「指针盖掉了状态」。
于是 running 与 selected 可以同框：内圈读状态、外圈读指针。

二、通道口径（窗口 hidden）
--------------------------------------------------------------------------------
本轮 `document.visibilityState` 全程是 `hidden`（末态实测 `{"theme":"light","stored":"light","vis":"hidden"}`）。
按 AGENTS.md §9 的两条：
- CDP 派发的鼠标事件**不落页** → react-flow 的 `onNodeClick` 这条路走不通；
- 页内 `element.click()` 与 `Page.captureScreenshot` **照常生效**。

所以选中的通路换成「从算子库点一下建格」——`addOperatorNode` 本来就会把新格子设为选中
（5.10-03 那条点击建格的既有通路，一字未改）。这样一次手势同时造出**对照组**：
同一张画布上「刚点的那一格 = 选中」与「上一格 / 库里带来的三格 = 未选中」，
一行代码都不用替页面撒谎。

三、读数（探针 `tmp/v6c/sel06.mjs`，两趟跑下来逐位一致）
--------------------------------------------------------------------------------
起点：库里那条计划带三格（`jd-capture` / `jd-list` / `flaky`），`canvas-draft-count` =「图上 0 格」。

| 腿 | 主题 | 格子 | `data-node-selected` | 计算 `outline` |
| --- | --- | --- | --- | --- |
| empty | 毡案 | 3 格全在 | 全部 `false` | `none 3px rgb(107,118,129) offset:0px` |
| first | 毡案 | `jd-capture-draft-1` | `true` | `solid 2px oklab(0.554606 -0.0677615 -0.00587878 / 0.7) offset:2px` |
| first | 毡案 | 其余 3 格 | `false` | `none 3px …` |
| second | 毡案 | `draft-1` | `false` | `none 3px …`（**青瓷圈跟着换人，不留在原地**） |
| second | 毡案 | `draft-2` | `true` | `solid 2px oklab(0.554606 …/0.7) offset:2px` |
| dark | 墨案 | `draft-2` | `true` | `solid 2px oklab(0.7354 -0.0589094 -0.00346506 / 0.7) offset:2px` |
| dark | 墨案 | 其余 4 格 | `false` | `none 3px rgb(108,128,145) offset:0px` |

`--color-celadon` 本身随主题翻面：毡案 `#3f8078` → 墨案 `#7fb6ad`，
描边的 oklab 读数跟着翻（`0.554606` ↔ `0.7354`）——证明这一支取的是令牌，不是写死的色值。
透明度 `.7` 与 `2px` / `offset 2px` 两主题一致（档位语义不随主题翻，与 6.2 那条口径同一条）。

四、状态色没被选中改写（这一条是改动的代价，必须单独量）
--------------------------------------------------------------------------------
选中那一格与未选中那一格的 `border-color` / `background-color` 逐位相同：
毡案 `rgba(38,44,48,.3)` + `rgb(224,219,205)`、墨案 `rgba(150,178,196,.26)` + `rgb(15,22,28)`，
`box-shadow` 也仍是那一份 `shadow-sm`。也就是描边只加了一圈，没有把
`STEP_STATUS_STYLE` 的任何一项顶掉（画布格子与步骤行同色这条 1.10-03 的约束不破）。

五、撤销那一腿（不误标）
--------------------------------------------------------------------------------
`canvas-undo` 撤掉选中的 `draft-2` 之后：`图上 1 格`，剩下 `draft-1` 的
`data-node-selected` 是 `false`、outline 回到 `none`，参数卡整块不出现
（`formCount: 0`、`detailNodeId: null`）。也就是**撤销不会把旁边那一格冒充成选中的**——
这一腿是顺手量的，因为 `selectedNodeId` 是视图层状态、撤销不清它，
判据落在「找不到那一格时界面不画任何东西」上，与 6.5-05 的「单选才有检查器」同一条读法。

六、没取到的（如实）
--------------------------------------------------------------------------------
1. **真实指针点选**（react-flow 的 `onNodeClick` 那一路）：窗口 hidden 时 CDP 鼠标不落页，
   要用户在场把窗口带到前台才能取（§9 的 2.1-12）。本片判据是「选中之后长什么样」，
   选中态本身由既有通路（点击建格）真实设置过，不是替页面伪造的。
2. **running + selected 同框**：要真跑一次自治运行才长得出 running 格子，
   为一条颜色读数去起一次 run 会写库、会外发——与 6.5-05 的 `READ_ONLY` 同一支原因，不取。
3. **四角把手（节点缩放）**：10 稿 ⑨ 的那一件按 plan §3.7 的口径不在本片射程。

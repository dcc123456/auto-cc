1. 步进器：拨一档 + 两个边界都按不动且说得出原因

{
  "before": "1", "afterOnePlus": "2",
  "afterEightMinus": "1", "floorMinusDead": "AT_FIRST_LINE", "plusAfterFloorDead": null
}
{
  "start": "1",
  "atCeiling": { "line": "22", "max": "22", "plusDead": "AT_LAST_LINE" },
  "afterTwentyMinus": { "line": "2", "minusDead": null },
  "readyToSplitAt": "2"
}

→ 连点 30 次「+」停在 22（不是 23，也不越界），「+」自己长出 AT_LAST_LINE；连点 20 次「-」落到 2、
　 再点落 1 并长出 AT_FIRST_LINE。左端「-」在 1 处按不动、右端「+」在 22 处按不动，与主进程
　 index-out-of-range 的判界同一条，所以"界面放行、保存被拒"的分叉结构上不可能。
※ 读数里那一条 "atLine4": { "line": "1", "max": "22" } 是探针自己的缺陷：它在两次 click 之前抓了 DOM 节点引用，
　 React 换掉该节点后读到的是脱离文档的旧值。改成一律现查（step-b）后同一判据读到 22 / AT_LAST_LINE，
　 不是产品缺陷，写在这里免得后人按它去找 bug。

  "afterPaper": { "status": "idle", "text": "已是最新 · 15:59:10", "dirty": "false" },

}

→ 条数 1 → 2，2 + 21 = 23 一字不差；纸角时间戳从 15:53:11 走到 15:59:10，人没有按过任何「预览」键

　 纸面动了的正证是时间戳与条数同向变化，以及下面第 4 条撤销后时间戳再走一次。
→ 旧切法那一句从 4 个区块掉到 3 个：技能现在有两条，那句"按导入时的规则切的"就该消失，逐字对得上。

第一节  落了什么
--------------------------------------------------------------------
1. `packages/renderer/src/JobLabPanel.tsx`：最后那一段"库内清单"从**一列 12 行、每行两只朱砂键**
   改成三段：
   - 第一段 列表：每行是一只 radio（`name="jd-row"`、`data-jd-row="<jobId>"`），行上只留
     `jd.rowMain` 一行读数与「对方已回 N 条」；`data-job-selected` / `data-replied` 两个属性各就各位。
   - 第二段 详情：`[data-testid="jd-detail"]`，读的是**同一行 `JobRowView` 已经带回的字段**
     （title / company / city / experience / education / salary / description / requirements /
     sourceUrl / capturedAt / detailCapturedAt），不新增 IPC、不新增读路径（plan §3.6）。
   - 第三段 动作：`greet-<jobId>` 与 `deliver-<jobId>` 两只 `DeskButton variant="seal"`
     **字符串一字未改**，位置从行内搬到详情卡的页脚，前面常驻一句
     `jd.actionTarget`「下面两个动作只作用于这一行：…」；上面一条 `border-line-strong` 分隔线。
2. 选中态走 **celadon**（`border-celadon/50 bg-celadon-wash` + `accent-celadon`），与
   `ScriptPanel` 候选行同一套画法（§2.2/§2.5：同一件事不长第二套）；不走 jade（jade 是"已核"）。
3. **没选中时详情与动作段一起不出现**，只留一行 `jd.detailIdle` 提示——不是摆两只按不动的朱砂键，
   因此本片不新增原因码（plan §3.6 第 4 条）。
4. 清单那一段成为**查询容器**（section 上 `@container`，grid 上 `@2xl:grid-cols-[minmax(0,17rem)_minmax(0,1fr)]`）：
   并排还是上下走，看的是这一列自己的宽度，不是视口宽度。起因见第六节的实测读数。
5. 新增 10 支双语键（`jd.detailIdle / detailCaptured / detailByline / detailPartial /
   detailDescriptionHeading / detailDescriptionEmpty / detailRequirementsHeading /
   detailRequirementsEmpty / detailSourceUrl / actionTarget`），`pnpm lint` 的缺翻译校验通过。

第六节  窄/宽两腿：为什么并排要挂在查询容器上
--------------------------------------------------------------------
`tmp/v6b/rp33.out`（视口 1200 的实际列宽链）：

    innerWidth 1200 → main 560 → 面板 section 520 → 清单 grid 486
    aside（内嵌内核视图槽位）456 = w-(--kernel-view-width)，**不可收起**（宽度与
      KERNEL_VIEW_WIDTH_RATIO 机检同源，App.tsx 里那一句注释就是这个约束）
    第一版按视口断点（lg:）量出来的列：gridTemplateColumns = "272px 202px"

202px 的详情栏放不下正文与两只朱砂键，而视口断点救不了它——视口 1200 已经算"宽"，
被内核视图吃掉的是**这一列自己的宽度**。所以换成容器断点：
`@container`（section）+ `@2xl:`（672px 容器宽）才并排，窄时退回"列表→详情→动作"的纵向读序。

两腿都取了活体：
- 窄腿（真实窗口 1200）：`gridTemplateColumns: "486px"`（单列，rp35/rp40），截图见第七节四张。
- 宽腿（`tmp/v6b/wide-shot.mjs`，CDP `Emulation.setDeviceMetricsOverride` 1600×1000，
  放大→量→截图→复位在同一条 WebSocket 里做完，§9 的 5.4-b ⑥）：

      innerWidth 1600 / containerWidth 768 / cols "272px 450px"
      listWidth 272 / detailWidth 450 / detailLeftOfList 284 / sameRow true / actionCount 2

  也就是 02 稿的横向骨架在宽窗口下确实兑现，且详情卡与清单**同一行**（`sameRow: true`）。

第八节  没取到的（[!]）
--------------------------------------------------------------------
1. **08 稿那一行的"双击 = 跳简历区并带面包屑"没做**——它是跨区跳转（形态 ⑥），
   要新增"带着某个岗位进简历屏"的状态传递，不在 6.4-04 的判据里，另立条目。
2. **↑↓ 换行的键盘等价没敲过**：radio group 原生支持方向键换选，但本轮取的是鼠标那一腿，
   键盘那一腿按 §7.1 的 V 口径不算已证。
3. **`jd.detailPartial` 那一支只取了文案，没单独读它的 `text-amber` 色值**（同一档色值已由
   第六~九片取过）；`jd.descriptionEmpty` / `requirementsEmpty` 同理。
4. **02 稿的匹配分 / 缺口三栏 / 骑缝章 / 四页签（缺口报告·话术·改简历·抓取证据）都没落地**：
   它们要的是 GapPanel 的比对结果与话术候选，属于"另一屏的数据挂到这一屏"，
   判据只要求三段骨架，不在此片扩张（§2.6）。
5. **抓取那一路的活体行仍然没有**：`automation_consents` 空，签字要人来做（第二节）。
   所以"抓完一轮之后清单长出新行、选中它看详情"这条端到端链，仍等用户在场的窗口。

**附记一条画面里看得见、但不在本片射程内的读数**：宽腿那张截图
（`6.4-04-jobs-wide-split-light.png`）下方「打招呼话术候选」的目标岗位段写着「JD 库还是空的」，
而同一画面里上方清单明显有两条演示行。查了源码，这不是文案说谎而是**它的那份读数停在挂载时刻**：
`ScriptPanel` 只在 `useEffect` 里读一遍 `jd.store.list`，之后只有收到 `jd/progress` 的 `done` 才重读
（`ScriptPanel.tsx:71-102`），而本片的演示行是从 SQL 侧插进去的、不经过抓取流水线，
所以没有 progress 事件可等。清单那一段是我在种完之后才按「读取」键现读的，两边才不一致。
**结论：这条是取证方法带出来的，不是界面缺陷**，但顺带显出一个真实的失效面——
任何不经 `jd/progress` 就写入 `jobs` 的路径（工作流节点直接落库、外部导入）都会让话术面板的下拉变陈旧。
本片不动它（§1.4 不许夹带），记在这里作为下一条待办的出处。

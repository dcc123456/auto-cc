spec 6.4-24 纸面高度口径（「整页一次看全」）的活体读数
=========================================================
日期：2026-10-14　环境：本机 macOS（Apple Silicon），我自己那一份 dev 实例
（`AUTO_CC_USER_DATA_DIR=$PWD/tmp/dev-userdata pnpm dev`，vite 127.0.0.1:5173，CDP 10222）
窗口 1200×772（CSS px），简历屏容器实测 940，纸栏 526（`--resume-paper-width: 56%`），
纸面槽 `resume-paper-slot` 宽 494 / 内容宽 470（`p-3` 各扣 12）。
`document.visibilityState` 全程为 `hidden`：窗口未在前台。因此
① 每次改完宽度 / 滚动位置后都跑一次 `harness shot` 逼出帧（`ResizeObserver` 与 rAF 在 hidden 页里不推进，
   §9 的 3.5-16 同条），下面的"改后"读数都是逼帧之后现读的；
② 这一条只测**几何**，不涉及指针输入。
探针：`tmp/65/probe-height2.js`（结构普查）、`tmp/66/probe-fit.js` / `tmp/66/read-fit.js`（三态：基线 / 拖窄 / 还原）、
`tmp/66/scroll-to.js` + `scroll-probe.js` + `scroll-undo.js`（滚动两态，测完已把 scrollTop 还原成 677）。

一、改前（6.4-12 的原口径：倍率只看宽）
----------------------------------------
    --paper-scale        0.5919395465994962   = (494 − 24) ÷ 794
    iframe 布局           794 × 898            （898 = 532 ÷ 0.5919，即"槽内容高 ÷ 倍率"那一支百分比）
    iframe 视觉           527 × 532
    槽（class 写死）      h-[min(72vh,900px)] = 556，top 150 / bottom 706
    纸栏 section          高 719，top 71 / bottom 790
    滚动容器下缘          742（app 的 `header` 高 51 + 滚动容器 p-5）
    一页 A4              794 × 297/210 = 1123 → 一次只露出 898 = **80%**，其余要在纸里滚
    副作用               section 底 790 > 742 → 导出回执那一行常驻在可见区之外

二、改后（`fit="page"`：宽与一页的高取小；槽高由同一处现算）——纸栏停在粘住位（scrollTop 677）
------------------------------------------------------------------------------
    --paper-scale        0.42369837385186876   = min(470÷794, 477÷1123) → **高绑**
    --paper-height       1123px                （iframe 的布局高 = 一整页）
    槽的内联 height      500px                 = 476（纸的视觉高）+ 24（槽的上下内边距）
    iframe 布局           794 × 1123            与 794 × 297/210 差 0px（判据 `pageRatioCheck` 容差 ±2 → true）
    iframe 视觉           336 × 476，left 716 / right 1052
    槽的内容区            left 649 / right 1119 → 左右各空 **67px**（居中，`margin-left` 现算）
    纸栏 section          高 663，top 71 / bottom **734** ≤ 742 → 回执条回到屏内（`receiptInsideFold: true`）
    → 判据① 倍率落进 `min(1, 470/794, 可用高/1123)`、纸的下缘不越可见区：过
    → 判据② 布局高 = 一整页 且 槽高 = 视觉高 + 24：过（整页可见，纸内不滚）

三、拖窄纸栏（写 `--resume-paper-width: 26%` 在纸栏节点上，与把手同一支变量）
------------------------------------------------------------------------------
    槽宽 212（内容 188）→ --paper-scale 0.2367758186397985 = 188 ÷ 794 → **宽绑**
    槽内联高 290 = 266 + 24；iframe 视觉 188 × 266，right 1119 ≤ 槽内容右缘 1119（`paperFitsSlotWidth: true`）
    section 底 550 ≤ 742 → 判据④（拖窄后从"高绑"切回"宽绑"、纸不越槽）：过
    还原变量后逐字回到第二节的读数（`restoredIdentical: true`）

四、滚动一挡（同一份可见区里纸栏从"未粘住"滚到"粘住"）
------------------------------------------------------------------------------
    scrollTop 0   → --paper-scale 0.36225268268325567，槽内联高 431px（可用高被上面那 83px 的 chrome 挤掉一截）
    scrollTop 677 → --paper-scale 0.42369837385186876，槽内联高 500px
    → 判据⑤（位移也要重量一次，`ResizeObserver` 看不见这个）：过——rAF 节流那条 scroll 监听在逼帧后跑到了
    测完 scrollTop 已还原（`{"restored":true}`），纸栏宽度变量已删除

五、本轮自己踩到的一条（写下来免得后人以为槽高可以省）
------------------------------------------------------------------------------
    第一版只把 iframe 的布局高设成"一整页 1123px"，结果：
    槽量到 **1147**（= 1123 + 24）而纸的视觉只有 **476** → 纸底下白留 647px，比报障本身还难看。
    原因是 `scale` 只改视觉、不改布局盒。所以槽的 `height` 必须由同一处现算（第四节那些读数是补上这一条之后取的）。

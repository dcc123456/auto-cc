┌─ ⑥ 「同时只 1 只遮罩」的结构判据（负腿）──────────────────────────────────
│ 弹窗挂在岗位屏自己的子树里（`ConsentOverlay` 在面板内渲染）。切到对话屏后：
│   mounted=true（React 还挂着）· dialogWidth=0 · scrimWidth=0
│   [data-view-scroll=jobs] 的 computed display = none（`hidden` class）
│   画面上有宽度的 dialog 数 = 0 → 屏幕上没有第二只遮罩，也没有能挡住新操作的隐形遮罩
│   期间 document.body.style.overflow 仍是 hidden（副作用还在，等用户回来表态，符合"没表态就不算完"）
│ 结论：不需要为浮层新造一份跨面板汇流，"同时 ≤1 只"由视图挂载结构自己保证（plan §3.8 那条论证的活体版）。
│ ⚠ 这一条腿同时暴露一个已知缺口：遮罩虽然画不出来，但背后**没有 inert**，Tab 键仍能走进隐藏面板的控件——
│   已立 6.2-13，本片不做。

┌─ ⑧ 本片顺带修掉的一处原件缺陷 ────────────────────────────────────────────
│ `Modal` 原先的 class 是 `w-full ${MODAL_WIDTH[width]}`，两条宽度 utility 同时挂在一个节点上，
│ Tailwind 的最终胜者由 CSS 输出顺序决定而不是书写顺序——活体首读宽度是 **1152px**（= 1200 − 2×24 padding），
│ 也就是 `width="560"` 这一档从来没有生效过。改成 `max-w-full w-[560px]` 后同一处读数为 560（见 ①）。
│ 这条属于"原件至今零消费者所以从没被测过"那类：抽屉 `Drawer` 没有同样问题（它的宽度档没有配 w-full）。

================================================================================

一、口径与环境
----------------
- 机器：macOS（Apple Silicon）/ 开发实例 `pnpm dev`，CDP `10222`，渲染层 target `--url 5173`，
  视口 1200×772 dpr 2。视图切到「信任」（`[data-action="nav-trust"]`），面板锚点 `[data-testid="model-settings"]`。
- 这一片的性质是**结构换件**，不是改样式：那五处原本手抄 `FIELD_CLASS`（`ui/controls.tsx` 导出的同一串字面量），
  本片改成 `DeskSelect` / `DeskField`。所以判据写成"**换件前后计算值逐位相同**"，
  任何一处签名漂了都算本片做错。
- 全程只读：没有点「保存」「测连通」「清除」任何一颗（那三颗会写这台机器的模型配置与系统钥匙串）。

- 五支签名与第二十七片入库的那一条统一桶**逐字符相同**，即"塌成同一签名"这件事从
  「源码里各抄一遍」变成了「只有一处能长出来」。毡案翻面后同样五支一致
  （`rgba(38,44,48,.3)｜6px｜rgb(216,211,198)｜11px｜4px/8px`）。
- `type="password"` 这一条必须单独盯：`DeskField` 的 `type` 是 rest 透传，默认值是原生 `text`，
  换件时漏掉 `type` 不会报错、不会变色、只在真人打字时才露出明文——按第二十七片立的口径
  （"原件有默认值而调用点依赖另一种语义"的换件，换完必须回读），活体回读到的仍是 `password`。
- 三支 `placeholder` 逐字未动（`https://…/v1` / `该家的模型名` / `尚未填写`），
  提供商下拉的 5 条 `<option>` 与"读回未知 id 时原样显示 id"那条兜底选项都还在（选项数据归调用方，原件不造数据）。

四、顺带纠正本片自己发现的一条旧账（写进 spec 第二十七片记录的勘误）
--------------------------------------------------------------------
- 之前几片把 `MetricsPanel` 的四处理解成"另一套手抄档"。**活体读数不支持这个说法**：
  它的 `#metrics-preset` 计算值是 `rgba(150,178,196,.26)｜6px｜rgb(8,12,16)｜11px`，
  与统一桶**同一支**（它自己手写的那串 `min-w-0 rounded-md border border-line-strong bg-ink-950 px-2 py-1
  text-[11px] text-slate-200` 与 `FIELD_CLASS` 是同源字面量）。
  这条纠正有实际用处：它说明**放宽 `check-dashboard-readonly.ts` 判据 1 之后换进原件不会动画面**，
  待表态的那一条从此没有"改了会不会花"这一层风险，只剩"要不要给看板开第二条能力通道"这一层。
- 同时本片删掉了 `ui/controls.tsx` 的 `export const FIELD_CLASS`：换完这五处之后它**零消费者**
  （§2.4 死代码即删）。从此面板要长一只字段框只有一条路——用原件；手抄档口物理消失，
  第三份复制再也写不出来。`fieldClass(isInvalid)` 作为原件内部的私有函数保留。

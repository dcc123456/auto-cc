五、本轮顺手挖出来并修掉的缺陷（提交 `578f73d`）
-------------------------------------------------

第一版探针在**一页干净的页面**上量到 `operator-param-form` 会长兄弟：建格 1 张 → 翻一次主题 2 张 →
再翻 3 张，而撤销掉那一格之后三张仍堆在页面上（`y=1022/1247/1472`，全部可见）。
`parentChildTags` 与 React 的子 fiber 链对不上，控制台报的是：

```
Encountered two children with the same key, `jd-capture-draft-1`.
Keys should be unique so that components maintain their identity across updates.
Non-unique keys may cause children to be duplicated and/or omitted.
```

根因是**两张卡是同一个 children 数组里的兄弟，而两者的 `key` 都直接取节点 id**——
参数卡 `key={selectedSpec.id}` 与读数卡 `key={selectedCell.id}` 说的本来就是同一格，键值必然相同。
React 遇到同键会复制出它自己不再管的 DOM。修法两支键各加一个前缀（`params:` / `detail:`），
"换一格就重挂载"的语义一字未改。复核（`tmp/v6b/rp72.mjs`）：建格 1 张 → 深浅各翻一次仍是 1 张 →
撤销回到「图上 0 格」且表单归 0，控制台不再出现同键报错。

六、没取到的（如实留着）
------------------------

1. **`READ_ONLY` 那一支仍只有静态映射**：要它得让 run 真在跑（`isReadOnly` 由运行期推来），
   为一条颜色读数去起一次自治运行会写库、会外发，不值当。参数卡上的只读提示行
   （`param-form-readonly`，琥珀）与调色板那一条同理由，见 `6.5-04-drag-readings.txt` 第 9 条。
2. **选中那一张格在画布上看不出来**：`[data-testid="canvas-node"]` 上没有 `data-node-selected`，
   `OperatorNodeCard` 不画选中态，只有 react-flow 自己那一个 `selected` 类，而计算样式读出来是
   `outline: none 3px rgb(27,34,40)`（也就是不画）。10 稿 ⑨ 要求"选中态 = 描边 + 四角把手 + 检查器同步"，
   三件里只有"检查器同步"这一件成立（见第四节）。**这条已另立 6.5-06**，不在本行射程内。
3. `busy` 转针那一帧（每次往返都在两次 eval 之间回来，与前十八片同一结论）。
4. 截图里画布那一段是空的（节点在 flow 视口的当前变换之外）——本轮的验收对象是检视器那两张卡，
   它们在画面里完整可读；格子本身的画法见 `6.5-01`/`6.5-04` 那两张。

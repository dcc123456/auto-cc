6.4-12 · 简历屏左右分栏常驻（46rem 档）——活体读数
=====================================================

取证对象：用户自己的 dev 实例（`pnpm dev`，CDP 10222，渲染层 5173），窗口未动，视口用
`Emulation.setDeviceMetricsOverride` 临时换档（Electron 的 endpoint 没有 Browser 域，且该覆写只在
那条 WebSocket 存活期间有效——AGENTS.md §9 的 5.4-b ⑥），所以"换档 → 冻动效 → 逼帧 → 量几何 → 拍图 → 复位"
全在一支脚本里做完：`tmp/57b/desk57.mjs`（暗色那张在 `tmp/57b/dark57.mjs`）。

两条环境事实先记在开头，否则下面的数字会被读错：
① `document.visibilityState` 全程 `hidden`（窗口没在前台）。hidden 时 Chromium **不产渲染帧**，
   而 `ResizeObserver` 的回调排在帧末，所以换档之后必须先逼帧再读（脚本里 `settleScale()` 用
   `Page.captureScreenshot` 当节拍器，判据是 `|--paper-scale 变量 − 现算值| < 0.005`）。
   本轮第一版没逼帧，1600 档读到的是上一档（1200）的 0.5919——那是环境读数，不是产品读数。
② 量几何前注入 `*,*::before,*::after{transition:none!important;animation:none!important}`，
   收尾摘掉（§9 的 6.2 ①）。每支脚本最后一行 `ANIMATIONS_AFTER_UNFREEZE` 就是自证摘干净了。

→ `direction:"row"`：1200 窗口（容器 940）这一档**真的分栏了**——这正是 6.4-07 那 77rem 档在这台机器上
  永远不发生的那件事。纸栏在左列右侧按横坐标判：`paperColX 618 ≥ leftRightEdge 606`（差 12 就是 `gap-3`）。
  纸面不被裁的两条正腿：`paperScale 0.5919 ∈ (0,1]` 且 `neverClipped:true`（`frameRect.right ≤ slot.right`）。
  `w-[210mm]` 一字未改：`frameNaturalWidth 794`，折完是 `frameRenderedWidth 470 ≤ slotWidth 494`。

  **一条被活体推翻的判据（写在这里，spec 行内同步更正）**：原先第三条腿写的是"槽内
  `scrollWidth ≤ clientWidth`"。实测三档的 `slotScrollWidth` 恒为 **818**（=794+2×12 的**变换前**布局溢出），
  而 `slotClientWidth` 是 494/718/682——Tailwind v4 的 `scale-(…)` 写的是独立 CSS `scale` 属性
  （`getComputedStyle(frame).scale === "0.59194"` 而 `transform` 为 `none`），`scrollWidth` 量的不是它的视觉结果。
  所以那条换成 `scale` 计算值 + `neverClipped`（矩形右缘）这一对，`scrollWidth` 读数保留在此作为反例。

⑥ 取证过程中改的一处产品代码（不是探针产物）
----------------------------------------------------------------------

第一版 `editor57.mjs` 拍到"滚到左列的排版控件时，右栏整格空白"：`slotTopInViewport:-2519`。
根因是 `@[46rem]:sticky` 长在 flex 项上而 flex 项默认被 `align-items: stretch` 拉成整行高（左列实测
2673px），拉满就没有可粘的余量。补 `@[46rem]:self-start` 之后同一支探针复跑：

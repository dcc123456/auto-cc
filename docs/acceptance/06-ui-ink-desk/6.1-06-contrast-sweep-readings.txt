② 测量口径（为什么不能直接信 getComputedStyle）
═══════════════════════════════════════════════════════════════════════════════
- 颜色 → sRGB 字节一律走 1×1 canvas（`fillStyle` + `getImageData`）：墨案的令牌是 oklab，
  `getComputedStyle` 回来的就是 `oklab(...)` 字符串，自己换算必错；canvas 也顺带吃掉
  `color-mix()` 与 `/45` 这类透明度写法。
- 背景 = 祖先链上所有非零 alpha 的 `background-color` 从远到近叠合（半透明淡洗因此参与合成），
  最外层垫白。文字 = 自身 `color` 叠在该背景上，再按 WCAG 相对亮度公式求比值。
- 分档规则（写进 spec 6.1-06 的那句「正文 ≥ 4.5:1，次级文案 ≥ 3:1」的落地口径）：
  **计算字号 ≥ 12px 记正文档（门槛 4.5:1），< 12px 记次级/元信息档（门槛 3:1）**。
  取 12px 而不是 WCAG 的 24px/18.66px 作为放宽点，是因为本项目 11px 与 12px 之间
  正好是「读数」与「说明文案」的分界；13~18.66px 这一段仍按 4.5 判，不放宽。
  本轮全部失守行都落在 11px 与 12px 这两档上，所以两条门槛就是判据的全部。

③ 第一轮读到的假失守（这条必须先记，否则后面的数字没人该信）
═══════════════════════════════════════════════════════════════════════════════
- 现象：第一轮（未处理冻结）在**毡案**的扫描里读出 `rgb(226,84,58)`（墨案 seal）、
  `rgb(164,182,195)`（墨案 slate-300）、`rgb(224,163,63)`（墨案 amber）这类**另一个主题**的
  文字色，压在浅底上得到 1.33 / 1.59 这种不可能的比值；镜像地，墨案扫描里也读出过
  6 行浅主题的 hex。
- 根因：`DeskButton` 的 `transition-[background-color,border-color,color,box-shadow] duration-150`
  在窗口不可见时时间轴是冻住的（与本项目 `animate-wash` 卡在 opacity 0 同一条环境事实）。
  切完主题立刻量，`getComputedStyle().color` 还停在**上一个主题**的值上。
- 自证读数：`animBeforeKill = 14` —— 注入抑制样式之前 `document.getAnimations().length` 是 14，
  即页面里确实挂着 14 个没走完的动画/过渡句柄。
- 修正：探针在 reload 之后、任何测量之前先注入
  `*,*::before,*::after{transition:none !important;animation:none !important}`。
  运行中的过渡被取消时属性直接落到 after-change value（目标值），读数才是当前主题的真值。
  修正后两主题的读数不再互串。
- 顺带一条：第一轮的总数 253 与修正后的改前基线 247 不是同一口径，**以 247 为准**。

     `--color-seal: #c0391f` **不动**（按同一门槛它只有 3.00，但它是十几份验收证据里的

     `slate-500 #6b7681 → #5f6a74`、`slate-600 #7d8892 → #6b7681`。
     定下的对应关系：**≥12px 的文字只许用 slate-400 及更深（4.5 门槛），
     slate-500/600 只属于 ≤11px 的读数（3 门槛）**。
D. 20 处 `text-xs` 的说明/空态/状态行从 `text-slate-500` 改挂 `text-slate-400`
     （App、AssemblyPanel、GapPanel×3、GeneratePanel、KbPanel×11、ScriptPanel、
     SessionPanel、UpdateSection）—— 全部是 `<p>/<li>/<span>` 的成句说明文案。
E. 新增**文字档 `-ink`**（两主题各三支）：`--color-seal-ink`（毡 #96290f / 墨 #ef7a55）、
     `--color-jade-ink`（毡 #1f6244 / 墨 #4fb78a）、`--color-amber-ink`（毡 #6f4c06 / 墨 #e0a33f）。
     `DeskButton` 三档语义按钮的文案改挂 `-ink`，描边/淡洗/图标仍走色相档；
     墨案青玉与琥珀的 `-ink` 与色相档同值（留键是为了组件侧只有一条写法，不分叉）。
     实测：`text-seal-ink` 在两主题都真的生成了 utility —— 毡案读到 `rgb(150, 41, 15)`、
     墨案读到 `rgb(239, 122, 85)`，命中 8 只朱砂档按钮（退出登录 / 确认并执行 / 加白 /

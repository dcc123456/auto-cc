一、提示一律走气泡（2026-10-20 口径）
------------------------------------
① **点开式说明**（卡下读数带那两支）：新增 `DeskHint`（`src/ui/disclosure.tsx`）。
   `chat-hints` 气泡：320 × 108，圆角 12，描边 `rgba(38, 44, 48, 0.3)`（毡案 `line-strong`），
   底色 `rgb(224, 219, 205)`（毡案 `ink-850`），字色 `rgb(65, 76, 86)`（毡案 `slate-300`），12px / 1.625。
   逐字正文：「/tool 开头的消息会真调注册表里的工具（缺省 jd.capture.run）」
   「/plan 开头的一句话交给 agent 规划：先出可见计划，确认后才动手」。
   气泡浮在卡面上（`absolute bottom-full`），**正文展开不再把卡往上顶**——改前 `DeskExplainer`
   会把 footer 撑高、消息流跟着缩，正是用户说的「读一句说明换一次版面」。
   点气泡外面或按 Escape 关上，Escape 把焦点还给触发键。
② **悬停式提示**（图标键）：`DeskButton` 新增 `tip` / `tipPlacement` / `tipAlign` 三个口子，
   气泡走 `group-hover/desk-tip` + `group-focus-visible/desk-tip`，不再挂原生 `title`
   （系统框的字族、底色、圆角不归本仓主题管）。对话屏内 `title=` 已清零（grep 只剩 `data-session-title`）。
   发送键（第 1 档、空输入）悬停：110 × 29，底色 `rgb(212, 206, 189)`（毡案 `ink-750`），
   字色 `rgb(37, 45, 52)`（毡案 `slate-100`），`visibility: visible / opacity: 1`，
   文本是**原因码那句**「先写一句要说的话」（`INPUT_EMPTY`），而不是「发送」——按不动时先回答"为什么按不动"。
   手柄悬停：`visibility: visible`，文本「拖动改输入框高度」。
③ 气泡尾巴是旋转 45° 的小方块（只有朝向触发键的两条边描边），没有手写 SVG（§5.3）。
   顶栏那一排用 `bottom` + `end`，因为上方没有空间且右端会溢出面板。

二、拖拽：手柄搬到上沿，按高度差吸附（真实鼠标读数）
--------------------------------------------------
先记改前的毛病：手柄挂在卡**底边**且参与布局，拖动时卡的上沿在跳、手柄自己不动——
观感是"拖的东西没跟着手走"，也就是用户说的「拖拽也不对」。
现在手柄是卡上沿一条**浮层**：命中区 880 × 12（诚实高度取自 `h-3`），
浮在那 13px 上内边距里，**不占布局高度**；可见横条 36 × 4、圆角全满，
毡案 `rgb(95, 106, 116)`（slate-500）、墨案 `rgb(108, 128, 145)`，拖动中变 `celadon`。
手柄外层包一层 `absolute` 定位层而不是给原件写 `absolute`：`DeskButton` 基座的 `relative`
与 `absolute` 同族、谁赢按样式表顺序算；按钮成为 flex item 后还被块化，不再多出一层行盒（改前卡片因此高 9px）。
拖动读数是**真实 CDP 鼠标**（按下 → 分两步移到 −40 / −80 → 读 → 松手 → 第二趟拖回）：

  start     step=0  textareaH=66   cardTop=555  tip=拖动改输入框高度  data-dragging=false
  dragging  step=1  textareaH=140  cardTop=481  tip=140 像素          data-dragging=true
  released  step=1  textareaH=140  cardTop=481  data-dragging=false
  restored  step=0  textareaH=66   cardTop=555  data-dragging=false

高度取 `起始档像素 + (起点 Y − 当前 Y)`，再在 [66, 140, 220, 320, 520] 里取最近档；
`setPointerCapture` 保证指针移出手柄也继续拖；`localStorage['auto-cc.composerHeight']` 落档。
卡片底边锚定，所以加高时**只有上沿跟着指针走**（cardTop 555 → 481，textarea 66 → 140），
与用户"拖上沿"的直觉一致。缺省档从 6.2-40 的第 2 档（140）改成第 1 档（66），这是稿 `.card textarea` 的矮档。

四、与稿的对照（以及为什么还差一点）
----------------------------------
对齐项：46px 顶栏、卡圆角 16、文本域 66 / 13px 上内距 / 14.5px / 1.8、胶囊 28、发送 32 圆片、
读数带 12px、消息两侧无底色、空会话居中。卡高 127 = 13 + 66 + 46 + 2 描边；
稿上无描边（约 125），差的 2px 就是那两条 1px 边。
三处如实偏差：
① 稿上卡内还有工作区与上下文 meter、附件 / 语音 / 插入三颗图标。前两项没有真读数入口
   （工作区选择器不存在；上下文只在**真折过一次**时才有数字，所以放在卡下读数带右侧）；
   后三颗在 `sandbox: true` 下没有选文件口，按「只补有真读数的」裁定不发货。
② 读数带触发链是 11px（`DISCLOSURE_CLASS` 这一族的既有字档），容器是 12px；比稿面小 1px，
   没为这一格另写一套披露层字档（§2.2）。
③ 6.2-40 读到的卡高 161、手柄在底边，已被本片覆盖；6.2-40 那四张证据保留为"常驻带搬出流"那一轮的快照，
   不按 §4.5 改写。

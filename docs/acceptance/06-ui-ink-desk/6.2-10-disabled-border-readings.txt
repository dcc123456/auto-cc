同一次普查还读出：27 只里 hoverClass 全部为 true —— 因为组件用的是 aria-disabled 而不是原生
disabled（原生禁用不派发鼠标事件，tooltip 就出不来），CSS 的 :hover 对它们照样生效，
于是「按不动的键移上去会提亮」，与 buttonClass 注释里那句「禁用时不提亮」相反。
这是同一个根因的第二条症状，不是第二条缺陷：语义档的 class 无条件拼在禁用分支后面。

二、修复（packages/renderer/src/ui/controls.tsx 的 buttonClass，禁用时整档语义色都不拼）
------------------------------------------------------------------------------------------------
原来：base（含禁用分支的 border-line/bg-ink-850/text-slate-500）+ tone（各档的 border/bg/text/hover）
现在：`const tone = disabled ? '' : <按 variant 取档>`，禁用的画法只由 base 的禁用分支给一份。
为什么不是「只去掉 tone 里的描边」：Tailwind 生成的样式表里同类工具的排序不由 class 字符串顺序决定，
活体上 bg 那一路恰好是禁用分支赢了（bg 全收敛到 ink-850）、text 那一路也是禁用分支赢、
border 那一路三档输——同一个「拼在后面」在三件事上给出三种结果，逐件打补丁只会再来一次。
整档不拼之后：禁用态与 variant 无关（一条代码路径），hover 类也随 tone 一起消失。

四、覆盖矩阵与「seal/jade 无活体禁用样本」这条诚实话
------------------------------------------------------------------------------------------------
探针 rp25-matrix.js（浅色）数出带 data-effect 的键共 263 只节点（含隐藏面板，死键 27 只与第一节同数）：
  line 81 活 / 9 死，ghost 7 活 / 2 死，solid 12 活 / 4 死，amber 108 活 / 12 死，
  seal 24 活 / 0 死，jade 4 活 / 0 死
  另有 7 只 data-action 键没有 data-effect（App 导航条、ChatPanel 档位开关、GapPanel/GeneratePanel
  的证据 chip、MetricsPanel 的 refresh —— 都在第十四片就登记为「不换装」的名单里）
所以 seal / jade 两档这次**没有活体禁用样本可拍**：它们的禁用只由「动作在途」（busy → ACTION_BUSY）
或「选中态/计划态」驱动，取证期间没有任何请求在飞，也没有一条已确认的计划。
补一条 DOM 级的等价证明（探针 rp26-classstring.js）：取四种档的死键各一只，读它们自己的 class 列表——
  canvas-undo  ghost | border ['border','border-line'] | bg ['bg-ink-850'] | hover [] | active []
  canvas-save  amber | border ['border','border-line'] | bg ['bg-ink-850'] | hover [] | active []
  open-editor  solid | border ['border','border-line'] | bg ['bg-ink-850'] | hover [] | active []
  preview      line  | border ['border','border-line'] | bg ['bg-ink-850'] | hover [] | active []
  navigate     solid | border ['border','border-line'] | bg ['bg-ink-850'] | hover [] | active []
四档的死键节点上**根本没有档位色类**（text-[11px] 与 text-xs 的差是 compact 属性，不是档位），
而 buttonClass 在禁用时不读 variant —— 所以 seal/jade 走的是同一条路径，不需要各拍一次才算数。
这一格因此按「构造 + 四档活体」判过，seal/jade 那一格标的是「无样本」而不是「通过」。

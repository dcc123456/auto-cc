一、改了什么
------------------------------------------------------------------------------------------------
1. `packages/renderer/src/AgentPolicyPanel.tsx`：可加白清单里那一只 `add-exempt` 从 `DeskButton`
   换成 `ArmButton`（`action="add-exempt"` + `confirmAction="add-exempt-confirm"`），
   处理器整段搬到 `onConfirm`，**调用的是同一只手**（`agent.policy.setExempt`），没有换实现、
   没有加第二条写库通路。`revoke-exempt` **保持一次点**（08 稿：撤回是安全方向，不该加摩擦）。
2. `packages/renderer/src/ui/controls.tsx` 的 `ArmButton`：这一片是它的第一只消费者，
   原件按真实消费者的需要补了转发（原先它只能传 variant + 禁用两件套，面板要的
   `compact` / `busy` / `disabledReasonLabel` / `className` / `markers` 都进不去，
   调用方就得为第二步再手写一遍样式）：
   `ArmButtonProps extends Omit<DeskButtonProps, 'action' | 'onClick' | 'children'>`，
   除 `action`/`confirmAction`/`onConfirm`/`armedLabel` 四位外整份转给两态共用的 `DeskButton`。
3. 同时删掉一个会说谎的旋钮：`armMs` prop 去掉，武装时长收成模块常量 `ARM_MS = 4000`，
   与倒计时条 `animate-[wash_4s_linear_forwards]` 是同一个数。原先传非默认值会得到
   "条还在走、闸已经关"的两份事实；而条的时长只能由 Tailwind 扫得到（动态拼 class 不生成），
   所以正确做法是钉成一处，不是留一个 prop。
4. 确认一次即解除武装（`onClick` 里先 `setArmed(false)` 再 `onConfirm()`）：不然倒计时条走完前的
   那几帧里连点两下会写进两条。
5. 文案：新增 `agent.policy.armedAdd`（zh「再点一次才写入」/ en「Click once more to write it in」），
   武装态的图标沿用同一只 `ShieldCheck`（§5.3/5.4：不新增图标、不自绘）。

------------------------------------------------------------------------------------------------
基线（浅色，探针 rp27-arm.js）：
  可加白候选 10 行（`outbound.script.generate` / `browser.act.click` / `browser.act.type` /
  `outbound.greet.perform` / `outbound.deliver.perform` / `jd.capture.run` / `workflow.run` /

  `data-exempt-count` = **0**、已加白行 0 只（所以 `revoke-exempt` 在 DOM 里为 0 只，见第五节）
  未武装的 `add-exempt`：seal 档，border `oklab(.../0.45)`、bg `oklab(.../0.18)`、
  color `rgb(192,57,31)`（= 浅色的 seal），rect `74x24`，`data-armed` 节点数 0

第一次真点之后（同一探针，约 1–2 秒内读）：
  `data-armed` 节点数 = 1，且那只节点的 `data-action` 已经是 **`add-exempt-confirm`**（不是同一只键换属性）
  文案从「加白」变成「再点一次才写入」，rect 从 `74x24` 变 `129x24`（窄档不锁宽：这一步不是外发在途）
  倒计时条：`animationName=wash`、`animationDuration=4s`、`animationTimingFunction=linear`、
    `height=2px`、bg `oklab(.../0.7)`（seal 的七档）
  **`data-exempt-count` 仍是 0、已加白行仍是 0、`[data-testid=agent-policy-notice]` 不存在**
    —— 这一行就是 6.2-11 要的判据：第一次点之后名单读数不变，而且连"动作跑过"的回执都没有长出来。

等过四秒（同探针再读）：
  `data-armed` 节点数 0、`add-exempt-confirm` 消失、`add-exempt` 回到未武装形状、
  **`data-exempt-count` 仍为 0**、notice 仍不存在 —— 自动解除，不留状态、不写任何东西。

三、两条容易看错的颜色读数，写清楚
------------------------------------------------------------------------------------------------
第一次读到的武装键是 border `oklab(.../0.7)` + bg `oklab(.../0.28)`，看着像"武装换了色档"。
不对：那是 **hover 档**（`hover:border-seal/70 hover:bg-seal/28`），因为 CDP 真点之后指针停在那只键上。
反证在第二次取证里：同一时刻有两行武装（第一行还挂着、第二行被 `[data-action="add-exempt"]`
这条选择器新命中——已武装那行的 `data-action` 已经改名，所以选不中它），
未被指针压着的那一行读到的正是 base 档 `oklab(.../0.45)` / `oklab(.../0.18)` / `rgb(192,57,31)`，
与未武装时逐位相同。
**结论：武装态不换色档。** 09 稿形态⑤′ 给的状态指示是"文案 + 改名的 data-action + 四秒倒计时条"三件，
朱砂底纹从头到尾是同一份——这只键本来就是 seal（不可逆方向），再加深一档反而读成"更危险了"。

顺带一条从这次序列里掉出来的事实：**两行可以同时武装**（每行自己的 `useState`，互不影响）。
这不是缺陷（各自确认各自的、各自四秒后各自解除），但界面上会同时出现两条倒计时条。
留在记录里，等 08 稿下一次复核时再判要不要收成一格只许武装一只。

五、没取到的（`[!]`，不许冒充通过）
------------------------------------------------------------------------------------------------
1. **第二颗真写库的那一腿没按**。判据要求的是"第一次点不许写"，这一条已经取到；
   而"第二次点会写"走的是搬过去的那同一只处理器，没有新代码。真按一次会往这台机器的
   免确认名单里写进一条豁免（并且撤销之后仍留一条变更痕迹），与第十二/十三片立下的
   "不为了读数改写用户实例"同一口径，所以不按。
   要补这一腿，需要用户在场、指名要免确认某只手，那时点第二颗是办正事而不是取证。
2. **`revoke-exempt` 的活体外观本片没重取**：名单是空的，DOM 里 0 只撤销键。
   它的色值与"一次点"由第十一片的记录（`6.2-06-chat-agent-readings.txt`）与本片源码共同覆盖
   （`AgentPolicyPanel.tsx` 里它仍是一只普通 `DeskButton`，`variant="amber"`，无 `confirmAction`）。
3. **08 稿后半句「第二下该工具行首长出朱砂勾」没做**：那是第二次点击之后的已加白行呈现，
   而名单是空的——没有活体可验的样式不凭推测写。它挂在第 1 条同一腿上，一并等用户指名免确认某只手时落地。
   前半句「第一次点转朱 armed」按"静息已是 seal"处理（第十一片的归属裁定），武装不换色档，
   理由与那条 hover 误读一起写在第三节；详见 spec 的「6.2-11 与 08 稿那两句原话的对齐」。
4. **键盘等价（6.2-07 那条）在本片同样没取**：武装后按 Enter 走的是同一只 `onClick`，
   但"Tab 顺序里第二颗的位置"没测——它要一份非空名单，与第 2 条同因。

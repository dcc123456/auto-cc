6.4-14 · 纸面实时跟着左列翻面，且同一屏只有一份画面——活体读数
================================================================

取证对象同 6.4-12/13（用户自己的 dev 实例，CDP 10222 / 5173，窗口 1200×772，容器 940，全程
`visibilityState:"hidden"`）。两支脚本：`tmp/57b/live57b.mjs`（去抖与"画只画在一格里"）、
`tmp/57b/latency57.mjs`（一次改动到落定的真实延迟）。

----------------------------------------------------------------------
① 计数通道为什么不是"桥接调用次数"（一条必须先说的形状事实）
----------------------------------------------------------------------

第一版想把 `window.autoCC.resume['export.preview']` 包一层数调用次数，**装不上**：预加载里那份命名空间
是 `Object.freeze` 过的（本轮读数 `frozen:true / assignStuck:false`），页面里赋值**静默失败**——
不报错，只是没生效，于是那一版的 `calls` 恒为 0，看起来像"根本没发渲染"（同批还有一条：页面里写 90×200ms
的轮询循环，在 hidden 窗口一路挂到超时，因为 `setTimeout` 被按 1 秒粒度节流——§9 的 6.2 ③；轮询从此放 node 侧）。
那一份读数**不作证据使用**，只留在这里说明计数通道为什么换了。

换成的是一条**同样直接**的通道：给那张纸的 `srcdoc` 属性挂 `MutationObserver`。
每一次真渲染落地都是一次 `srcdoc` 写入；五次连改若各发一趟，计数就是 5；去抖成一趟，计数就是 1。
这一条比"包一层函数"更硬，因为它量的是**产物有没有被重写**，不是某个包装器有没有被调到。

----------------------------------------------------------------------

③ 判据③ 的耗时半边：一次改动到落定到底多久（`latency57.mjs`）
----------------------------------------------------------------------

$ node tmp/57b/latency57.mjs 3
START   {"status":"idle","len":33835,"selected":"modern"}
SAMPLES [{"templateId":"classic","clickToSettleMs":533,"renderingSeen":true,"srcDocLength":33784},
         {"templateId":"modern","timeout":true,"renderingSeen":true},
         {"templateId":"classic","clickToSettleMs":462,"renderingSeen":true,"srcDocLength":33784}]
RESTORED{"status":"idle","len":33835,"selected":"modern"}

→ 两条有效样本：**462ms / 533ms**（点一下 → 看见 `rendering` → 落回 `idle` 且 srcdoc 换掉）。
  拆开就是"去抖 350ms + 一趟跨进程渲染 ≈ 110～185ms"——模板切换这一腿远没用掉 `maxPreviewResponseMs:1200`
  那个预算，所以 350 的窗口不需要往下调（计划里"收口时以活体读数校准"就是为这一条留的）。
  中间那条 `timeout:true` 是**探针的判据缺陷不是产品缺陷**：那一发点回 `modern`，srcdoc 长度回到与
  起手相同的 33835，我拿"长度变了"当落定信号就永远等不齐（`renderingSeen:true` 说明渲染确实跑了一趟）。
  读数保留在此，写判据的人不该再犯同一条：换档类延迟的落定信号要用**状态位**，不是内容指纹。
  最后一行是自证收尾：用户的选中态点回起手那一套（`selected:"modern"`，与 `START` 逐字段相同）。

⑥ 未过的那一腿
----------------------------------------------------------------------

"点一行原文就地改"是片 58 的事，本片没有这一腿。本片**真实指针**相关的是拖把手那一腿（见 6.4-13 第③段末），
不在这里。本片的五处读数全部来自页面自己的回执（`data-status` / `srcdoc` MutationObserver /
`data-stage-mode`），不依赖 CDP 输入落页——`element.click()` 在 hidden 窗口里照样派发 React 监听
（§9 的 2.1-12 补窗那条），所以"处理器跑不跑"这一半是真相；而"人点得动点不动"由 6.4-13 的 `[!]` 那一腿统一欠着。

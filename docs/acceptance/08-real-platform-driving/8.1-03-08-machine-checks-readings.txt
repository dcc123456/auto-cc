三、8.1-04 外发遇未取证定位（`LOCATOR_UNVERIFIED`，六个用例）
═══════════════════════════════════════════════════════════════════════

用例组「未取证定位：外发停手、读取照试（spec 8.1-04）」，`adapter.test.ts` 里把某条定位的候选标成
`unverified` 后交给适配器，断言的是**它一个动作都不发**：

  1) 发送键一条证据都没有 → `LOCATOR_UNVERIFIED`（path `platform.boss`，details `{platform:'boss', locator:'chatSendButton'}`），
     且 `page.navigated === []`、`page.kinds === []`、`act.typed/clicked === []`、`act.waitsStarted === 0`
     —— 「不发起任何动作」含**导航**：连会话页都不打开。
  2) 输入框未取证 → 同样整条停手（另一半还能用也不发半截话）。
  3) 只有部分候选未取证 → 交给 `browser.act.click` 的声明 = 声明里去掉被标那条（`candidates` 逐条比），
     本次外发照旧 `sent:true`；模块级那份知识包**没被改坏**（第一条候选仍是已取证）。
  4) 上传控件未取证 → `LOCATOR_UNVERIFIED`，`page.navigated/kinds` 皆空、`act.uploaded === []`
     —— 下架二次校验那次状态行读取都不发生。
  5) **读取通道仍然试未取证的候选**：把抓取用的 `jobSalary` 整条标 unverified，`search()` 递给 `page.extract` 的
     候选列表仍是原对象（未经筛选），薪资照常读回来。读错一条只是少一条数据，点错一下撤不回来——
     这条分界与 `LocateSpec.effect` 的分档是同一件事的两个侧面。
  6) 状态行属于读取通道：`chatStatus` 全标 unverified 时 `chat()` 仍起等待、仍回 `sent:true`，
     `act.waitFor` 拿到的就是知识包那一个对象（`toBe` 判同一实例，不是筛过的拷贝）。

  ✔ 合规护栏机检通过（…测试面 URL 判据…）
→ 8.1-08：`check-compliance-redlines.ts` 的**判据集合**（哪些主机名允许出现、哪些判违规）一字未动；
  动的是两处，且都不是判据：
  ① `TEST_REAL_HOST_ALLOWLIST` 里 `zhipin.com` 那条的**理由文案**（按 plan 要求补一句：发布包取值面扩大，
     但测试面判据不变——这些用例不发请求、不 attach 真 target）。
  ② 主机名**提取**的字符类补上 CJK 范围（`\u3000-\u303f\u4e00-\u9fff\uff00-\uffef`）。
     原写法 `[^\s'"`/?#\\]+` 会把紧跟在地址后面的全角 `）」` 一起吃进主机段，于是
     `origin 不许带路径、查询或锚（形如 https://example.com）` 这类**被测中文字符串**里的保留域名匹配不上
     RFC 名单、许可域名匹配不上许可名单，假报成违规。这不是判据松动，是提取层的一处假阳性。

  探针（`packages/browser/src/zzRedlineProbe.test.ts`，跑完即删，未入库）：
    const requested = 'https://acme-recruiter.com/jobs';                      → 判违规 ✓（第 1 行）
    const adjacent  = '…源「https://acme-recruiter.com」';                     → 判违规 ✓（第 2 行：主机段剥掉 CJK 后
                                                                                   仍是未登记的真域名，照样拦）
    const trailingFullwidth = '形如 https://example.com）';                    → 不判（RFC 保留文档域名，正是上面那条假阳性）
  $ pnpm exec tsx scripts/check-compliance-redlines.ts   → 探针在位时 EXIT=1 且逐行点名，删除后 EXIT=0。
  → 结论：一个不在许可名单里的真实域名，**无论后面跟不跟中文标点**都照样被拦；被修掉的只有假阳性。

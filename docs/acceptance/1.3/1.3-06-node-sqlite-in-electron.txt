# 1.3-06 前置探测：node:sqlite 在 Electron 44 主进程内可用（实测）

plan §7 把这条列为未决风险（「宿主 Node 24 已确认可用，Electron 待测」）。实测结论：**可用，
无需原生编译、无需 electron-rebuild**，1.3 的 `store.db` 直接走 `node:sqlite`。

探测脚本写在 `docs/acceptance/1.3/tmp/probe-sqlite.cjs`——`tmp/` 按 AGENTS.md §7.5 不入库，
脚本内容可由下面的输出复现。

```
$ node -p "require('./packages/main/node_modules/electron')"   # 取 Electron 二进制
$ <electron.exe> docs/acceptance/1.3/tmp/probe-sqlite.cjs
PROBE {
  "electron": "44.4.5",
  "node": "24.21.0",
  "v8": "15.2.124.28-electron.0",
  "exports": ["DatabaseSync", "StatementSync", "Session", "constants", "backup"],
  "memoryRow": { "a": 1, "b": "hello" },
  "sqliteVersion": "3.53.4",
  "userVersion": 7,
  "diskJournalMode": "wal",
  "diskFiles": ["probe.db", "probe.db-shm", "probe.db-wal"],
  "diskOk": true
}
```

要点：

1. `require('node:sqlite')` 在主进程直接成功，`DatabaseSync` 内存库/文件库都能建表读写。
2. `PRAGMA journal_mode = WAL` 生效（返回 `wal`，磁盘出现 `-wal`/`-shm`），1.3-08 的
   「退出时连接回收 → WAL 收敛」有可断言的观测面。
3. `PRAGMA user_version` 可读写，1.3-07 的 migration 版本号机制不需要自建版本表。
4. 附带 `backup` 导出，后续「导出/迁移用户数据」有现成能力（P1 不用）。

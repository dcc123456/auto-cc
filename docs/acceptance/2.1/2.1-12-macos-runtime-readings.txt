## 一、取到的 mac 半边读数（都算"与 Windows 同表现"的正向证据）

1. **会话分区表在 mac 上是同一形状**：`sessions.status()` 回三只平台，`partition` 分别
   `persist:fixture` / `persist:fixture-alt` / `persist:boss`，`isPersistent: true`，
   `storagePath` 落在 mac 的 userData 下 `…/tmp/v6-userdata/Partitions/<id>`（Windows 那轮的读数同一表达式）。
2. **分区隔离在 mac 上成立（这条是本行的核心）**：在视图里导航 `/login?next=/boss`（fixture 写带 Max-Age 的

   与 Windows 那轮的判定表达式逐字同构（对照 `docs/acceptance/2.1/2.1-04-partition-isolation-1.txt`）。
3. **内核视图能开能导航能读**：`shell.setKernelViewVisible(true)` + `browser.page.navigate(url)` 后
   `shell.getStatus().kernelViewUrl = http://127.0.0.1:10233/boss`，`browser.page.snapshot` 与

## 三、顺带记两条活体坑（本窗踩到，属 §9 那一类）

- `browser.page.navigate` 的实参是**一个 URL**（位置参），平台由"当前 `sessions.open` 绑定的那只"决定；
  把平台名当第一个实参传会得到 `NAVIGATE_URL_REJECTED / 地址无法解析：boss`。
  因此在同一条活体页面里连续测两只平台时，**登录动作会落进上一次 open 的那只分区**——
  上面的判定就是照这个事实写的（登录落进 `fixture-alt`，`boss` 保持空），不是笔误。
- `sessions.status()` 的回值是 `{ ok, value: { platforms: [...] } }`，直接 JSON 打平成 `{}` 的写法读不到东西。

## 五、2026-10-06 第二次补格：抓取行读数取到了，act.click 的真点仍取不到（原因已定位）

实例写法（`pnpm dev` 起第二份必失败）：`ELECTRON_RENDERER_URL=http://127.0.0.1:5173 Electron packages/main/dist/main.cjs
--remote-debugging-port=10299 --user-data-dir=$PWD/tmp/2112-c`。原因：`pnpm dev` 自己会拉 vite，而 5173 已被前一份 dev 占用，
它以 `Error: Port 5173 is already in use` 退出（实测），所以要**复用已在跑的 vite**、只换 CDP 端口与 userData。

三条口径纠正（上一窗按猜的形状作废）：
1. **bridge 是位置实参**：`browser.act.click` 的 args 声明是 `[spec: LocateSpec]`（`packages/shared/src/bridge.ts:1786`）。
   把 `{ spec }` 整包传进去，`spec.candidates` 就是 undefined，于是页面里报
   `PAGE_SCRIPT_FAILED: scanCandidates … reading 'length' of undefined`。`{ spec }` 那个形状属于 **agent 工具层**
   （`packages/browser/src/act-service.ts:484` 的 `input: z.strictObject({ spec: locateSpecSchema })`），不是 IPC 层。
2. **返回值是 `{ok:true,value}` / `{ok:false,error}` 信封**（`packages/ipc/src/gateway.ts:69`），渲染层不会 throw，
   所以"没报错"不等于成功，必须现读 `ok`。
3. `LocateResultView` 里的候选列表字段名是 **`ranked`**（`bridge.ts:2524`），**没有 `matches`**。
   上一窗数 `matches` 因此白等 6 秒并把"有没有命中"读成 null。

### 抓取链路（2.3-01 的「容器 × 字段」批量抽取）——本窗取到
- 声明与 `packages/platform-boss/src/knowledge/boss.json` 的 `capture.list` 同源（容器 `li.card[data-testid=jd-card]`，
  字段 `a[data-field=title]` 取 href、`data-field=company|salary` 取正文）。
- 结局：`containers=5`、`rows=5`、`truncated=false`、`frames=[{url:'http://127.0.0.1:10233/boss', ok:true, error:null}]`。
- 第一行：title「桌面端前端工程师（Electron）」+ attribute `/boss/detail?jobId=1001`（matched:true）、company「星桥科技」、
  salary「25-40K·14薪」；第二行「React 前端工程师」/`jobId=1002`/「云栖数据」/「30-45K」。
- 页面自述（内核视图自己的 target 里读）：状态行「状态：已渲染 5 张卡 · 命中 12 条 · 继续滚动可加载更多」、`li.card` 计数 5。

  （reason「与次优候选只差 0 分，小于最小分差 12」）、`chosen:null`。多条同分是 many 容器的常态，
  所以抓取路径只能用 `page.extract`，不能用 `locate.find` 选容器——不是缺陷，但下一窗别误报成缺陷。

### act.click 的真点——仍没取到，原因定位清楚了
- 连点三次（含把内核视图显式切到可见之后），服务一律返回 `status:'done' / channel:'cdp' / trusted:true`，
  `waitedMs` 落在 5346–6005ms，`located.rect` 是 `{x:29, y:337.74, width:61, height:32.09}`、`frameUrl` 为
  `http://127.0.0.1:10233/locator`（与页面里 `getBoundingClientRect()` 的读数逐位一致，所以坐标没算错）。
- 但页面自己的两套读数都说"没有点击"：
  ① `[data-testid="hit-log"]` 仍是「（尚无点击）」、`hit-placeholder` 还在；
  ② 在 document 的 capture 阶段挂 pointerdown/mousedown/mouseup/click 四个监听，**计数全 0**。
- "事件是不是发到了别的文档"也排除了：同一份探针挂在 app 渲染层（127.0.0.1:5173）上，一次求值里点完再看自己的计数，
  仍是 `eventsInAppDocument: []`。
- 决定性读数是可见性：内核视图页 `document.visibilityState === 'hidden'`（`hasFocus:true`）、
  app 渲染层 `hidden` 且 `hasFocus:false`。也就是整个 app 窗口在 macOS 下处于被遮挡/非前台，
  合成器不给隐藏帧派发输入，CDP 的 `Input.dispatchMouseEvent` 就这么被丢掉。
  `shell.setKernelViewVisible(true)` 回 `{kernelViewVisible:true}` 救不了它——那管的是视图挂载，不是窗口遮挡。
- 所以这一格现在欠的是**「窗口在前台」这个环境条件**（§7.1 的真实窗口），要用户在场把 app 窗口点到前台再重放一次；
  不是本机的逻辑缺陷——同一份 `browser.act` 在 Windows 那轮取到过真点。
- 顺带一条**可报告的设计事实（本窗不改代码）**：`click` 的 `done` 是「派发完」而不是「页面确认收到」。
  `type` 有 `valueAfter` 回读、`upload` 有 `changeCount` + 文件名/字节数回读，`click` 没有任何页面侧回读，
  于是 `trusted:true` 只在"事件通道是 cdp"这个意义上为真，在"页面收到过这次点击"的意义上未经证实。
  要不要给 `click` 补一条页面侧确认（等回执文本/`textAppears` 类谓词），是 P2 的一条独立待裁，不要顺手夹带。


## 六、2026-10-06 第三次补格：窗口已经在前台了，但 click 连派发都没走到（第五节的结论要改一半）

1. **可见性条件已经不成立了**：`appDocument.visibilityState === 'visible'`、内核视图页

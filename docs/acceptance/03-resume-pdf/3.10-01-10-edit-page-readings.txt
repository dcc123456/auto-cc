3.10-04 样式条改字号 / 行距 / 对齐 / 字重 / 字族 / 字色 + 整份度量，每改一次是一个撤销单元（U+V）
--------------------------------------------------------------------------------

界表沿用 `view.metricBounds` 那一张（`OUT_OF_BOUNDS_REACH` 只在界面上把可拖范围放大，
判定仍只发生在主进程 `planDesign`/`planMetric` 一处——§2.5）。滑杆的 `min`/`max` 属性因此是"合法界 ± 界宽×0.25"，
探针从属性把合法界换算回来：`baseFontPt` 属性 1.5…28.5 → 合法 6…24；`lineHeight` 属性 0.5…3.5 → 合法 1…3；
`topMm` 合法 5…40。

段级五格（`tmp/310/p-d-axes.js` + `p-d2-numeric.js`，选中段种类 `summary`）：

| 格 | 改动 | 纸面读数（帧内 `getComputedStyle(documentElement)`） | 撤销 |
| --- | --- | --- | --- |
| 字号 | 拨到 `23.5`（合法上界 24 之内） | `--rz-p-summary-size = 23.5pt`，且 `[class~="rz-summary-size"]` 计数 0→1 | 见下 |
| 行距 | 拨到 `2.95` | `--rz-p-summary-lh = 2.95` | 见下 |
| 对齐 | 点「居中」 | `--rz-p-summary-align = center`，该格 `data-on` false→true | — |
| 字重 | 点「半粗」 | `--rz-p-summary-weight = 600` | — |
| 字色 | 点第一格色卡 `#101820` | `--rz-p-summary-ink = #101820` | — |

撤销单元逐条对账（这是判据里"每一次改动 = 一个撤销单元"那一句）：

- 改动前 `undo = NOTHING_TO_UNDO`、`dirty = false`；拨完字号那一下 `undo = null`（可按）、`dirty = true`、
  `rejected = null`。
- 连撤两步的读数：`step1 { size: "23.5pt", lh: null }`（**只把行距撤掉**，字号还在）→
  `step2 { size: null, lh: null, dirty: false }` → 撤到 `NOTHING_TO_UNDO`。
  两步各自只回一条轴 = 两条轴各是一个撤销单元，不是一笔总账。
- 离散三格（对齐 / 字重 / 字色）各改一次后连撤三步：`undoWalk.steps = 3`，撤完 `dirtyAtEnd = false`、
  `undoReasonAtEnd = NOTHING_TO_UNDO`。

整份文档那六格（右栏）：

- 基准字号拨到 `23.5 pt`：帧内 `html` 计算字距从 `14px` 变 `31.3333px`、`line-height` 从 `21px` 变 `47px`
  （23.5pt 与 2.0 倍的算术自证：14px→31.33px 就是 10.5pt→23.5pt）。
- 上边距拨到 `39.25 mm`：第一段离纸顶从 `57px` 走到 `153px`（左边距没动，`60→60`，说明只改了这一边）。

拒绝路径（判据原文"把字号拨到界表外 → 条上出现主进程那句原因、滑杆弹回"）：

- 段级字号拨到属性上界 `27.5`：`rejected = 这次改动被拒：out-of-bounds：summary.sizePt=27.5 不在 6…24 之内`，
  `readout` 仍是 `10.5 pt`（已提交值），`--rz-p-summary-size` 仍是空、`dirty` 仍是 `false`
  → **越界值没有进文档，也没有生成撤销单元**。
- 再拨到 `28.5`：同一句话换数字（`sizePt=28.5`），`attrValue` 弹回 `10.5`。
- 上边距拨到 `48.75`：`out-of-bounds：topMm=48.75 不在 5…40 之内`，读数弹回 `39.25 mm`、`attrValue` 弹回 `39.25`。
- 整份字号拨到 `3.5`：`out-of-bounds：baseFontPt=3.5 不在 6…24 之内`。
- 颜色这一格结构上拒不掉：色卡只摆 `SWATCH_HEXES` 那几档（§6.6-05 同一口径），人挑不出一个不合法的 `#rrggbb`。

字族这一格（判据原文里有、整屏页到货时**缺的那一格**）：补齐在右栏「整份文档」里，
走的是同一条已白名单的 `resume.editor.design`（补丁形状 `{ body: { fontFamily } }`，与左列那颗
`resume-editor-design-family` 同一条通道），文案沿用既有键 `resume.editor.axes.bodyFontFamily`
与 `resume.editor.family.*`，**不新增语言包键**。活体读数（`tmp/310/p-i-family-sans.js`）：

```
before      { cls: "font-serif", family: 'Georgia, "Times New Roman", "Noto Serif SC", …', srcdoc: "bd735bdd/36463" }
afterSans   { cls: "font-sans",  family: '"Noto Sans SC", system-ui, -apple-system, "Seg…', srcdoc: "80ec6253/36462",
              on: "true", dirty: "true", undoClickable: true }
afterUndo   { cls: "font-serif", family: 'Georgia, "Times New Roman", "Noto Serif SC", …', srcdoc: "bd735bdd/36463",
              dirty: "false", undoReason: "NOTHING_TO_UNDO" }
```

- 纸上的落点是 `<article class="font-serif|font-sans">`（`template-kit.ts:413` 那条 `design.body.fontFamily ?? spec.serif`），
  帧内 `getComputedStyle` 两家族名逐字不同 → 不是"状态改了而画没动"。
- 撤一步之后 `srcdoc` 的哈希与长度都**逐字节弹回**起手那一份（`bd735bdd/36463`）→ 这一格同样是一个撤销单元。

- 另一条探针自身的坑（同一条读数口径）：`undoReason()` 写成 `getAttribute(...) ?? 'NO_BUTTON'` 会把

3.10-05 在纸上拖区块改序（V）
--------------------------------------------------------------------------------

逐字读数（`tmp/310/p-c-drag.js`）：

- 起手顺序 `beforeDrag.anchors = [summary, experience, skills]`（帧内 `[data-rz-section]` 的文档序）。

这一批探针用到的三条口径（写下来防止下一片重踩）

1. 桌台（左列）那一档帧是 `sandbox=""` 的只读帧：父页读它的 `contentDocument` 拿到的是 **null**，

   所以纸面上的锚点/选区类读数都在这一档取。

结论与边界
--------------------------------------------------------------------------------
1) P95 在 7.5～7.8ms 之间两次可复现（语料是确定性的混合进制组合，不用 Math.random，
   所以两次差异只来自机器本身），预算 150ms 的余量是 20 倍量级 → 判 PASS，按 plan §4.3-e
   的边界「只在超预算时才动优化」，本轮不做任何投机性优化。
2) 负载位取 1500 条切片是**远超真实负载**的压力位（真实库是几十到几百条切片，
   1500 条相当于十几到几十份简历），240 次采样是为了让 P95 落在第 228 个样本上——
   几十次采样时 P95 就是最大值，读数没有意义。
3) 0 命中样本 86 次来自查询集里的三个冷门词（北极光半导体 / 量化交易 / 元宇宙）
   与短 token 组合，说明"库里没有"那条腿也被跑到而不是全程只测热路径。
4) 脚本内置三条判定（任一不过就 exit 1，不等人工读表）：P95 ≤ 预算、fetch 存根零调用、
   kb_chunks 与 kb_chunks_fts 行数都等于配置值且孤儿倒排行为 0。
5) 未覆盖（如实声明）：并发检索下的延迟（本轮判据是"千级切片下的检索 P95"，不是吞吐），
   以及向量腿为 `ok` 时的融合开销——本机没有 embedding key，那一路只能在
   单测里用替身跑到（4.3-07 的增益用例已按 `unavailable` / `ok` 两态分别断言）。

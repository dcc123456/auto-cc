--------------------------------------------------------------------------------
实现侧的约束点（为什么读数是干净的，而不是碰巧没写）
--------------------------------------------------------------------------------
- `search()` 只有一条日志：`[kb-profile] 检索 N 个 token / M 条候选 → K 条命中（status · 向量腿 vectorStatus / 语义名单 X 条）`，
  参数全是计数与枚举状态，没有 query 字符串、没有 chunk 文本。
- 查询向量编码失败的 warn 行只记 `AppError.code`，不记 `AppError.message`——
  那一句话里带端点与对端文案，把它抄进日志等于把"谁的 key 在打不通"写进一个通常会被一起提交/贴出的文件。
- 向量补建的读数（`KbVectorSyncResult`）只有计数与模型名，返回值经 IPC 会落进渲染层日志，
  所以 4.3-12 的口径同样适用于返回值而不只适用于 logger 调用点。

判定标准不是「字面量里有没有出现这些词」，而是三件事：有没有对应的包、有没有对应的依赖、
有没有真实站点的访问面。下面按这三条给读数。

说明：没有 resume / kb / pdf / browser / crawler / scraper 这类包名。
`outbound` 是外发**记账与闸门**（1.9），不是外发**执行**；`workflow` 是状态机 + runner 骨架。

-- 2. 第三方运行时依赖全集（跨 19 个包去重，共 9 个） --
@standard-schema/spec, cordis, i18next, lucide-react, react, react-dom, react-i18next, yaml, zod
根 package.json 的 dependencies 为空对象，只有 12 项 devDependencies（构建/测试工具链）。
命中数（应为 0，实测 0）：
  pdfkit / pdf-lib / pdf.js / canvas-editor / turndown / cheerio / axios / got / node-fetch
  playwright / puppeteer / selenium / chromium / tough-cookie
  better-sqlite3 / sqlite3 / level / lowdb
结论：P3（PDF）与 P4（知识库解析）所需的能力库一个都没有引入；P2 的浏览器驱动走 Electron
自带内核（1.8），因此不需要外部依赖，这一点与 1.7-12 的产物审计（asar 内无 node_modules）一致。

-- 3. 外网访问面 --
`grep -rInE "https?://" packages/*/src` 中，除 127.0.0.1 / localhost 之外的命中数 = 0。
真实招聘平台域名（liepin|lagou|zhaopin|51job|boss.com|kanzhun|linkedin）在 packages/*/src 命中 2 处，
两处都不是访问面：
  packages/sessions/src/index.ts:29  —— 注释：「P1 只有本地 fixture，P2 起在此加 boss / liepin」
  packages/workflow/src/runner.test.ts:221 —— 测试里把 'liepin' 当任意平台字符串用
'boss' 作为词命中 7 处，全部在测试字面量 / 注释 / 分区名映射（partitionFor('boss') → 'persist:boss'）里，
无 URL、无选择器、无请求代码。
本地 fixture 站点：scripts/fixture-server.ts，端口 10233（FIXTURE_PORT 可覆盖），只监听 127.0.0.1。

-- 5. 业务词汇只以「契约名」存在，不以「实现」存在 --

packages/renderer/src/UsagePanel.tsx:11 `OUTBOUND_ACTIONS = ['greet','deliver']` 是额度面板的两个动作名。
这三处都不含任何页面操作。对话骨架的兜底回复文案（agent/src/session.ts:383）显式写明
「不接 LLM、不发网络请求，也调不到任何外发能力」。

且有 3 条单测把「调不到」钉住。P1-03 判 PASS。

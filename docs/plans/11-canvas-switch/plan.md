> 立项：2026-11-19，由皇上亲报的故障条目 **2.1-10**（内核视图随窗口尺寸变化未正确重排、空白/错位）落位。

## 0. 裁定与口径（本片的既有决策，非新裁定）

1. **主画布模式（canvas）**：内核视图容器从「右栏 38% 槽位」换成「header 与 footer 之间的内容区」；
   宽度事实唯一来源 = 渲染层实测容器矩形，仍经 `shell.setKernelViewBounds` 单通道上报。
2. **缩放口径**（门下省第 3 轮点名，修正中书省草案的 1409 窗口宽算法）：
   `zoom = min(1, 内核视图宽 / 1224)`，按**视图宽**算，不按窗口宽算。
3. **`setZoomFactor` 走 bridge 白名单**并过四门禁；非法值结构化失败，不静默。
4. **回滚是双路**：① localStorage `auto-cc.kernel-view-mode = 'sidebar'` 走旧 8.8 分支——旧代码整段保留在该分支
   （门下省二选一中选「保留」）；② 必要时 revert 本片实现提交，回到右栏态。
5. **2.1-10 由本片认领**：宽（≥1409px）窄（1000px）两档判据；V 证据**必须真实修改操作系统窗口尺寸**。
6. **四屏判据**：切回四屏（视图隐藏）时 `innerWidth ≈ 左轨 + 主区`，误差 ≤1px（56/184 两档各一次）。
7. 中书省修订与门下省准奏的退役/改写表见 §2，逐条给替代判据；本文件不删任何历史条目。

## 1. 现状与问题基线

- **结构性矛盾**：BOSS 首页是 1224px 起铺的定宽桌面布局（8.0 在场取证；`8.8-05` 边界段实测），
  而右栏槽位 = 窗口 × 38%：1200px 窗只有 456px，展开档也只有 1015px，仍差 209px。
  8.8 换边解决的是「谁说了算」，没解决「窗口本来不够宽」——这就是 2.1-10 报障与「网页显示不全」的共同根因。
- **旧证据不可信**：2.1-10 原 Windows `user32!SetWindowPos` 两档读数与 2.1-01/03/04/07 四张图同字节，
  2026-10-06 证据审计降回未取；当时明确「`Emulation.setDeviceMetricsOverride` 只改页面视口、
  不改 `WebContentsView` bounds，用它拍的两档是伪造的」。本片的窗口 resize 判据继承这条硬约束。
- **当前摆位实现**（canvas 分支的改造对象）：`KernelViewSlot.tsx` 持 `WIDTH_MIN=38 / WIDTH_MAX=72`、
  `--kernel-slot-width`、把手（`useSplitWidth`/`SplitHandle`）、`kernel-slot-expand/hide/show` 与 36px 竖条；
  主进程 `KERNEL_VIEW_WIDTH_RATIO = 0.38` 兜底；`check-renderer-conventions.ts` 第 4 节钉三条同源字面量。
- **机检事实**：`WebContents.setZoomFactor(factor: number): void` 在 Electron 44.4.5
  `electron.d.ts:18724` 有声明（一手读数，非文档转述）；运行期形状由实现片活体核验（§6.2）。
- **活体基线（工部 10222 已回奏，2026-11-19，真实 BOSS 屏）**：窗口内容区 1200×772 DIP、DPR=2 正确落到页面、
  `visualViewport.scale=1`；右栏槽位 bounds `x=745, y=88, w=455, h=654`，BOSS 页 `innerWidth=455` 而
  `scrollWidth=1224` → **横向裁掉 769px（63%）**；槽位摆位本身无歪斜、无空白错位（`slotFits=true`），
  错的是**槽位语义**——455px 装不下 1224px 定宽桌面布局。resize 重排通道（`win.on('resize')→layoutKernelView`
  - `ResizeObserver` 重报，8.8-03/09 那条）实测已存在且工作正常，11 片不新建第二条通道。
    **反向数字（坐实「必须主画布」）**：保持右栏语义要 BOSS 不裁切需 `zoom≈0.37`，字形不可用；
    换主画布后本窗（内容区 1200、左轨 184）视图约 1016 → zoom≈0.83，≥1409 窗 → zoom=1 原生排布。
    两条如实边界：① 该屏 BOSS **未登录**，页面被引到登录页（`_security_check`）——几何读数有效，
    「桌面布局完整」判据须登录态窗口、与 11-05 同批在场取；② 工部读数与探针在 `tmp/dev-observe/`，未入库。

## 4. 设计

### 4.1 模式开关

- 键：localStorage `auto-cc.kernel-view-mode`，取值 `'canvas' | 'sidebar'`，默认 `canvas`。
- 渲染层启动读一次，切换在 reload 后整体生效——不允许两态同屏并存出两份几何事实。
- `sidebar` 分支 = 现状代码路径整段保留（三档常量、把手、竖条、两键、`--kernel-slot-width` 写入、38% 兜底）。
  保留而非删除是本片成立的前提：它是运行时回滚通道；同时它不是死代码——回滚入口真实可达（11-09 反向验证）。

### 4.2 canvas 布局

- 内容区（header 下沿 → footer 上沿，左轨以右）整块为视图容器；右栏 aside 与 36px 竖条在 canvas 态不渲染。
- 控制行（主画布切换键 + 状态读数）摆在上报矩形之外——沿用 8.8-02/04 的同一结构判据 `handle/control.right` 不落入视图矩形。
- 兜底换语义：主进程在收到首份上报矩形前**不铺位**（视图保持隐藏），拒绝 38% 假矩形；收到非法矩形仍走
  `KERNEL_VIEW_BOUNDS_INVALID` 并保留上一份（8.8-06 原样）。
- 上报通道复用 `shell.setKernelViewBounds` 与同一 `ResizeObserver`（8.8-03/09 的通道形状，门下省点名复用），零新增轮询。

### 4.3 缩放

- `zoom = min(1, 容器CSS宽 / MIN_LAYOUT_WIDTH)`。`MIN_LAYOUT_WIDTH` 是平台适配器的单一事实（BOSS 现值 1224，
  证据 = 8.0 在场取证 + `8.8-05` 边界段）；**渲染层不得出现第二处 1224 字面量**，适配器缺值时 zoom 恒 1 并如实提示未适配。
- 新桥方法 `shell.setKernelViewZoomFactor`（args `[zoom: number]`，returns `ShellStatus`，与 `setKernelViewBounds` 同族）：
  校验有限、`0 < z ≤ 1`，否则 `KERNEL_VIEW_ZOOM_INVALID` 保留上一份；白名单登记，绕过 gate 的直调有测试使其失败（§7.3 同款形状）。
- zoom 与 bounds 在同一条 observer 回调里算完一起报，不各开通道；换平台/换视图时现读适配值。
- 判据形状（两档数字与 spec 11-04/11-05 逐字一致，视图宽记 `w`）：**窄档**窗口 1000（< 1120 换档点 → 左轨 56）
  → `w = 1000−56 = 944` → `zoom = 944/1224 ≈ 0.771`，页面 CSS 布局视口 ≈ `w / zoom` ≥ 1224 且 BOSS
  `scrollWidth ≤ clientWidth`、页面可自主滚动（`scrollHeight > clientHeight`，非 app 代滚）；
  **宽档**窗口 ≥ 1409（左轨 184，`1409−184 = 1225 ≥ 1224`）→ `zoom = min(1, 1225/1224) = 1.0` 原生排布。
  本窗 1200（左轨 184）→ `w≈1016` → zoom≈0.83，为过渡读数。
  **V 类布局判据须在登录态 BOSS 窗口取值，且与 11-05 同批在场**；`_security_check` 登录页读数只能证几何，不得冒充布局完整。
- **命中负对照（必须如实登记的风险）**：zoom≠1 改变 CSS px ↔ 设备 px 映射，CDP 输入与接管点的坐标口径要重新量。
  实现片须在皇上在场时验证「缩放后真实鼠标仍能点中站点控件」并把读数归档；不通过则本片降级为
  「canvas 无缩放 + 在场用宽窗」，并把该缺口如实写回 spec，不得静默。

### 4.4 四屏与可见性

- 视图隐藏（`kernelViewVisible=false`）时：`innerWidth = 左轨 + 主区` ±1px；窄窗（<1120）左轨 56、宽窗 184，各测一次。
- 主画布切换键语义 = 视图显示/隐藏（承接 8.8-10 那颗 expand 的用户语言），宽度档键在 canvas 态不存在。
- 内嵌视图截图仍按 §9 既有口径：页面内容证据取自视图自己的 target，app 侧文案取 `--url 5173`。

### 4.5 i18n 与可访问性

全部新键文案走 `kernel.*` 既有命名空间补 bilingual；切换键带 `data-action`、禁用带 `data-disabled-reason`；
`NarrowLabel` 规则在 1120 换档处保持。

## 6. 回滚与恢复验证

1. 一级（运行时）：`auto-cc.kernel-view-mode='sidebar'` + reload → 右栏 38% 三档形态；复测 8.8-10【1】
   （工具行两键 + 竖条）读数成立即算恢复验证通过。
2. 二级（代码）：revert 本片实现提交 → 回到立项前状态（第 4 节机检、1.2-17 字面量判据原样变绿）。
3. 本片不碰 SQLite、迁移号段、配置落盘——回滚没有数据恢复动作；新增 localStorage 键单值可清。
4. 两路回滚都必须跑四门禁各一次并留 EXIT 读数（11-07）。

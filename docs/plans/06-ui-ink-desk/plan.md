## 1. 目标与边界

**目标**：让 app 的界面达到设计稿的四件事——

1. 一套有材质的配色（墨案深色 / 毡案浅色），三色效果归属贯穿全 app；
2. 一条清晰的分区导航（对话是第一入口，岗位 / 简历 / 流程 / 信任是四张工作台，诊断低一档）；
3. 一套统一的控件行为（五态：默认 / 悬停 / 按下 / 进行中 / 结果），点击后果只允许六种形态；
4. 每个可点的东西都有 `data-action` 与键盘等价，harness 能点到、能截图取证。

**边界（明确不做）**：

- 不改 `packages/**` 里除 `renderer` 之外的任何包；不动 service、IPC 契约、工具注册表。
- 不新增页面能力、不新增数据源；设计稿里有但当前没有后端支撑的控件（例如"批量外发确认"的批量选择）
  只在**已有能力**的范围内做样式，能力缺失的条目在 spec 里标 `[ ]` 而不是伪造。
- 不引入 CSS-in-JS、不引入第二套样式入口（AGENTS.md §5.1，机检在 `scripts/check-renderer-conventions.ts` 第 1 节）。

## 3. 选型与证据（AGENTS.md §6.1/§6.2）

### 3.1 令牌怎么进 Tailwind：`@theme` + 运行时覆盖，实测过

- **候选**：① 手写 `theme.css` 第二份入口；② `@theme` 定义令牌；③ JS 侧 `tailwind.config` 的 `theme.extend`。
- **否决 ①**：`scripts/check-renderer-conventions.ts:52` 只允许 `globals.css` 一个样式文件，第二份入口直接 lint 失败。
- **否决 ③**：当前装的是 Tailwind v4（`packages/renderer/package.json` 的 `tailwindcss ^4.0.0` + `@tailwindcss/vite`），
  v4 的官方口径是把令牌写进 CSS 的 `@theme`，JS 配置不再是主路径；项目里没有 `tailwind.config.*` 文件。
- **采用的机制**：`@theme` 里的 `--color-*` 会同时生成 utility **并**以 CSS 变量形式被 utility 引用。
  因此 `[data-theme='light']` 里重新赋值同一批变量，就能在不改一行业务 class 的前提下整屏换主题。
- **本机实测（2026-10-06，非文档转述）**：现有构建产物 `packages/renderer/dist/assets/index-fEm4nybQ.css` 里
  可以 grep 到 `var(--color-slate-900)` / `var(--color-slate-950)`——证明 utility 走的是变量间接引用，
  运行时覆盖成立。这条是 6.1 全部做法的前提，若在后续版本失效，验收以 `grep` 该产物为判据。

### 3.2 存量 class 的处理：重映射色阶，不逐文件重写

全 app 的面板现在都用 `slate-*` 阶（约 20 个面板文件）。两条路：

- **A**：逐文件把 `slate-*` 换成 `ink-*`——一次改动两千多处，diff 淹没真实变更，且极易漏。
- **B（采用）**：把设计稿的墨案色阶**映射到 slate 阶上**（`--color-slate-50…950` 重新定义为 ink 的等亮度档），
  同时新增语义令牌 `--color-seal / jade / amber / celadon / paper`。整个 app 一次换装，
  新代码用语义令牌，存量代码不动。AGENTS.md §2 的"以逻辑复用为荣"在这里读作"不复制两千处 class"。
- 代价与补偿：`slate` 这个名字不再表达真实色相，读代码时靠 6.1 的注释与 spec 的映射表对齐；
  语义色（三色效果归属）必须走新令牌，不许再用 slate 表达风险。
- **补记（6.4 第二片，同一条策略用到默认色阶上）**：`slate` 收编之后，源码里还剩 **450 处**
  Tailwind 默认色阶用法（实测 tally：`rose` 125 / `emerald` 115 / `amber` 101 / `sky` 91 /
  `indigo` 11 / `violet` 6 / `red` 1，分布在 34 个文件）。这些是"红=失败、绿=成功、蓝=进行中"的临场配色，与三色效果归属**撞语义**：
  例如工具卡片把「进行中」画成琥珀色，而琥珀在设计口径里只说"这台机器在等人"。
  同样走 B 路线——把 `--color-rose-*` / `--color-emerald-*` / `--color-amber-*` / `--color-sky-*` /
  `--color-violet-*` / `--color-indigo-*` 的**值**并进 seal / jade / amber / celadon 四族
  （浅色主题整条色阶反向，与 slate 同一处理），于是不存在"跑到体系外的颜色"这种缺陷类别了。
  代价：这六个色阶名在源码里失去色相含义，读代码时看注释；新增代码一律用语义令牌或 `seal/jade/amber/celadon` 族。
  明确不做的事：不给图表另留一套调色板——`MetricsPanel` 的漏斗分级用的是 `slate-*` 与语义色，
  没有依赖被收编的这六族来区分品类（收编后逐屏截图复核过，见 spec 6.4 落地记录）。

### 3.4 主题偏好的存储：localStorage，与隐私声明同一条路

- 候选：① 新配置键走 `plugins.saveConfig`；② localStorage。
- **否决 ①**：AGENTS.md §9 已实测——配置层只写内存运行时层，**从不落盘**（重启即失），
  且任何配置变更都会重建注入它的下游服务。主题偏好是"跨重启仍然算数的人的表态"，配置层给不了。
- **采用 ②**：与 `usePrivacyNotice` 同一存法（`PrivacyNotice.tsx`），不构成"第二套状态存储"，
  因为它只是渲染层 UI 偏好，不是业务事实；不新增迁移号段。

### 3.5 原件放哪：`src/ui/` 一个目录，不新增包

AGENTS.md §4.3 要求新功能先归入已有包——全部落在 `packages/renderer`。
目录内固定分区（`src/index.ts` 是唯一出口的规则针对跨包，渲染层是应用本体，`ui/` 只被同包引用）。
五态与浮层的**动画关键帧**只能写在 `globals.css`（Tailwind 的 `--animate-*` 需要 `@keyframes` 同处定义），
这是 §5.2 允许的那一个 `@layer` 例外，在 plan 里登记、在 spec 里逐条验收，不得扩散成第二份样式文件。

### 3.6 岗位屏三段式（6.4-04）的数据源与选中语义

判据是 spec 6.4-04："点一行出详情、动作区跟着那一行走，不再是一列 12 行行内按钮"。它改的是信息架构，
按 §6 先补取证再动。

- **详情数据源**——候选 ① 新增 `jd.store.get(id)` 现读那一条：
  **否决**。`JobRowView`（`packages/shared/src/bridge.ts:2663-2689`）已经带着
  `description / requirements / sourceUrl / capturedAt / detailCapturedAt / replied / inboundCount`，
  为同一个界面再开一条读路径就是第二套实现（§2.5），还要多占一条 IPC 白名单（§8.2）。
  **采用 ②**：详情与动作都从已载入内存的那一行 `JobRowView` 现读，选中态是渲染层的本地 state，不进库、不发 IPC。
- **选中形态**——候选 ③ 保留行内按钮、点行弹抽屉：
  **否决**，08 稿「岗位行（列表项）」那一行写死的是形态 ⑥ 选中，原话"点行 = 选中并让中栏 JD 换内容（**不是弹窗**）"。
  采用与 `ScriptPanel` 候选行**同一条实现**（radio group + `border-celadon/50 bg-celadon-wash`，§2.2/§2.5：
  同一件事不再长第二套画法），radio group 顺带白送 08 稿要求的 ↑↓ 换行。
  选中色走 **celadon 不走 jade**，与第十片同一条理由（jade 是"已核"，"人挑了这一行"只是当前指向）。
- **未选中时的动作段不出现**（而不是摆两只按不动的朱砂键）：没人指定目标时外发键根本不该在屏上，
  这比"画出来再禁用"更符合 §8.3；因此本片不新增原因码。
- **本机实测（取证前置，`tmp/v6b/rp28.out`）**：dev 实例（`AUTO_CC_USER_DATA_DIR=tmp/v6-userdata`）
  `jd.store.list(12)` 回 `{total: 0, rows: []}`、`store.status` 回 `{total: 0, withDetail: 0, schemaVersion: 29}`；
  `packages/platform-boss/src/knowledge/boss.json` 的 `startUrl` 是 `http://127.0.0.1:10233/boss`（本地仿站，
  正是 §7.2 要求的那一路），但那份开发档的 `automation_consents` 表**为空**——抓取的界面拦截点 ① 会先长风险确认卡，
  而签字是人的表态，无人在场我不替用户签（§8.3 与 5.3「不可自提升」同一口径）。
  所以详情段的活体数据由**直接往那份被忽略的开发档 SQLite 插两条演示行、取证后删除并把 `total` 读回 0** 提供：
  绕过的只是抓取流水线（不在 6.4-04 射程内），`jd.store.list → JobRowView → 渲染层` 这条读路径全是真的。
- **一条连带影响（写清楚，不默默改）**：`greet-<jobId>` / `deliver-<jobId>` 两个 `data-action` 字符串一字未改，
  但**只有选中一行之后才出现在 DOM 里**。2.5-f 与 6.4-01 那批按"整列行内都有 greet"写的探针口径，
  今后必须先选行——这是本条判据故意要改的东西。

### 3.7 算子从调色板拖进画布（6.5-04）的事件通路：取证

判据（10 稿⑤⑧ + 08 稿那一行）：**拖动中朱砂虚线 + 原槽位留 40% 透明残影，落点是青瓷虚线框**；
08 稿同一段另钉了三条行为——"新节点带默认参数落在光标处"、"**松手才建**，中途 Esc 取消"、"运行中面板整体禁用"。

- **候选 A：HTML5 原生拖放**（`draggable` + `dataTransfer` + `onDragOver` / `onDrop`）——react-flow 官方
  的 sidebar 例子走这一条。**否决，两条理由**：
  ① 本项目的活体取证通路是 CDP `Input.dispatchMouseEvent`（`packages/testing/src/cdp.ts:489-508` 的 `drag`
  就是 `mouseMoved` → `mousePressed(buttons:1)` → 分步 `mouseMoved` → `mouseReleased`），Chromium 要
  `Input.setInterceptDrags` + `Input.dispatchDragEvent` 才派发出 `dragstart`/`drop`，走 A 等于让这条 V 判据
  在 harness 里取不到真点，只能拿页面里合成的 `DragEvent` 假装——§7.1 明令不许用单测/合成事件替代 V 类；
  ② 同一张画布上**已经有一种拖拽**（格子挪位），它不是 HTML5 拖放：安装包实测
  `@xyflow/system@0.0.83` 的 `dist/esm/index.mjs` 里 `mousedown` 出现 5 次、`mousemove` 3 次、
  `dragstart` **0 次**。同一条画布上长出两套拖拽事件族，正是 §2.5 禁止的那种"两个都能用"。
- **采用 B：鼠标事件**（`onMouseDown` 起手 → `window` 上的 `mousemove` / `mouseup` 跟踪 → 越过阈值才算拖、
  否则仍按原来的"点一格建格"走）。与格子拖拽同一事件族、与 harness 的派发同一套原语，
  且**不改动 5.10-03 已取证的点击建格通路**（阈值以下行为逐字不变）。
- **落点怎么换算**：`flow.screenToFlowPosition({ x: e.clientX, y: e.clientY })`。一手来源是**安装包内的声明**
  （`@xyflow/react@12.12.0` 的 `dist/esm/types/general.d.ts:147-160`，官方 docstring 写的正是
  "useful for implementing drag and drop from a sidebar"），不是博客转述（§6.2）。
  顺带读到一个必须避开的兜底：`dist/esm/index.mjs:559-563` 在 store 里 `domNode` 缺失时**原样返回 client 坐标**——
  所以隐藏视图（宽高 0，§9 的 5.4-b ⑦）里拿到的读数不能信，本片只在画布 rect 命中时才落点。
- **"位置不进指纹"这条不能破，且它破不了**：落点只写进视图层的 `dragOffsets`
  （`WorkflowCanvas.tsx:241` 持有、`:336` 读取、`:354-366` 由 `onNodesChange` 更新），
  命令栈拿到的仍是 `draftNodeSpec` 那七个字段、**没有 position**；`packages/workflow/src/graph.test.ts:79-88`
  已经把这条钉成结构判据（指纹函数的形参里根本没有落点，"挪位置"在结构上够不到执行身份）。
  本片因此**不碰**这两处，只在落地后复核一次"拖完撤销一次，格子数回到拖之前"。
- **一条明确不在本片的东西**：10 稿⑧ 后半句"自动接上被穿过的那条边（插队而非并列）"与⑥"外发算子拖入即挂停靠"
  都**不做**。前者改的是图的拓扑规则（要判"落点压在哪条边上"、且现有的点击建格不会插队，
  同一条画布长出两种"加一格"的拓扑语义就是 §2.5 那类缺陷），后者要的"停靠"在数据模型里还没有对应字段；
  两条都超出 6.5-04 的判据（判据只要求三态视觉 + 落点框），按 §2.6 不在样式片里扩张。

### 3.8 09 稿形态⑤ 那五只弹窗的落点：先解决⑤-1 与 spec 2.7-06 的冲突（2026-10-06 裁定）

**冲突**：`09-dialogs.html` 的⑤-1 写的是「**冷启动一次** · app 级表态 · 不同意并退出」，
而已落地并验收过的 spec 2.7-06 是「**按平台、动作前**、库里 `automation_consents` 那一行为凭、fail-closed」
的拦截点①（`useConsent.ensure(platforms, action)`，三块面板共用）。
两者不是同一件事的两种画法：前者要在启动时就替 app 决定"用户已经表过态"，而后者的判据恰恰是
**签字属于某一个平台、且只在真要动那个平台之前问一次**。照稿做冷启动 = 新写一份 app 级签字语义
（要么新增一支迁移存"app 级已签"，要么把 app 级映射成"对所有已配置平台各签一次"），
还要一条 `shell.quit` 口——那既不是样式片，也会让同一件事长出第二份真相（§2.5），
按 §0 的冲突条款先停下来提出，不自行打破规则继续写。

**裁定（用户 2026-10-06 通过对话选定）**：**把现有拦截点① 弹窗化**——判定语义一字不动，
只把"等签字"那一层的画法从行内卡片升成 09 稿形态⑤ 的遮罩弹窗（Esc 不关、点遮罩不关、必须勾满才能签、
焦点落在安全动作）。冷启动那一次**暂不做**，稿上「不同意并退出」也**不做成退出 app**：
现有安全动作是 `consent.deny`（丢弃挂起的动作、一个页面都不碰），它与稿上的退出同一语义方向
（不签字 → 什么都不发），而退出进程属于 `shell` 而不是样式片。

**落点选择（为什么在三块面板就地渲染、而不是提到 `App.tsx` 挂一只）**：
隐藏视图的容器是 `display:none`（`App.tsx` 的 `workspace()` 用 `${view === … ? 'flex' : 'hidden'}`），
而 `display:none` 的祖先会把它下面的 `fixed` 后代一起藏掉——于是"同一时刻只 1 只遮罩弹窗"
由视图常驻结构**天然保证**，不必为新浮层再挂一份跨面板汇流（对比 `deskToast.ts`：
toast 是**六张视图都可能报**的通道，才值得汇流；签字弹窗只在"人刚点过的那一块面板"里等表态）。
这一条要拿活体判据（切走视图之后弹窗不在画面上），不是纸面推理。

**明确不在本片的**：① 背景容器挂 `inert` 把 Tab 锁死在弹窗内——那需要"哪一层浮层开着"这份事实
从面板传到外壳的**顶层容器**，是一件独立改动，立 **6.2-13**；② ⑤-2 批量外发确认、⑤-3 批量拒绝改动、
⑤-4 导入冲突、⑤-5 清空本机数据打字确认——后三只的**数据来源当前都还没有白名单口**

### 3.9 渲染层只留一套 UI 基础设施：令牌层 + 原件层（2026-10-07 裁定）

**问题的提法**（用户的原话是"三套 UI 基础设施并存：外部组件库 / 自定义封装 / 原生 HTML 控件"）。
先按能力做一次普查，把"三套"换成读数：

- **外部 Web 组件库：0 套。** `packages/renderer/package.json` 的运行时依赖只有 react、react-dom、
  react-i18next、lucide-react、@xyflow/react，没有任何 UI kit（无 shadcn/radix/antd/mui/headlessui）。
  唯一的第三方 chrome 是流程图画布的 `@xyflow/react`：它自带一份 `dist/style.css`（在 `main.tsx` 里
  import），并渲染一对 `<Controls>` 按钮。**这一条是本片唯一真实存在的"第二套"**，且它管的是画布内部，
  不参与页面其余部分的表单与浮层。
- **自定义封装原件：已在 `src/ui/`（`controls.tsx` 的 `DeskButton` / `Banner` / `FIELD_CLASS`、
  `overlays.tsx` 的 `Toast` / `Drawer` / `Modal` / `useOverlayBehavior`）。** 这一套是当前唯一有
  层级表、有门禁口径、有双主题读数的实现。
- **原生 HTML 控件裸用：54 处。** 计法：`<input>` 30、`<select>` 13、`<textarea>` 6、`<button>` 5，

  `aria-disabled` + `data-disabled-reason` + `title` 三件套，也就绕开了 harness 唯一能断言的通道。

  `ConsentModal.tsx` 之前是行内卡片（第二十五片已收进 `Modal`）。

**裁定（用户选定，逐字）**：

1. **机检时机 = 「全换完再上机检」**。54 处裸原生控件全部迁进原件之前，**不**把
   "禁止 `src/ui/**` 之外的 `<button>/<input>/<select>/<textarea>`" 写进
   `scripts/check-renderer-conventions.ts`，也不留基线豁免清单——留清单等于承认两套并行合法。

## 5. 设计不变式 → 代码不变式

| 设计稿不变式                 | 代码侧要求                                                                   |
| ---------------------------- | ---------------------------------------------------------------------------- |
| 对话是第一入口               | `App.tsx` 默认 view 仍是 `chat`（§5.9，spec 1.11-01 不许回退）               |
| 切换视图不卸载               | 每个工作台一个 `<section>`，只改 `display`（spec 1.10-01）                   |
| 诊断比主视图低一档           | 诊断入口的字号 / 对比度低于四张工作台（spec 1.10-07）                        |
| 外发必经闸门                 | 外发按钮只做样式，点击仍走既有 `useBridgeAction` → `entitlement.gate`        |
| 档位不可自提升               | 档位指示是只读展示，不新增任何"提升档位"的样式入口（spec 5.3）               |
| 六类点击后果，不许第七类     | 浮层只用 `ui/` 里的原件组件，禁止就地散落 `alert` / 自制遮罩                 |
| 每只可点控件有 `data-action` | 原件组件强制要求 `action` prop；存量按钮逐个补                               |
| 三色效果归属不许串           | seal=外发/风险/签字，jade=已读已核，amber=本机写入/等人，celadon=进行中/证据 |

## 6. 风险与回退

1. **slate 重映射会影响所有存量截图**（`docs/acceptance/**` 是历史证据，不重拍、不改写）。
   判据只看当前视口，历史证据按 §7.5 保持原样。
2. **浅色主题在嵌内核视图槽位上会露白**：视图槽位是占位文案，不是我们的 DOM；
   槽位背景跟随 token，内核真实页面内容不受控（§9 的 2.1 补片：`shot --url 5173` 截不到原生子视图）。
3. **信息架构改动会打到 harness 选择器**：`scripts/smoke-dist.ts` 依赖 `[data-view="chat"]`（第 270/276 行）。
   本片保留 `data-view` 属性名与 `chat` 取值，四张工作台用新 `data-view` 值追加，不重命名既有的。
4. **i18n 缺键即 lint 失败**（§10 已落地）：新增文案必须 zh-CN + en 同时补齐，占位符实参齐不齐也查。
5. 若 6.1 的运行时覆盖在某次 Tailwind 升级后失效：回退方案是两套 `@theme` 由构建期切换，
   但那会引入第二份样式入口 → 触发 §5.1 例外申请，届时先停下来提冲突，不自行打破规则（文件头约定）。

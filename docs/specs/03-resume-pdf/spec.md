### 3.1 验收记录（2026-10-01，本机 Windows）

**迁移号段撞号的就地修掉（值得记，因为 boot 抓不到）**：本包初稿把全局号段末位当成 5，误占 `6`——而 `6` 已被 consent-store（spec 2.7-06）占用。`ensureSchema` 是「见号已存在就跳过 push」的幂等设计，所以撞号**不抛错**，而是让后挂载的 resume-doc **静默不建 `resume_docs` 表**，直到读写才炸「no such table」。更关键：**正常启动 Electron 也照不出来**——devtools 面板把服务显示成 `active`（init 与 ensureSchema 都没报错，只是没 push），任何不碰 `resume_docs` 的路径都不会暴露。收口时人工枚举全局号段（账本 1 / agent 会话 2 / jobs 3 / workflow run 4 / conversation 5 / consent 6）确认 resume-doc 应取 **7**，并把这条做成**可执行护栏**：`doc-store.test.ts:83` 断言 `RESUME_DOC_MIGRATION_VERSION ∉ {1,2,3,4,5,6}`。今后再撞号，`pnpm test` 会红，不依赖人肉记号段。

**显式顺延（不是漏做，是没有调用方就预置=造死代码）**：3.1 没有渲染层入口，`resume.*` 的 IPC 白名单键（`RENDERER_ALLOWLIST` / `BridgeCall`）**不在本片添加**——等 3.2/3.3 界面真正 `cordis:call` 时再随调用面开，避免提前铺无用的安全暴露面（§2.4 / §8.2）。

### 3.2 验收记录（2026-10-01，本机 Windows）

**本片交付的是「模板 = 纯函数 + 注册表 SPI」这一能力**，落在 `packages/resume-doc`（§4.3：属于既有包，不新建）。测试在 `template.test.ts`（21 例），四道根门全绿（typecheck / lint / format:check / test）。

U/C 可现在兑现的六条：

- **3.2-01**：`resumeTemplate.render(doc, id, locale)` 输出确定性 HTML；同一 doc+模板+语言两次字节一致（不读时钟 / 不读随机），产物含姓名与字段值。
- **3.2-03**：`list()/get()/render()` 三个方法构成 SPI；内置 ≥3 套（classic/modern/minimal）；`get(未知)` 返回 null、`render(未知)` 抛可读错并列出可用 id；测试**运行期 `register()` 一套新模板**后立即出现在 list、render 可用、重复 id 被拒——`list/get/render` 源码一字未改，直接兑现「新增模板不改核心」。
- **3.2-04**：核心槽位（经历/项目/校园的公司+职位、教育的学校）缺失时抛 `TemplateBindingError`，带 `sectionKind` + `fieldKey` + 本地化区块名；三套模板共用同一 `toEntryView`，故同一处绑定缺陷在三套里都可定位（各测一例）。可选字段（电话）缺失只跳过不抛。
- **3.2-05**：扫描 `internal/templates.ts` 源码，断言无 `.slice(` / `.substring(` / `Math.` / `new Date` / `toFixed(` / `parseInt` / `parseFloat` 等业务加工；模板只做「取数据视图 → 拼 class」。
- **3.2-07**：产物 `class="…"` 齐、无 `<style>`、无 `style="`；模板/基元源码不 import 任何 `.css`（1.2-13 口径的生成轨版本）。
- **3.2-10**：每套模板 `origin` 字段标 `clean-room-rewrite`，文件头写明「未从 ai-resume 拷贝 HTML/代码，仅沿用『模板=纯函数』形态」。因**无任何 ai-resume 代码进入本包**，抽取许可问题在 3.2 未被触发——这不放宽 `ai-resume` 所有权仍为 `[!]` 的前置门禁（3.3-13 / 3.4-09 若真要抽取才生效）。

四条显式挂 `[!]` 的理由（都是「要打印才验得了」，不是漏做）：

- **3.2-02 / 3.2-06**：`V` 类判据是「**导出后**逐页截图」——逐页位图依赖 3.3 的 `webContents.printToPDF` 管线，3.2 没有打印出口。i18n 切换的**逻辑**已由 3.2-06 的单测覆盖（zh→`工作经历`、en→`Experience`，且 `星桥科技` 数据不随语言变、en 联系人出现 `Email:`），只有截图腿顺延到 3.3。按 §7.1，`V` 类没有截图证据不得写 `[x]`，故记 `[!]`。

- **3.2-09**：`U` 腿（超长 5000 字成果不被截断、条目不被丢弃、不重复）已过；`C` 腿「页数随内容增长」需要打印侧回写的 `metrics.pages`（正是 3.3-09 的判据），在 3.2 无法断言，故整条挂 `[!]`、待 3.3 收。

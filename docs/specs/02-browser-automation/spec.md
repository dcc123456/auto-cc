- 热改配置（`plugins.saveConfig`）会重新装配内核并**关掉已打开的内核会话视图**，

  改配置 → 重开会话 → 跑。这属 1.5 插件运行时与 1.8 会话服务的交互面，另计条目。
- 诊断视图的「已重试 k 次」只统计已终结节点的 DB attempts，重试在途时会读到 0
  而播报已写「第 2 次失败」；两处口径不同源，看板接线（P5）前需统一。
- 证据文件名 `<runId>-<nodeId>`，重试同一节点会覆盖上一次证据，只保留最后一次的现场。

**2.5-e（发送编排）收口记录**：

- 编排顺序在页面上逐项撞过一遍， precedence 是**渠道 → 幂等 → 内容 → 额度 → 频控 → 发送 → 落账**：
  平台名写错时在生成话术之前就失败（不花钱写一段发不出去的文案），黑名单压过额度（`daily/2` 已用尽时
  仍报 `OUTBOUND_FORBIDDEN_CONTENT` 而非 `QUOTA_EXCEEDED`）。读数见 `2.5-02-gate-rejected.txt`。
- 「渠道从哪来」在本切片被推翻重做一次：原先 `outbound.greet` 自己存一张渠道表、由平台包在挂载时推进来，
  实测发现**改一次上游插件配置会连带重建 `outbound.greet` 并重跑 `[Service.init]`，那张表当场清空**，
  打招呼从此静默失败到重启为止（`OUTBOUND_CHANNEL_MISSING {registered: []}`）。现在渠道由
  `platform.registry` 实现 core 的 `GreetChannelSource`，编排层每次外发**按名字现问现取**，
  适配器是唯一事实来源。修复后的证据是同一次运行里 `saveConfig(outbound-throttle)` 重建了编排服务，
  紧接着的第二条照样发出并落账（`2.5-02-pull-model-readout.txt` 末四行日志：每次就绪都读到 `boss`）。
- 频控的钟是**账本最近一条 greet 的 ts**，不是内存里的时间戳：把区间收成 30s 单点后，页面连发两条得到
  `waitedMs=19496`（第一条发送本身耗掉约 10s）与账本 ts 差恰好 30000。
- 遗留（不假装过）：① 2.5-02 的 V 半边「界面显示拒绝原因」要有打招呼按钮的界面入口，随 2.5-f 补；
  ② 闸门拒绝只抛 `AppError`、不写日志，工作流节点路径的失败有 run 证据，单次界面触发则只在回执里，
  若 2.5-f 之后仍觉得「为什么这条没发出去」难复盘，再补一行 warn；
  ③ 用量面板是挂载时快照 + 手动「重新读取用量」，外发后不会自己跳动（本次靠点按钮取到 6 条）。

**2.5-15 反向验证结算（2026-10-04，读数见 `docs/acceptance/2.5/2.5-15-reverse-validation.txt`）**：

§6.5 要的是一条结论——"不引入 OCR"到底有没有把主线撞出一个补不回来的洞。四条独立证据，
每条都只说"没有洞"，不说"我们不需要"：

1. **能力面**：活体 `agent.tools.list()` 的 17 只登记工具（逐字清单在证据文件①）里没有任何
   图像→文字识别口，被否决的那只 `recognize_image` 没有同位物；最接近的 `browser.page.snapshot`
   读的是 DOM 文本，不识别图、也不回填验证码输入框。
2. **依赖面**：根与各包的 `package.json` 检索 `tesseract|opencv|jimp|sharp` 零命中；
   第三方打码服务（`2captcha` 一类）本来就是 2.7-02 那条机检的字面量之一，在 `pnpm lint` 链内。
3. **需求面**：全 docs/specs 检索「验证码 / captcha / OCR」共九处，逐处归类后**没有一处要求识别**
   ——它们全是反向条目（2.1-09 脱敏、2.5-10 与 4.6-12 禁外发、2.7-01 检测即停、2.7-02 明确不做、
   2.8-11 人来解完再重读 DOM、4.1-05 不引入、5.5-07 一律转人工接管）。
   所以换掉的只有"无人值守地闯过去"这一件，而那正是 §8.3 明令不许要的。
4. **替代路径确实通**：风控页把 run 停在可恢复点 + 界面横幅通知，人工处理后点续跑 →
   同一 run 三个节点依次 `done`（2.7-01 的 `2.7-01-captcha-paused-panel-3.png` /
   `-captcha-page-4.png` 与 `-risk-signal-6.txt`，V 半边按本行判据里的"与 2.7-01 联验"取这一组）。

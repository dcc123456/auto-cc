# 计划八 · 真实站点驱动 — 验收 Spec（8.0 / 8.1 / 8.2 / 8.3 / 8.4 / 8.5 / 8.6 / 8.7）

> 实施计划：`docs/plans/08-real-platform-driving/plan.md`
> 方式：**V** = 可视验收（CDP harness 驱动真实窗口，截图与 DOM 断言一律带 `--url 5173`，须留证据）；
> **V-人工** = 真实招聘平台上的验收，**必须用户在场、本人账号**，harness 对真实 target 只 attach 读取、不 navigate；
> **C** = 命令/脚本机检；**U** = 单元/集成测试。状态：`[ ]` 未验 / `[x]` PASS / `[!]` BLOCKED（必须写原因与解除条件）。
> 证据归档：`docs/acceptance/08-real-platform-driving/<条目ID>-*`；V 项无截图不得置 `[x]`（AGENTS.md §7.1/§7.4②），
> 收图前整批跑 `md5 -q | sort | uniq -c` 去重（§9 实测 5.10-18 / 3.6-c ⑭）；量几何与读色前先冻结动画并在收尾摘掉（§9 实测 6.2 二三/二四片）。

> **条目统计**：32 条（8.0×6 / 8.1×8 / 8.2×4 / 8.3×4 / 8.4×3 / 8.5×3 / 8.6×3 / 8.7×2 + 收尾 1 段）。
> **本计划总基调**：验收的是"这台机器在真站点上到底做没做成人的动作"——
> 说搜到了要 `jobs` 表真增行，说发出去了要页面自己回读「已送达」，说送达了要 `delivery_records` 有行；
> **一切以页面与库的读数为准，不以 `browser.act.*` 的返回码为凭**（§9 实测 2.1-12）。

## 8.8 内嵌视图几何换边（2026-10-08 用户在场点名）

用户报的现象是"网页显示不全"，根因不在真站点而在摆位权属：主进程按固定 38% 硬铺、且 `y:0` 起铺满整高，
于是右栏只有 456px（BOSS 的桌面布局必然裁切），而原生视图同时盖掉了顶部标题栏与底部状态条。
这一片正是 P6 早就记下的缺件 6.2-04 / 6.4-04（"界面侧改不动，得主进程配合"）。

| ID     | 验收标准                                                                                                                 | 方式   | 验证操作                                                                                    | 状态 |
| ------ | ------------------------------------------------------------------------------------------------------------------------ | ------ | ------------------------------------------------------------------------------------------- | ---- |
| 8.8-01 | 摆位权威换边：渲染层量出槽位矩形经 `shell.setKernelViewBounds` 报来，主进程只在**没收到上报**时按 38% 兜底               | U+V    | `slot-bounds.test.ts` 7 条 + 六态活体对照（`8.8-01-geometry-readings.txt` A 段）            | [x]  |
| 8.8-02 | 视图不再盖住标题栏与状态条：槽位上沿 = header 下沿、下沿 = footer 上沿，两侧读数都对得上                                 | V      | 同文件 A 段矩形算术（header 51 / 槽位 88→742 / statusbar 742）+ `8.8-02-04-desk-chrome.png` | [x]  |
| 8.8-03 | 自适应：拖窗口、换宽度档、展开/收起三条来源都会重报，视图跟随（`ResizeObserver` 一条通道，不开轮询）                     | V      | 同文件 B 段：1200/1512 两种窗口下 bounds 与槽位逐位一致                                     | [x]  |
| 8.8-04 | 三档宽度 + 展开占满工作区，且**控件摆在视图盖不到的那一行**；到界禁用带 `data-disabled-reason`，展开态以可见性为前置条件 | V      | 同文件 A 段 `gated:WIDTH_MAX` 一行 + 工具行矩形 51→88 在上报矩形之外                        | [x]  |

| 8.8-06 | 非法几何不铺：非有限 / 非正 / 与客户区无交集 → `KERNEL_VIEW_BOUNDS_INVALID` 并保留上一份摆位；零尺寸上报在渲染层即跳过   | U      | `slot-bounds.test.ts` 负腿 + 同文件 C 段（右栏收起时主进程停在上一份，未被 0×0 覆盖）       | [x]  |
| 8.8-07 | `--kernel-view-width` 与 `KERNEL_VIEW_WIDTH_RATIO` 仍同源（最窄档 = 兜底比例），1.2-12 那条机检未松                      | C      | `pnpm lint`（`check-renderer-conventions.ts`）绿                                            | [x]  |

**8.8-05 的边界要如实记下**：BOSS 首页是 1224px 起铺的定宽桌面布局，而展开档在 1200 宽的窗口里只有 1015px，
仍差 209px——**换边只解决"谁说了算"，不解决"窗口本来就不够宽"**。要完全不横向裁切需要展开档 + 窗口 ≥1410 宽
（185 左轨 + 1224 站点最小布局）。真要把这一格彻底拿掉，得给视图一只可独立最大化的窗口，
那是另一片（记在 plan 08 §7 的后续缺件里，不在 8.8 射程内）。

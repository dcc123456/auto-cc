> **本计划总基调**：验收的不是"能不能跑"，而是"界面有没有说谎"——
> 颜色有没有把风险说成安全，按钮有没有把没做的事做成像做了的样子，
> 弹窗有没有在本可以就地解决的地方多占一层。

## 6.1 / 6.2 / 6.3 落地记录（2026-10-06，令牌层 + 原件层 + 外壳归位）

**本片实际只干三件事：把颜色收成一套可翻面的令牌、把控件行为收进一个原件目录、把 16 只面板按用户语言归位。**

1. **令牌层**（`packages/renderer/src/globals.css`）：`@theme` 落墨案 ink 阶 + 纸面 + 三色效果归属 + 圆角/阴影/字族/动画；
   `[data-theme='light']` 落毡案（只有变量赋值）。存量 `slate-*` 的**值**换成墨案等亮度档，class 名一个都没改。
   实测前提：构建产物里 utility 是 `var(--color-…)` 间接引用（6.1-08），所以运行时翻 `data-theme` 就整屏换装。
2. **原件层**（`packages/renderer/src/ui/controls.tsx` + `ui/overlays.tsx`）：五态按钮 `DeskButton`
   （`action` 必填 → `data-action`，`disabledReason` → `data-disabled-reason`，`markers` 补 harness 断言点）、
   `useDeskResult`（jade 2 秒回落 / seal 不回落）、`EffectChip`（三档副作用）、`Banner`、`InlineEditField`、`ArmButton`、
   `Drawer` / `Modal` / `Toast`。
   **本片只有 `DeskButton` 有了消费者**（标题栏三只：主题 / 语言 / 隐私入口，活体已断言）；
   其余原件按 plan §4 的顺序在 6.4 接入——现在它们是"设计系统的下一层"，不是死代码，但 **6.4 不落地就该删**（§2.4）。
3. **外壳**（`App.tsx` + `theme.ts` + 两份语言包）：左轨六档（对话 / 岗位 / 简历 / 流程 / 信任 / 诊断，诊断低一档）、
   底部状态条、主题开关。`data-view="chat"` 与 `data-view="workflow"` 两个值原样保留（`scripts/smoke-dist.ts` 依赖它们），
   新增 `data-action="nav-<view>"`。面板一个都没动逻辑，只换挂载位置。
4. **门禁实跑**：`pnpm --filter @auto-cc/renderer typecheck` → `TC=0`；`pnpm exec eslint packages/renderer eslint.config.js` → `ESLINT=0`；
   `pnpm lint`（12 项机检链）→ `LINT=0`；`pnpm format:check` 全绿；`pnpm test` 全绿（逐包通过数在 `tmp/p6/test2.log`，
   退出码按 §9 的 5.4-c 用重定向读，不管道接 `tail`）。
   顺带两处必要的基线修正：`eslint.config.js` 的 ignores 补 `docs/design/**`（设计稿是独立 HTML/JS，不属于任何 tsconfig 工程，
   与既有 `docs/acceptance/**` 同一条理由）；修掉 `docs/design/ui-drafts/04-workflow.html` 一个标签笔误（`</i></b>`），
   否则 `prettier --check .` 过不去。
5. **`[!]` 的真实原因**（禁止用推测填 `[x]`）：
   - 6.1-05：切换与落盘已活体取到（`stored:"light"`），**重启半边没验**——本机跑着用户自己的 `pnpm dev` 实例
     （5173 端口占用即证据），按 AGENTS.md §9 不允许为了验收杀掉用户正在用的 app。
   - 6.1-06：浅色次级文案在收口时按读数把 `slate-400/500/600` 从"等比翻转"加深到 `#56626c/#6b7681/#7d8892`，
     但**逐屏对比度还没量完**。
   - 6.2-01 / 6.2-02：悬停与按下态要真实鼠标事件（窗口遮挡时 CDP 输入不落页，§9 的 2.1-12 补窗）；
     渲染层没有 `test` script，U 半边缺通道——补它等于新起一套测试基建，超出本片边界，留给 6.4 一起提。
   - 6.2-04：形态③「右栏替换」缺件。右栏当前是主进程摆位的内核视图槽位（`--kernel-view-width` 与
     `KERNEL_VIEW_WIDTH_RATIO` 同源），界面侧替换它需要主进程配合，不是纯样式改动。
   - 6.3-05：状态条四项读数只落了"有没有在跑、跑到哪一步"（来自既有 `useWorkflowRun` 订阅，没新开通道）。
     登录态 / 额度 / 档位三项**没有伪造**——它们各自的面板才是真相来源，状态条宁缺不谎。

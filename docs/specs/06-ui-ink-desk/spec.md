## 6.4 第一片落地记录（2026-10-06，会话改名换成「就地编辑」原件）

选会话条（`ChatSessionBar.tsx`）作为落点，因为它六种后果里已经占了三种（就地编辑、禁用带原因、行内回执提示），

1. **删掉了一份平行实现**（§2.5）：会话条原先自己写了输入框 + 保存/取消两只裸 `<button>` + 一套本地

   `delete-session` / `new-session` / `restore-session` / `chat-session-title-input`）。
2. **`InlineEditField` 改成受控**：原件原先自己存一份草稿，`onSave` 把草稿回传给调用方——
   而会话条的「保存名字」按钮读的是它自己那份 `titleDraft`，两份草稿会分家（敲了字却存下旧值）。
   现在值只存在调用方一处（§2.7 禁第二份事实），原件只负责 Enter/Esc 两个键与自动聚焦。
3. **禁用态从"按不动"变成"说得出为什么按不动"**（6.2-06）：`DeskButton` 新增 `disabledReasonLabel`，

2. **为什么是"整档不拼"而不是"只去掉描边"**：原先的写法是禁用分支（`border-line bg-ink-850
text-slate-500`）后面无条件再拼语义档，而 Tailwind 生成的样式表里同类工具的先后**不由
   class 字符串的顺序决定**。活体上因此出现三种走向：`bg` 一路是禁用分支赢（第六~九片的
   bg 读数早就收敛在 `rgb(15,22,28)`），`color` 一路也是禁用分支赢，`border` 一路三档输
   （`line-strong` / `slate-600` / `transparent` 各自盖过 `border-line`）。按症状只修 border 的话，
   下一次 Tailwind 换排序又会回来，所以让禁用态**根本不读 variant**。
3. **顺带修掉的第二条症状**：27 只禁用键在修复前**全部带着 `hover:` 类**。这不是另一条缺陷，

   鼠标事件，原因码的 tooltip 就出不来），于是 `:hover` 对禁用键照样生效，表现为"按不动却会提亮"，
   与 `buttonClass` 自己的注释"禁用时不提亮"相反。整档不拼之后 hover 随 tone 一起消失，
   普查里 `hoverClass` 27→0。
4. **ghost 档的外观是有意的变化**：禁用时它从前画 `border-transparent` + `bg-transparent`

   判据是"同一件事只有一种画法"，不是"保留 ghost 的空框"。
5. **重取方式改了**：不再逐屏重拍，而是**一次全量死键普查**——六张视图在工作台里是同时挂载的

   编排屏 7 只可见死键）× 双主题 = 四张，四张 `md5` 两两不同（§9 的 5.10-18）。

## 6.5 第十八片落地记录（2026-10-06，算子从调色板拖进画布：三态虚线与“松手才建”）

1. **先取证再动代码（§6.1/§6.2）**：候选 A 是 HTML5 原生拖放（`draggable` + `dragstart`/`drop`）。
   读安装产物 `@xyflow/system@0.0.83` 的 dist 数了一遍监听器——`mousedown` 5 处、`mousemove` 3 处、
   `dragstart` **0 处**，react-flow 自己就不听原生拖放；而 `Input.dispatchMouseEvent` 派不出原生
   drag 事件（要走 `Input.setInterceptDrags` + `Input.dispatchDragEvent` 那一整套），V 类判据就只能靠
   合成 `DragEvent` 造假，§7.1 不允许。加上“同一张画布上长出第二套拖拽族”违反 §2.5，
   于是走候选 B：**鼠标事件 + 4px 阈值**，点击建格（5.10-03）一行没改。取证结论写在 plan §3.7。
2. **`screenToFlowPosition` 按 typings 用，不按博客用**：签名是
   `(clientPosition: XYPosition, options?: { snapToGrid?: boolean }) => XYPosition`。
   它有一条**兜底陷阱**：store 里没有 `domNode` 时原样返回传入的 client 坐标
   （`dist/esm/index.mjs:559-563`），于是隐藏 / 零尺寸视图上拿到的“flow 坐标”其实是屏幕坐标——
   本片只在 `isOverCanvas` 为真（holder 命中测试过了）时才调用它。
3. **落点框是一只 react-flow 节点，不是跟着光标跑的绝对定位 div**（§5.1 的读法）：
   渲染层此前没有一处 `style={{`，“跟随光标”若用内联 style 定位就破了这条。
   改成 `type: 'dropFrame'` 的预览节点（`draggable: false` / `selectable: false`），
   位置交给库自己算，样式全走 Tailwind 类（`border-2 border-dashed border-celadon/70` +
   `-translate-x-1/2 -translate-y-1/2`）。原槽位那一半（10 稿⑤ 的“40% 残影”）留在调色板：
   `opacity-40 outline-2 outline-dashed outline-offset-2 outline-seal`，并挂 `data-dragging="true"` 作判据。
4. **三条取消路径共用一个状态机**：松手在画布外 → 不建；Esc → 不建；未越 4px 阈值 →
   连拖都不算（`click` 照常派发，故 08 稿的“点一格 = 加一格”零改动地活了下来）。
   监听挂在 `window` 的 `mousemove`/`mouseup`/`keydown` 上，`useEffect` 不带依赖数组、

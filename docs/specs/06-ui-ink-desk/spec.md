## 6.1 / 6.2 / 6.3 落地记录（2026-10-06，令牌层 + 原件层 + 外壳归位）

**本片实际只干三件事：把颜色收成一套可翻面的令牌、把控件行为收进一个原件目录、把 16 只面板按用户语言归位。**

## 6.4 第一片落地记录（2026-10-06，会话改名换成「就地编辑」原件）

**这一片只推进一条：让 `InlineEditField` / `DeskButton` 有第二个真实消费者，并把 09 稿形态② 落到活体上。**
选会话条（`ChatSessionBar.tsx`）作为落点，因为它六种后果里已经占了三种（就地编辑、禁用带原因、行内回执提示），
换装它一次能兑现多条验收，且不动任何业务逻辑与 bridge 调用口径。

1. **删掉了一份平行实现**（§2.5）：会话条原先自己写了输入框 + 保存/取消两只裸 `<button>` + 一套本地
   `onTitleKeyDown` 键盘处理。现在键盘语义只在 `InlineEditField` 一处，六只按钮全部走 `DeskButton`，
   `data-action` 与 `data-testid` 一个都没改名（`save-title` / `cancel-rename` / `rename-session` /
   `delete-session` / `new-session` / `restore-session` / `chat-session-title-input`）。
2. **`InlineEditField` 改成受控**：原件原先自己存一份草稿，`onSave` 把草稿回传给调用方——
   而会话条的「保存名字」按钮读的是它自己那份 `titleDraft`，两份草稿会分家（敲了字却存下旧值）。
   现在值只存在调用方一处（§2.7 禁第二份事实），原件只负责 Enter/Esc 两个键与自动聚焦。
3. **禁用态从"按不动"变成"说得出为什么按不动"**（6.2-06）：`DeskButton` 新增 `disabledReasonLabel`，
   并**不再使用原生 `disabled`**——Chromium 对禁用控件不派发鼠标事件，`title` 提示因此永远不出现，
   人只能看到一颗灰掉的按钮。改走 `aria-disabled` + 原件内部挡下 `onClick`：既能悬停出提示、也能被 Tab 到，
   点击仍然完全 inert。原因码走 `data-disabled-reason`（机器读），人话走两份语言包新增的
   `chat.session.reasonNoSession` / `reasonEmptyTitle`（§5.5/§5.6/§5.7：值用插值、专名不进主句）。
4. **活体读数**（用户自己的 dev 实例在 5173 上跑着，HMR 已吃到改动；按 §9 不杀用户的 app，也不点真提交）：
   - 点「改名」→ 标题原地变输入框、`data-editing="true"`、`document.activeElement` 就是它，**没有出现任何遮罩层**（形态② 兑现）；
   - 空草稿时 `save-title`：`aria-disabled="true"` + `data-disabled-reason="INPUT_EMPTY"` + `title` 是中文那句，
     对它 `click()` 后仍是编辑态、没有新增提示行（点击确实被挡）；敲入文字后 `aria-disabled` 消失（可点）；
   - 派发 `keydown Escape` → 输入框收起、`[data-session-title]` 仍是空串、无提示行 = **草稿被丢弃且没有写库**；
   - 证据：`docs/acceptance/06-ui-ink-desk/6.4-03-inline-edit-dark.png`（同批 6 张 md5 全不相同，无重复）。
5. **门禁实跑**：`pnpm exec prettier --write packages/renderer/src` → `FMT=0`；
   `pnpm --filter @auto-cc/renderer typecheck` → `TC=0`；`pnpm exec eslint packages/renderer` → `ESLINT=0`；
   `pnpm lint`（12 项机检链）→ `LINT=0`；`pnpm format:check` → `FMTCHK=0`；`pnpm test` → `TEST=0`
   （逐包通过数在 `tmp/p6/test2.log`，退出码按 §9 的 5.4-c 用重定向读，不用管道）。
6. **本片留下的 `[!]`，都是真没做完而不是"环境不给"**：
   - 6.2-06：机制与一个真实消费者已过，但**其余面板的禁用按钮还没逐个补码**——补一个就得读一遍那个面板的禁用条件；
   - 6.2-07：Enter 那半边只验到"与保存按钮同一个回调"，**没有真提交**（会改写用户当前会话的标题，无人验收时不动它）；
     真实键盘（非程序化 keydown）序列要用户在场的活体一轮；
   - 6.4-03：会话改名这半边已取证；**简历正文就地编辑 + 「事实待校验」标记**属于简历屏，随 6.4-02 一起做。

## 6.4 第二片落地记录（2026-10-06，把默认色阶收进四族 + 归属标签接上活体消费者）

**这一片干的是"取消一整个缺陷类别"，而不是"改几个颜色"**：`slate` 收编之后源码里还剩 450 处 Tailwind 默认色阶
（rose 125 / emerald 115 / amber 101 / sky 91 / indigo 11 / violet 6 / red 1，34 个文件）。
它们各自表达"红=失败、绿=成功、蓝=进行中"，与设计口径的三色效果归属**撞语义**——
最典型的是工具卡片把「进行中」画成琥珀色，而琥珀在这套系统里只说"这台机器在等你"。

1. **策略与 6.1-03 同一条（plan §3.2 补记）**：只改 `@theme` 里六条色阶的**值**，class 名一个不动，
   于是 34 个面板一次换装；浅色主题里整条色阶**反向**（低号当文字要深、高号当底色要浅），与 `slate` 同一处理。
   唯一一处 `text-red-300` 在调用点直接改成 `text-seal`（`ShellPanel` 的"上一次错误"），
   顺带修掉一处说谎：那一行**没有错误时也涂着失败色**，现在只有真有错误才染朱砂。
2. **`EffectTone` 改回注册表的枚举本身**（`ToolEffect` = `read / local-write / outbound`）：
   原件原先写的是驼峰 `localWrite`，等于给同一个概念起第二个名字（§3.6 术语一致 / §2.7 第二份事实）。
   现在类型从 `@auto-cc/shared` 引进来，界面这一侧不可能再和注册表漂移。
3. **`EffectChip` 拿到活体消费者**（原先零个）：工具卡片底部那一格、信任面板「可加白的工具」候选栏 10 行、
   以及已加白那一栏（未登记的工具**不涂色**——它连副作用是哪一档都不知道）。
4. **读数（`docs/acceptance/06-ui-ink-desk/6.4-01-ramp-readings.txt`）**：深色 `rose-300=#ef9a86`、
   `emerald-950=#0c2119`、`sky-800=#2d4a46`；浅色整条反向（`rose-300=#9f3323`、`rose-950=#fdf1ee`）；
   计算色核对 `.text-rose-300 → rgb(239,154,134)` 证明 utility 走变量间接引用；
   候选栏 chip 实测 `local-write → rgba(224,163,63,.13)`、`outbound → rgba(226,84,58,.13)`。
   取完两档已把主题切回 dark（`localStorage["auto-cc.theme"]="dark"`），没把用户的实例留在浅色态。
5. **截图这一路本片取不到，如实标 `[!]`**：`document.visibilityState === "hidden"`（窗口被遮挡/最小化）时
   Chromium 不再产出帧，`harness shot` 挂住不返回——与 §9 的 2.1-12 补窗是同一条硬约束（那里说的是输入不落页，
   这里是帧不产出）。按 §7 的规矩，缺的是 V 半边，**不用计算色读数冒充截图**。
   留给用户在场的活体一轮：对话屏（工具卡片 + 候选栏）、岗位屏、诊断屏（`MetricsPanel` / `UsagePanel` 换色后的读数）。
6. **门禁实跑**：`pnpm --filter @auto-cc/renderer typecheck` → `TC=0`；`pnpm exec eslint packages/renderer` → `ESLINT=0`；
   全量 `pnpm lint` / `pnpm format:check` / `pnpm test` 见收尾记录（退出码用重定向读，§9 的 5.4-c）。

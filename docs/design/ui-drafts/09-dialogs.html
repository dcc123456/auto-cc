RULE六种形态，不许有第七种全 app 通用
一个控件点下去，画面上的反应只能是下面六类之一（外加"不响应 + 原因码"）。这条是给实现收口的：新增任何交互，必须先归到某一类里，归不进去就说明交互设计没想清楚。 排序原则是"打扰度递增"：能在原地解决的不许开新面，能不开浮层的不许开浮层。

形态 ③右栏替换要看细节但不肯离开列表时
右栏是一栏多用的可替换面板（裁定一）：默认显示内核浏览器视图，点「详情 / 预览 / 证据」时在同一格里换成对应内容，不换视图、不滚走左边的列表。 这一类承担 app 里绝大多数的"看更多"——因为它让列表位置和滚动深度保持不变，用户回得去刚才那一条。 面板顶部永远留一只「返回内核视图」，收起后宽度回到原状。

    浮层纪律（实现时必须照抄）

    条目 规则
    同屏数量上限 遮罩弹窗 ≤1 只；抽屉 ≤1 只；两者互斥（开弹窗前先关抽屉，状态存住）。toast 同时只 1 只。违反即视为 bug。
    焦点 弹窗/抽屉打开后焦点落在默认安全动作（通常是「取消」），Tab 在浮层内循环不出来；关闭后焦点还给触发它的那只控件。
    滚动锁 遮罩弹窗锁底层滚动；抽屉不锁左栏与列表（允许边看边改）。
    Esc 层级 toast → 关掉；右栏面板 → 返回内核视图；抽屉 → 关闭（有未保存改动先行内确认）；弹窗 → 仅"可安全取消"的 4 只关，5-1 首次签字不关。
    尺寸 抽屉 420px（批量编辑 520px）；弹窗 480 / 560 / 640 三档，不许自定义。窄窗（<1120px）时抽屉改为全宽覆盖、右栏替换降级为抽屉。
    动效 抽屉 220ms 位移 + 遮罩淡入；弹窗 160ms 缩放 0.98→1 + 淡入；toast 180ms 上滑。都只动一次，不做弹跳、不做视差。
    浅色主题 遮罩在浅色下改为 rgba(38,44,48,.5)（墨色下是 .72），因为毡案底色亮、深遮罩会把内容压成"另一个 app"。
    埋点/证据 每只弹窗的确认动作都写一条运行记录（含当时展示的额度读数），事后能在证据链里回放"用户看到了什么才点的"。

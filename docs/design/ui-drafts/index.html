墨案 / Ink Desk

石墨色的桌面上摊着几张纸，纸角盖着朱砂印。这套界面只表达一件事：哪些动作只在这台机器里发生，哪些动作会替你走出去。朱砂色在全 app 只用于后者——凡是会离开本机的，都必须像盖章一样有重量、有留痕、有可撤回的签字。浅色主题另起一张桌面叫毡案 / Felt Desk：桌面从墨换成浅灰毡，纸面换成更白的纸，靠阴影而不是明度差分层——右下角的浮标整板切换，十张稿与本页同时换装。

墨 · 桌面
石墨灰蓝的 chrome 承担结构与读数，永远不与内容抢注意力（浅色主题里这张桌面换成浅灰毡，角色不变）。工程类读数压到底栏一行，诊断面板因此可以折叠。
纸 · 文档
JD、简历、PDF 一律画成桌上的暖纸，与 chrome 形成材质对比。纸面的"原文一字未改"就是事实锁定红线的视觉对应物。
印 · 外发
朱砂只属于外发：盖印执行、风险签字、状态骑缝章、风控接管。普通按钮没有这个颜色，用户不可能把"确认"看成"保存"。

二 · 信息架构：现有 40 个组件去哪了
核心问题不是"不好看"，而是三个视图里 1.1 号视图后面堆了 13 块面板，用户必须自己从面板名反推产品流程。这一版把它们折成 4 个工作区 + 2 个系统区，对话仍是第一入口（不违反 P1.11 与 §5.9）。

三 · 交互层：每只按钮点下去发生什么
这一节是 v1.2 新增的主体（07 / 08 / 09 三张稿的索引）。先回答你举的那个例子：点「修改」是直接编辑，不是弹窗。短字段就地变输入框（Enter 保存 / Esc 还原），正文直接进可编辑态；弹窗全 app 只留 5 只，判据是"做了撤不回"或"不读完整风险就无法负责"。
结果形态（打扰度递增） 什么时候用它 画面代价与硬约束
① 就地回执 低风险、可逆、结果一句话说得清 控件自己走完 转针 → 对勾 → 2 秒回落；不新增浮层。失败态（朱砂）不自动回落，必须人读过。toast 同时只允许 1 只、不抢焦点。
② 行内编辑 改一个字段 / 改一段正文 青瓷描边 + 外发光标记编辑态，不换底色（换底色就看不出改的是原文哪一句）。失焦不自动保存。改完整屏不跳。
③ 右栏替换 要看细节又不肯离开列表 右栏一栏多用（裁定一）：把内核视图藏在后面，不卸载（1.10-01）；列表滚动位置不动。
④ 抽屉 要横向对照 / 要一次改一批 420px（批量编辑 520px），遮罩只盖主区、不盖左栏；有未保存改动时关闭先行内确认，不直接丢。
⑤ 遮罩弹窗 不可逆，或必须先读完整风险 盖整窗含左栏、焦点锁死。全 app 只 5 只：首次风险签字 / 批量外发确认 / 批量拒绝改动 / 导入冲突 / 清空本机数据。只有 5-1 与 5-5 需要打字或勾满。
⑤′ 两步就地 不可逆但影响面只有一条 同一只按钮按两次：第一次进 armed 态（朱砂底 + 文案换动词 + 4 秒倒计时、整行其他控件暂时失效），第二次才真做。比弹窗的一次性「确认」更安全。
⑥ 视图推进 跨工作区跳转 / 进入编排 必须带面包屑且「返回」回到原位；按下瞬间不给 loading（目标是本地已渲染视图，出现转针说明实现走错路）。
⊘ 不响应 前置条件没满足 禁用态旁边必须挂原因码（NO_CONSENT ENTITLEMENT_EXHAUSTED SCRIPT_DIRTY RUNNING_READONLY …），且给一条解除路径。只灰不给码视为缺陷。
覆盖度与一致性
08 稿逐只列了 118 只控件（对话 26 / 岗位 19 / 简历 26 / 流程 22 / 信任 15 / 状态 10），每只写四项：按下瞬间的样式差值、结果形态、完成后与回落与禁用原因、键盘等价。07 稿给出五态总则与 8 类控件的差值表——悬停只提亮一档、不位移；按下才 translateY(1px)，这条在全 app 一致，避免"按钮跳一下"的廉价感。实现层的收口条件是：归不进这六类的交互，说明交互本身没想清楚。

五 · 实现时必须守住的不变式（对着 AGENTS.md 逐条过）
这页是给"评审通过之后谁来写代码"看的：设计稿里每一个元素都有对应的约束，评审时请一并确认这张表没有被破的地方。
  • 对话仍是第一入口，工作流是第二视图，工程台是第三档（§5.9、P1.11）。四区之间不许长出"绕过主流程的捷径"。
  • 样式全部映射到 Tailwind 主题扩展：本稿的 CSS 变量与 shared.css 只是设计令牌的定义方式，落地时写进 tailwind 配置与 utility 组合，不留 .module.css（§5.1）。
  • 图标全部是 lucide-react 现有件：MessageSquare / Briefcase / FileText / Workflow / ShieldCheck / Wrench / Stamp / Hand / Clock / AlertTriangle / Scale / Landmark；稿内 SVG 就是这些图标的 path，不新增自绘（§5.3）。
  • 每一条可见文案走 i18n，键名沿用 shell.* 现有层级并补齐 en；本稿文案可直接作为 zh-CN 语言包初稿（§5.5 / 5.6）。
  • 三色效果芯片 = 工具契约的 effect 字段（read / local-write / outbound），由 check-tool-contract.ts 供数，前端不得自己判色。
  • 档位指示常驻，且不可程序自升；全自动档必须与白名单状态同屏出现（5.3 的"不可自提升"）。
  • 画布进度只由事件推，节点不许自轮询 runner.state()（5.10-11 已机检）。
  • 渲染层不碰 Node：右栏内核视图、截图、账本一律经 window.autoCC 白名单（§5.8 / §8.1-8.2）。
  • 白名单与签字落 SQLite，不做配置键（配置层重启即失，§9 的 5.3-b 实测）。
  • 个人信息在 UI 上就是脱敏态（手机号、姓名、cookie），不是导出前才处理（§8.5）。
  • 工程台零外发按钮；检测到验证码/风控只暂停不识别，界面上不留任何"帮我通过"的入口（§8.3）。
  • 空态、stale、拒绝、失败四类文案必须给出路，且带原因码——与 §7.4 的自检清单同源，评审时按 06 稿逐面打勾。
  • 交互结果只有六形态（就地回执 / 行内编辑 / 右栏替换 / 抽屉 / 遮罩弹窗 / 视图推进，外加"不响应 + 原因码"），遮罩弹窗全 app 限 5 只；新增第七种浮层或给短字段开编辑弹窗，都算破坏本稿（07 / 08 / 09）。
  • 每一只可点控件带 data-action 且有键盘等价（§9 harness 的活体断言依赖它）；禁用态必须同时给出原因码属性，便于断言"灰得有理由"。

Q1
右栏到底是不是"常驻一栏"？
稿里右栏在对话/岗位屏是内核页面，在简历屏是 PDF 预览，在流程屏是节点详情。备选：内核视图严格常驻不可替换，简历与节点详情改为主区内的抽屉。前者一栏多用、心智要教一次；后者更贴近现有 KERNEL_VIEW_WIDTH_RATIO 的摆位实现。
已裁定（2026-10-06）：一栏多用、可替换。落地时右栏是一个容器组件，内容按当前工作区切换，内核实页仍走现有 KERNEL_VIEW_WIDTH_RATIO 的摆位；首屏用一行提示教会"这一栏随分区换脸"。

四区命名是否用「岗位 / 简历 / 流程」这套用户语言？

Q3
"盖章"这套材质语言要不要一路走到底？
朱砂方章 + 骑缝章 + 手写签字，辨识度极高但带明显中式文书气质。备选：更中性的"审批"图形（对勾 + 印章轮廓），跨语言（en）语境更稳。
已裁定（2026-10-06）：一路走到底。en 语境靠文案解释（章即"批准并外发"），图形不做分支；朱砂色仍然只出现在外发动作上，与 effect.outbound 一一对应。

Q5
深浅双主题要不要一起做？
本稿只有墨色深主题。纸面元素在浅主题里会失去对比优势，需要为浅色另设一套"桌面材质"（例如灰毡），属于额外一份设计。
已裁定（2026-10-06）：一并出浅色稿。落地为「毡案」：[data-theme='light'] 一整段 token 覆盖（毡底 / 更白的纸 / 收紧的阴影 / 语义色加深一档），十张稿与总览板都能整板切换；布局与组件零分支。

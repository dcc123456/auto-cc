  1. "流程"这一个区收五块面板：WorkflowPanel / WorkflowLabPanel / WorkflowPlans / SchedulePanel / MetricsPanel / AuditSection。左栏是"什么时候跑什么"，中间是"怎么跑"，右栏是"跑得怎么样"。
  2. 运行中画布只读沿用既有约束，并把它写成一颗看得见的芯片而不是只在 tooltip 里。
  3. 计划库自带节点数 / 跑过几次 / 外发步数，选择计划时就完成风险预判；内置计划显式标"只读"。
  4. 定时任务与计划库并列同栏：cron 是"这条计划什么时候跑"，不该是独立面板。停用 / 删除走二次确认，按钮文案直说。
  5. 节点可观测四要素（状态、耗时、失败原因、可重试）在画布上就可见一部分，点选后右栏给全。
  6. 失败码直接印在节点上，人不需要点进去才知道哪一步断了。
  7. 镜头控制 + "进度只由事件推"：5.10-11 的机检条目对应的界面承诺——不许节点自己轮询 runner.state()。
  8. 运行控制条固定在画布下方：开始 / 暂停 / 续跑 / 重试 / 中止 + 六态读数，永远在同一位置。
  9. 节点详情 + 失败证据同栏，审计回看因此可以从"独立面板"降级为"任意节点的历史"。
  10. 失败原因写成人类语言：先说结论（编造了"主导"），再说证据支持什么，最后给两个可执行动作。
  11. 漏斗只读、贴在运行旁边：跑完一轮就地看转化，不需要切去诊断。
  12. 漏斗给结论句：指出唯一标红的环节，并把"该改什么"说出来——指标面板最容易变成一堆没人看的数字。

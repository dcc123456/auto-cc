## 一句话概念

石墨色桌面上摊着几张纸，纸角盖着朱砂印。**朱砂在全 app 只用于"会离开这台机器"的动作**——盖印执行、风险签字、已外发的骑缝章、风控接管。普通按钮没有这个颜色，因此用户不可能把"确认外发"看成"保存草稿"。

## 主要改动主张

1. **三个视图 + 13 块平铺诊断面板 → 4 个工作区 + 2 个系统区**（对话 / 岗位 / 简历 / 流程 ＋ 信任与安全 / 工程台）。对话仍是第一入口，工程台仍比主视图低一档。
2. **六步闭环第一次成为界面脊柱**（02 稿顶部的进度条），用户的每个动作都能对上"现在卡在第几步"。
3. **三色效果芯片贯穿全 app**：只读 / 本地写入 / 外发，取自工具契约的 effect 字段，前端不自判。
4. **额度闸门、档位、证据被搬到动作发生的地方**，不再需要跳去诊断面板对照。
5. **工程台零外发按钮**——建议作为新的验收条目。
6. **交互层收口为六种结果形态**（07 / 08 / 09）：就地回执 < 行内编辑 < 右栏替换 < 抽屉 < 遮罩弹窗 < 视图推进，外加"不响应 + 原因码"。归不进这六类的交互视为没想清楚。
7. **编排与运行是同一视图的两个相位**（10），不是第三个页面。

## 你举的那个例子，答案在这

**点「修改」是直接编辑，不是弹窗。** 短字段就地变输入框（`Enter` 保存 / `Esc` 还原，青瓷描边标记编辑态、不换底色），正文直接进可编辑态并挂"事实待校验"角标；弹窗全 app 只留 5 只（首次风险签字 / 批量外发确认 / 批量拒绝改动 / 导入冲突 / 清空本机数据），判据是"做了撤不回"或"不读完整风险就无法负责"。单条可撤的不可逆动作走**两步就地**（同一只按钮按两次，第一次进 armed 态 + 4 秒倒计时），不开弹窗。详见 `09-dialogs.html` 形态②与形态⑤′。

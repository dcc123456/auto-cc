# 视觉规范：筛选区紧凑化 + 岗位删除入口

- 日期：2026-11-24
- 提出：设计师
- 依据：用户 2026-11-24 两条要求（"搜索条件不应该一个字段占用一行""岗位列表需要可删除"）、PMO 口径（城市+关键词同一行 / 其余 2–3 列 / 窄窗 1 列 / 不超一屏 / 不留横向溢出）、QA 改造前基线 `docs/acceptance/10-job-journey/10.12-qa-delete-and-compact-baseline.txt`（12 行、684px、岗位 0 删除入口）
- 落地边界：只用 Tailwind + lucide + i18n + 既有 Desk 控件；不引 UI 库、不新增顶级菜单、不新开浮层体系

## 0. 一句话，外加一个根因

**筛选区的病根不是 gap，是两件事：① 关键词、城市、其余维度分处在三只不同的容器里；② 筛选卡那张 `section` 少了 `@container`，所以 `@2xl:grid-cols-2` 从来没有生效过（筛选卡那张 `section`，即 `jd.criteriaHeading` 所在；对比列表卡那张 `jd-cards` 所在——它才是 `@container`）。症状才是"12 行、684px"。**

所以这一版只做三件事：把 14 个字段收进**同一个网格**、给那张卡补 `@container`、把执行参数（本轮条数/平台）从条件区挪到动作行与其右侧。删掉"每行一个"的同时，行距、标签基线、动作行左沿一次对齐。

## 1. 筛选区：结构

**现状（基线实测 12 行 / 684px）**

```
搜索条件
[ 关键词 ─────────────────────────────── ]   ← 独占一行（grid 之外）
[ 城市 ───────── ][ 经验 ][ 条数 ]           ← 第二只 flex 容器
[ 区县 ]                                      ← 维度网格（容器查询没生效 → 1 列）
[ 经验 ]
[ 学历 ]  … 共 8 行
[ 抓取 ][ 列表 ]
```

**改后（同一只网格，3 列档；行数 5）**

```
搜索条件                                            平台 [ BOSS 直聘 ▾ ]  ← 仅多平台时出现
┌ 关键词 ────────────────────────┐┌ 城市 ▾ ───────┐
├ 区县 ▾ ──────┤├ 学历 ▾ ──────┤├ 薪资 ▾ ──────┤
├ 经验 ▾ ──────┤├ 规模 ▾ ──────┤├ 融资 ▾ ──────┤
├ 求职类型 ▾ ──┤├ 公司行业 ▾ ──┤└───────────────┘
─────────────────────────────────────────────────
[ 抓取 ] [ 列表 ]                        本轮 [ 20 ] 条
```

- 关键词占 **2/3**、城市 **1/3**（`@2xl:col-span-2`），两者同一行同一基线；其余 8 维各占 1/3。
- 14 个字段里 `平台` 与 `本轮条数` 不是筛选条件：平台进标题行右侧（只有多平台时才出现），条数进动作行右端。**筛选网格里只留真正的筛选条件**——这是这一版"看起来干净"的一半原因。
- 长列表选择器（城市/行业/职位类型）展开时**仍只占 2 列**（`@2xl:col-span-2`），其余维度照常可见；同一时刻只允许展开一只（既有 `openPicker` 单值状态已保证）。
- **1 列档（内容宽 < 320px）例外**：展开时只渲染那一只选择器，其余维度暂时收起，返回后恢复——否则 8 行加一块 340px 的列表会把整块推成 700px，比现状还难看。

## 2. 栅格、断点、间距（全部是既有令牌/既有断点）

| 容器内容宽（筛选卡的 content box） | 列数     | 依据                                                   |
| ---------------------------------- | -------- | ------------------------------------------------------ |
| ≥ 672px（`@2xl`）                  | **3 列** | 单元格 250+，标签与字段都松快                          |
| 320–671px（`@xs`）                 | **2 列** | 单元格 154+，正好装下"公司行业"（4 字标签）与 `10-20K` |
| < 320px                            | **1 列** | 再窄就该换页面布局了，不是筛选区的事                   |

**断点用容器查询，不用视口查询**：右栏站点展开时主区只剩 ~440，按视口判会得到"窗口很宽、字段挤成一条"。`@xs`(20rem) / `@2xl`(42rem) 是 Tailwind 4.3 已有的容器档（本机 `packages/renderer/node_modules/tailwindcss@4.3.3`，容器尺寸表 `xs:20rem / 2xl:42rem` 已核）。

- **卡片必须补 `@container`**：筛选卡 `section` 加 `@container`（与列表卡、`ModelsPanel` 同一写法）。**没有这一条，下面所有列数都不会发生**——这就是 684px 的机械原因。
- 间距节奏只允许三个值：
  - 横向 `gap-x-3`（12px）——字段之间留得出"两格"的缝（若沿用既有 `gap-2`，横向也必须是 8，同一档内不许混用两种缝）；
  - 纵向 `gap-y-2`（8px）——同一列上下相邻的字段，行距唯一；
  - 分块：标题→网格 `mt-2`，网格→动作行 `mt-3`（12px），卡内 `p-4`（16px）。
- 字段几何沿用既有：标签 `STACK_LABEL`（11px / `slate-400` / 标签与字段 gap-1）+ 字段 `fieldClass('meta')`（26px 高、11px 字）。**所有字段等宽等高**，不许某一格因为内容长而换行——`min-w-0` + `truncate`。
- 动作行：左沿与网格左沿对齐；`抓取`（solid）在前、`列表`（line）紧随、`gap-2`；右端「本轮 [20] 条」用 `ml-auto` 右对齐，与网格右沿对齐。动作行与网格之间**不画分隔线**（卡片里再画一条线就多一层框），靠 12px 留白断开即可。

### 2.1 与工作树上正在写的那一版差多少（复核时按这两条量）

现在那一版把网格写成了 `grid-cols-1 gap-2 @xl:grid-cols-2 @4xl:grid-cols-3`（`jd-search-filters`）。按本规范差两个类名，方向都是"更紧凑"：

| 位置     | 现在          | 本规范        | 后果                                                                                            |
| -------- | ------------- | ------------- | ----------------------------------------------------------------------------------------------- |
| 2 列门槛 | `@xl`（576）  | `@xs`（320）  | 主区被站点分栏时内容宽 ~368，现在会掉成 **1 列 → 块高 ~670**；改成 @xs 是 **2 列 → ~380**       |
| 3 列门槛 | `@4xl`（896） | `@2xl`（672） | 900 视口内容宽 ~772，现在只有 2 列（单元格 390，字段空得发慌）；改成 @2xl 是 3 列（单元格 250） |

两处都是一次类名替换，不动结构；改完 900/1024/1280/1600 四档都是 3 列。

## 3. 高度预算与目标读数

字段格 = 标签 18 + gap 4 + 字段 28 ≈ 50；纵向 gap 8。

| 档                                   | 列数 | 计算                                                               | 目标块高  |
| ------------------------------------ | ---- | ------------------------------------------------------------------ | --------- |
| 900 / 1024 / 1280 / 1600             | 3    | 标题 20 + 8 + 核心 50 + 8 + 维度 3×50+2×8 + 12 + 动作 26 + 卡内 32 | **≈ 320** |
| 主区被站点分栏（卡 ~408，内容 ~368） | 2    | 同上，维度 4 行                                                    | **≈ 380** |
| 真窄窗（内容 < 320）                 | 1    | 核心 2 行 + 维度 8 行                                              | ≈ 670     |

基线 684 → 3 列档 ≈ 320，**减一半以上**，14 个字段全部在一屏内。上面的数是预算（按既有控件几何算的），**判据以 QA 复测读数为准**，不是承诺值。

## 4. 删除入口：卡片右下角那一颗

```
┌──────────────────────────────────┐
│ 后端开发工程师            18-25K  │
│ 某某科技                          │
│ 上海 · 3-5 年 · 本科              │
│ ● 已打招呼  ● 已投递              │
│ 点开看详情                      🗑 │ ← 28×28，ghost，只在这张卡上
└──────────────────────────────────┘
```

| 项     | 规格                                                                                                                            |
| ------ | ------------------------------------------------------------------------------------------------------------------------------- |
| 位置   | 卡片右下角，`absolute bottom-1 right-1`；它是 `DeskTile` 的**兄弟**（`li` 里 `relative`），不是子元素                           |
| 尺寸   | 28×28（`h-7 w-7 justify-center`），图标 `Trash2` 13px，圆角 `rounded-control`                                                   |
| 档位   | `DeskButton variant="ghost" compact` + `tip="删除这个岗位"`；**不内联 hover 色**（档位色只出自 `buttonClass`，§5 那条机检也拦） |
| 常显   | 不做 hover 才出现——新手找不到、键盘也碰不到；ghost 本身没有底色，69 张卡也不会花                                                |
| 点击   | 只开确认卡，**不打开详情**（兄弟节点天然不吃 tile 的 click）                                                                    |
| 焦点   | Tab 顺序：整卡 → 删除键（DOM 顺序就是视觉顺序）；焦点环走 `DeskButton` 既有 `ring-celadon`                                      |
| 无障碍 | `aria-label="删除「{title}」"`（带岗位名，读屏能分清 69 张卡里删哪一张）；WCAG 2.2 目标尺寸下限 24×24，28 过线                  |
| 锚点   | `data-action="jd-card-delete"` + `data-job-id` / `data-platform`（QA 的 D1–D7 靠它）                                            |

**为什么不在右上角**：右上角是薪资（`text-amber` 的 `18-25K`），把危险键压在最贵的信息上不成立。**为什么不嵌进 tile**：`DeskTile` 是 `<button>`，按钮里再放按钮是非法 HTML，焦点与读屏都会错位。**为什么不只放在详情弹窗里**：详情弹窗底部已有三颗动作键（打开页面/生成定制/…），再加一颗危险键就是四颗挨着关闭键，误点风险比卡片角落高一档；而且那份痛点是"列表里清垃圾"，要的是在列表上就删得掉。

## 5. 二次确认：复用简历删除那一只

与 `ResumeDesk` 的删除确认同一只 `Modal`，不新画浮层：

| 项             | 规格                                                                                                                                                                                                                                            |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 容器           | `Modal width="480" tone="seal" dismissOnScrim={false}`；`testId="jd-delete-modal"`，`markers={{ jobId, platform, 'has-records': ... }}`                                                                                                         |
| 标题           | 「删除这个岗位？」                                                                                                                                                                                                                              |
| 正文           | 第一行 **岗位名**（12.5px `slate-100`）+ 公司（11px `slate-400`）；第二行小字「平台 · 城市 · 薪资」                                                                                                                                             |
| 已有记录的提示 | `dots` 里有 greet/reply/deliver/interview，或 `row.replied` 为真 → 一条 `Banner tone="amber" size="compact"`：「这个岗位已有打招呼/投递记录：删除后列表里不再显示，账本、投递记录与追踪统计都会保留。」——**这是用户要求写清的那一句，逐字上屏** |
| 会删 / 会留    | 两行列表（与简历删除同形）：`会删除：库内这条岗位与抓取到的 JD 详情`；`会保留：账本、投递记录、追踪与统计（审计用）`                                                                                                                            |
| 失败           | 卡不关：`Banner tone="seal"` 写 `code + 原因原文`，`testId="jd-delete-error"`；确认键恢复可点。**不把错误扔到页面顶部**——错误属于这一张卡，跟着它                                                                                               |
| 按钮           | 左「取消」`line`；右「删除」`seal`（与简历删除同档）；`busy` 期间两颗都禁用，取消键文案不变                                                                                                                                                     |
| 关闭           | Esc / 取消 / 遮罩**不关**（`dismissOnScrim=false`：危险动作不许点外面就消失）；关掉后焦点回卡片那颗删除键（`Modal` 既有回位）                                                                                                                   |
| 幂等           | 删除口回 `removed === 0`（库里本来就没有）→ 算**成功**：关卡 + 中性 toast「这个岗位已经不在库里了」，不弹错误（判据吃的是返回读数，不是接口名）                                                                                                 |

**不做**：不在卡片上做两步 armed（同一动作两个确认形态）、不做撤销（库内行删了就是删了；审计在账本与追踪里，不在这张表）、不做批量勾选删除（这一片没有多选状态，做了就是新入口）。

## 6. 删除之后的界面反应（判据要能看见）

1. 该卡片从列表消失，**卡片数与 `total/matched/shown` 三只读数同帧更新**（`read()` 重读，不手改本地数组）。
2. 删的是最后一条：`total` 归 0 → 回既有空态（`jd.listIdle`「还没搜过」）；被筛选滤空 → `jd.filterEmpty`。两句话不许混用（10.10-08 已定）。
3. 左下角 toast：`已删除「{title}」`（失败不给 success 形）。
4. Home：切回 Home 时**不得看到旧数字**。走既有可见性重读（`HomePanel` 的可见 watcher / 刷新键），**不加轮询、不加第二套事件通道**；账本派生的数字（外发/额度）**不该变**——变就是删错了东西。
5. 账本、投递记录、追踪三处**行数不变**（这一条是删除的正确性，不是界面；界面只负责不撒谎：toast 不写"记录已清理"这类话）。

## 7. 给 QA 的三处判据校正（C1/C3/C4 按现文会判错）

| 编号 | 现文                         | 问题                                                                                                   | 建议改成                                                                                                                           |
| ---- | ---------------------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| C1   | 城市+关键词同一 y（差 ≤2px） | 在 1 列档（内容 <320）它们必然上下相邻                                                                 | 加范围：**两列及以上**同一 y；1 列档判"相邻且顺序为关键词→城市"                                                                    |
| C3   | 900 / 1024 档每行 1 个       | 与 C2「每行 2–3 个」直接打架；且 1024 改 1 列等于把用户投诉的"一个字段一行"搬到 1024                   | 按容器宽判：**900/1024/1280/1600 = 3 列；主区被站点分栏（卡 ~408）= 2 列；内容 <320 才 1 列**。C2 与 C3 合成一条"列数按容器宽分档" |
| C4   | 块底 y ≤ 视口高（700）       | 筛选块起始 y 是 524（上方还有抓取卡），块高再怎么压，块底也到不了 700 以内——**这条永远红，与实现无关** | 改成**块高 ≤ 视口高**（目标 ≈320），另加一条"滚到筛选块顶部时整块一屏可见"                                                         |

另外建议补一条机检式读数：**`getComputedStyle(筛选卡).containerType === 'inline-size'` 且网格 `gridTemplateColumns` 在三列档解析出 3 个轨道**——没有这条，容器查询没生效会被"行数看起来少了"掩盖（这次 684px 的根因就是它）。

## 8. 复核清单（开发落地后我逐条量，不是看一眼）

1. `@container` 生效：筛选卡 `containerType=inline-size`；900/1024 档 3 个轨道、408 档 2 个轨道。
2. 城市与关键词同一 `y`（差 ≤2px）；14 个字段的行数：3 列档 5 行、2 列档 6 行。
3. 块高 ≈320 / ≈380；四档 `scrollWidth === clientWidth`。
4. 同一档内相邻字段 `y` 差只有一个值；动作行左沿 = 字段区左沿（差 ≤1px）；「本轮 N 条」右沿 = 字段区右沿。
5. 删除键：每张卡一只、28×28、Tab 可达、`aria-label` 带岗位名；点它不开详情。
6. 确认卡：三行文案齐（会删/会留/已有记录提示）、`dismissOnScrim=false`、Esc 可关、关后焦点回删除键。
7. 删后：卡片数 −1、三只计数同步、toast 正确、切 Home 无旧数字、账本三表行数不变。
8. 深/浅两案、200% 缩放、`en` 长文案三档各一张图；同批 `md5 -q | sort | uniq -c` 无重复。

## 9. i18n（双语同批，缺一即 lint 红）

`jd.deleteEntry`（含 `{{title}}`）、`jd.deleteTitle`、`jd.deleteHasRecords`、`jd.deleteRemoves`、`jd.deleteKept`、`jd.deleteCancel`、`jd.deleteConfirm`、`jd.deleted`（含 `{{title}}`）、`jd.deleteGone`、`jd.deleteFailed`（含 `{{code}}`/`{{message}}`）。

## 10. 待验证

- 2 列档单元格 154px 时，`en` 标签（"Company industry" 之类）会不会把标签挤成两行——需要一张 `en` + 408 宽的截图；若挤，2 列档把标签截断为 `truncate` 并在 `title` 气泡里给全文。
- 69 张卡 × 一只删除键的视觉噪音：需要一张 4 列满屏截图人眼判断；若太重，退路是"卡片 hover/focus 时图标才由 30% 变 100%"，但那会牺牲可发现性，**不先做**。
- 28px 在触屏上的命中率：WCAG 2.2 AA 过线（24），AAA 的 44 未达；等真实触屏走查。

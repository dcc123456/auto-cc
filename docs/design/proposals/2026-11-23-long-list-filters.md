# 口径：三张长列表筛选（城市 373 / 行业 145 / 职位类型 158）

- 日期：2026-11-23
- 提出：设计师
- 范围：**交互口径**（怎么展开、怎么搜、多选怎么显示、窄窗怎么落、空态与失效值），可用现有 Tailwind / lucide / Desk 控件实现；不含数据填充（dev 那份 `10.11-32-qa-boss-filter-enums.txt` 是数据来源）
- 约束：不引 UI 库、不新增顶级菜单、不新开浮层体系；按 plan §14.6 的既有裁定——**不赌 DOM 能盖住原生内核视图**，用「几何不重叠」换可用性

## 0. 一句话

**选项 ≤ 12 的维度继续用原生 `DeskSelect`；超过 12 的全换成同一只「原地展开的选择器」——点字段，筛选块就地变成搜索框 + 列表，选完回到筛选块。它不弹层、不遮页、不产生任何跨层关系，主区多宽它就多宽。**

## 1. 分档规则（一条阈值，不按维度名写死）

| 条件                 | 控件                                       | 本轮哪些维度                                                                    |
| -------------------- | ------------------------------------------ | ------------------------------------------------------------------------------- |
| `labels.length ≤ 12` | 既有 `DeskSelect`（原生下拉）              | 区县 16（按 §1 例外走下拉）；经验 9、学历 8、薪资 7、规模 7、融资 9、求职类型 3 |
| `labels.length > 12` | 新的「原地展开选择器」                     | 城市 373、公司行业 145、职位类型 158（后者要等契约加维度，见 §7）               |
| 知识包没声明         | 不上屏（既有规则：不摆"看起来能筛"的控件） | —                                                                               |

- **区县 16 项**：12 < 16 ≤ 12 之外 → 走上档长列表？不。区县是城市的子级，选完城市才出现；16 项原生下拉可接受，且它带序号码（`310104`）不适合搜索。**例外写清楚**：区县固定用 `DeskSelect`，阈值那一条不覆盖子级维度。例外理由：父级已收窄到 16 项，搜索不如扫一眼快。
- 阈值是判断不是实测：12 项以内扫视比输入快；超过 12 项，原生下拉只能靠滚轮找、且**无法搜索**——373 项里用滚轮找"杭州"是罚站。真正启用哪几维，以知识包的 `labels.length` 为准，不按维度名写死。

## 2. 触发行（筛选块里那一格）

```
┌ 城市 ────────────────┐     ┌ 公司行业 ─────────────┐
│ 上海              ▾  │     │ 不限              ▾  │
└──────────────────────┘     └───────────────────────┘
```

- 几何与既有 `DeskSelect` 完全一致：`STACK_LABEL` 11px 标签 + 26px 高字段（`fieldClass(false,'meta')`）+ 右侧 `ChevronDown` 12px。**视觉上它就是一个下拉**，因为人不需要知道背后是原生还是自绘。
- 未选：显示「不限」（沿用 `jd.filterAny`），字色 `slate-400`。
- 已选（单选）：显示 label，`slate-200`，单行 `truncate`；右端出现 12px 的 `X`（清除），仅在已选时出现，点击**不**打开选择器。
- 数据锚点不变：`data-action="jd-filter-<dimension>"`、`data-testid="jd-filter-<dimension>"` 原样保留（QA 与既有验收靠它）。
- 无障碍：它是一个 `button`，`aria-haspopup="dialog"`、`aria-expanded`、`aria-label` 为「城市，当前未选」/「城市，当前上海」。**不要**做成 `role=combobox` 的假输入框——它不接受键盘直接输入，读屏宣布成可搜索按钮才不撒谎。

## 3. 展开：原地替换（不是弹层）

点触发行 → **筛选块那一张卡原地换成选择器**，高度固定，选完换回。用设计稿既有六形态里的**形态③「右栏替换」**，只是替换的是筛选块而不是右栏。

```
┌ ← 城市        已选 1 · 清除 ─────────────┐
│ [ 搜索城市…                          ]   │  ← 打开即聚焦
│ 上海                                     │
│ 北京                                     │
│ 杭州                                     │
│ …（列表区自滚，340px 封顶）               │
│ ── 匹配 3 项 ──                          │
│ [完成]                                   │
└──────────────────────────────────────────┘
```

**为什么不用弹层（Modal/抽屉/Popover）**：三种都撞同一面结构墙，而且这面墙项目已经裁定过（plan §14.6：像素级覆盖实测因屏幕录制权限未取得，按受阻记录；改用几何不重叠），所以不去赌。

- 视口级 `Modal`/`Drawer` 是 `fixed`，矩形必然跨进站点那一栏；能不能盖住**没有实测证据**（§14.6 记的是受阻），按裁定就当盖不住——一个"选城市"的弹窗半截点不到，是最难解释的坏体验。
- `DeskPopover` 从下往上弹（`ui/overlays.tsx` 的 `bottom-full`，为标题栏那一排设计的），落在筛选行会往上盖住页面标题，且不锁焦点、不带滚动容器。
- 原地替换不需要任何层级、不遮左轨/顶栏/底栏、不抢原生视图，主区 420 也成立——而站点分栏时主区正好只有 420。**结构上不存在的缺陷，不必再用测试去证明它不存在。**

**为什么不是"在筛选行下面展开一块"**：那会把「抓取」主按钮推下去；选城市的时候按钮跳走，选完又跳回来，两次都要重新找。原地替换只换一块、位置不变。

**进出与焦点**

- 进入：点触发行 → 焦点落搜索框（不预填当前值，避免"一打开就被过滤"）。
- 单选：点某一行 → 立刻写回、自动返回筛选块（少一步），焦点回原触发行。
- 多选（§5）：点行只切换勾选，点「完成」或 `Esc` 才返回。
- 返回：左上 `←` + 标题；`Esc` 同效。**没有「取消」**：筛选值只影响下一次抓取，不属于要撤销的动作，做两态只会让人以为不点完成就不生效。
- 动画：无。原地切换只靠标题、描边与内容变化表达，避免 0.2s 里两次布局跳动（也让 `prefers-reduced-motion` 少一个分支）。

## 4. 搜索

- 位置：标题行下方，固定不滚（列表自己滚），高 32px（`DeskField` 加一档 `picker` 尺寸，不new一个输入框组件）。
- 匹配：对 label 做 **子串** 匹配，忽略大小写、去首尾空白；**不做拼音**（要额外词典，本轮不引数据，也不许猜「shanghai→上海」）。中文用户用输入法打中文，够用。
- 中文输入法**组字期间不过滤**：`event.nativeEvent.isComposing` 为真时不更新查询串。否则打「上海」时 `shang` 这几下会把列表清空成"没有匹配"，人以为坏了。
- 高亮：命中片段用 `<mark>` 等价的 `<span class="rounded-[2px] bg-amber/20 text-amber-ink">`，只高亮命中的子串，最多高亮前 3 处（避免长 label 花掉）。
- 计数：搜索框右侧 10.5px `slate-400`「匹配 N 项」，`aria-live="polite"`；0 项时不报数字，直接出空态（§6）。
- **不排序**：列表顺序 = 知识包原顺序（那是站点自己的顺序）。中文 `sort()` 按码点排，会得到一份"看起来随机"的名单——宁可不排，也不引入一个没有依据的秩序。
- 清空：非空时搜索框右端一颗 11px「清空」，点击清空并保持焦点。
- 性能：≤ 400 项同步过滤，不做防抖（防抖只会让输入看起来掉帧）。超过 2000 项才谈虚拟列表，本轮不做（§9）。

## 5. 多选怎么显示（口径先定，启用有数据门）

**门**：知识包新增一个可选键 `search.multi`（维度名数组）；只有声明过的维度才允许多选，**未声明一律单选**——站点到底收不收多值，不能由界面猜。已证的一条：经验 `experience=105,104`（QA 从站点 `initParams` 读到，逗号拼）；城市/行业/职位类型**没有多选证据**，本轮按单选。

启用后的显示口径：

| 位置   | 画法                                                                                                                                                                                       |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 触发行 | 只显示「已选 N 项」（N=0 为「不限」）+ 右端 `X` 清全部；**不塞 chips**——筛选格只有 ~180px，塞两个 chip 就把格子撑破                                                                        |
| 摘要带 | 筛选块下方一行「已选：`上海` `互联网` `后端开发` … [清除全部]」；chip = `h-5 / rounded-chip / border-line / bg-ink-750 / 10.5px` + 10px `X`；可换行，最多两行，超出部分「还有 N 项」可展开 |
| 列表行 | 行首 14px 方框（选中 = 青瓷底 + `Check`），整行可点；**已选置顶**成一组（无搜索时），组头 11px `slate-400`                                                                                 |
| 计数   | 标题行「已选 N 项」；N 由数组长度算，不从逗号串 `split`（label 里可能有逗号）                                                                                                              |
| 值     | 渲染层 `Record<string, string[]>`；只在构造 criteria 时 `join(',')`；适配器 `split(',')` 后**逐值查码，任一未知即整条结构化拒绝**（绝不"部分命中先发出去"）                                |

没启用多选前，这三张长列表就是单选：点一行、返回、字段显示那一个 label。**口径不会因为单选就作废**——同一只原件加一个 `mode` 就长出多选，不是第二个控件。

## 6. 空态、失效值、缺码

| 情形                                   | 画法                                                                                                                  | 禁止                       |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| 搜索无结果                             | 「没有匹配「shang」的选项」+「清空搜索」；不画空白列表                                                                | 空白一片                   |
| 维度列表为空（知识包没填码）           | 触发行禁用：`disabledReason="FILTER_NO_CODES"`，气泡文案「知识包还没填这一维的码，暂时筛不了」。不打开选择器          | 打开一个 0 选项的列表      |
| 当前值在当前码表里查不到（知识包换过） | 打开时置顶一行 amber：「当前选中的「X」已不在知识包里，重新选一个」；该值不勾选。触发行显示它但标 `data-stale="true"` | 静默吞掉，让"已筛"继续谎报 |
| 星号：知识包新增了维度但界面没标签     | 不渲染（`filterLabelKey` 兜底「筛选」只防裸 key，不防未知维度）                                                       | 画 `jd.filterLabel.xxx`    |

## 7. 实现接缝（给开发，不是新组件库）

1. **两只原件，放 `ui/controls.tsx`**（与 `DeskSelect` 同族，不新建包）：
   - `DeskFilterField`：触发器。复用 `fieldClass(false,'meta')`、`STACK_LABEL`、`ChevronDown`、`X`，只多 `justify-between` 与 `aria-haspopup`（行数按估算，别当验收数字）。
   - `DeskOptionPicker`：原地面板。组合 `DeskField`（新增 `picker` 尺寸档：`rounded-control px-2.5 py-1.5 text-xs`）+ 滚动列表（`role=listbox`）+ 底栏 `DeskButton`。~120 行。
   - 两者都只用既有令牌（`ink-*` / `line*` / `celadon` / `radius-*` / `focus-visible:ring`），零新 CSS 文件、零新依赖。
2. **渲染位置**：筛选块那张 `section` 内。展开时整块内容换成 `DeskOptionPicker`，不 portal、不 `fixed`、不加 `z-*`。这是**唯一**不需要讨论原生视图层叠的形态。
3. **锚点**（QA 要用，别改名）：`jd-filter-<dimension>`（触发，保留原值）、`jd-filter-search`、`jd-filter-clear`、`jd-filter-done`、`jd-filter-back`、`jd-filter-list`、`jd-filter-option` + `data-label`、`data-selected`；失效提示 `data-testid="jd-filter-stale"`。
4. **i18n**（双语同批）：`jd.picker.searchPlaceholder`、`jd.picker.matchCount`、`jd.picker.empty`、`jd.picker.clear`、`jd.picker.done`、`jd.picker.back`、`jd.picker.selectedCount`、`jd.picker.selectedSummary`、`jd.picker.stale`、`jd.picker.noCodes`。维度名继续走开发正在落的 `FILTER_LABEL_KEY` 显式映射（`city` 已在那张表里）——**这正好是那只映射表该有的下场**：新增维度时 typecheck 逼着补键。
5. **契约**：三张长列表本轮单选，现有 `JobSearchCriteria` 字段都是单值，**不用改契约**。多选要等 `search.multi` 声明与适配器逗号拆分，属于另一片（§5 已给显示口径，数据面一到就接）。
6. **职位类型 158**：它现在不在 `SEARCH_FILTER_DIMENSIONS` 里，接入要同时动「shared 清单 + 知识包 `params` + 契约字段」三处；接入后同一只原件，不用另画。**别为了让它"能看见"先加一个假的维度名**。
7. 城市那一格：把现有自由文本 `jd-city`（`DeskField`）换成这只选择器，但**保留 `data-action="jd-city"` 锚点**；适配器仍按人话查码表，查不到就结构化拒绝的那条不变。
8. `experience` 已被知识包声明（9 码）→ 从自由文本换成 `DeskSelect`，同一行里不留两个写口（现有 `declaresExperience` 分支正好收掉）。

## 8. 窄窗 / 深浅 / 放大

- **窄窗**：选择器就是筛选卡的宽度。主区 440（站点分栏）→ 卡片 ~408，字段 1 列（容器查询 `@2xl` 已按块宽分档），列表行 `min-h-9`、label 单行 `truncate`；不换布局、不出现横向滚动。
- **深浅**：只用令牌。深色 `bg-ink-950` 字段 / `bg-ink-850` 列表底 / hover `ink-750`；浅色同一套变量（毡案），不写第二套 class。选中那一行用 `bg-celadon/10` + 左侧 2px `celadon` 短线（与左轨选中同一语言）。
- **放大 200%**：行高 `min-h-9 + py-1.5`（不是 `h-9`），字变大行自己长高；列表区 `max-h-[min(52vh,340px)]` 兜住；搜索框与底栏不 shrink。
- **触屏**：行 `min-h-9`（36px）< 44。桌面指针为主；Windows 触屏的 44 需求记在待验证，若走查要求，行高提到 `min-h-11` 一行改动，不影响结构。

## 9. 不做项（写清理由）

| 不做                              | 理由                                                                                        |
| --------------------------------- | ------------------------------------------------------------------------------------------- |
| 视口级 Modal / 抽屉 / DeskPopover | 站点开着时被原生视图盖住；Popover 还往上弹（§3）                                            |
| 拼音 / 首字母搜索                 | 要引一份拼音词典，还得为 373+145+158 个 label 建索引；本轮没有这份数据，不猜                |
| 虚拟列表                          | ≤ 400 行一次渲染无压力；引入虚拟化会让"行是否等高/焦点顺序"多出一套约束，收益为 0           |
| 无限滚动 / 分页                   | 数据全在本地知识包，一次给全，滚动就是分页                                                  |
| 「最近使用 / 常用城市」置顶       | 需要第二处状态（localStorage）+ 排序规则；搜索已经够快，先不做。真要做得单独一片，别夹带    |
| 父子分组依赖                      | 知识包给了父子就按父分组（sticky 组头），没给就平铺——**不臆造层级**，同一原件两种数据都能画 |
| 每维一个抽屉 / 每个长维一套控件   | 三张长列表共用同一只原件，第二个实现就是 §2.5 的重复缺陷                                    |
| 选中即触发抓取                    | 筛选只改"下一次抓取"的条件；选完就抓等于替人按了主操作，越过人的表态                        |

## 10. 我认为 QA 最可能挑的三点

1. **「中文输入法组字时列表清空」** —— 应对：`isComposing` 期间不更新查询串；验收用真实输入法打「上海」的拼音串，判据是列表不跳、不出现"没有匹配"；再用一次 `compositionend` 后的提交值过滤。
2. **「打开时焦点在哪、关掉回哪、Esc 会不会把别的浮层一起关」** —— 应对：打开即聚焦搜索框（不预填）；单选点选自动返回并把焦点送回触发行；`Esc` 只返回筛选块。选择器不是浮层，不进 `overlayLayers`，所以不可能和助手面板/抽屉抢 Esc。
3. **「多选明明没实现，触发行却写着'已选 N 项'」** —— 应对：单选维度永远显示具体 label（不显示计数）；计数只在 `mode='multi'` 且确实启用的维度出现。判据：本轮三个长列表的触发行文本必须等于所选 label 或「不限」，不得出现「已选 1 项」。

## 11. 待验证

- 158 项的「职位类型」label 长度分布：若大量 > 20 字，单行 `truncate` 会丢掉区分度，需要改成两行（`line-clamp-2` + `min-h`），这要拿到真数据再定，现在不拍。
- 城市知识包顺序是否对用户有意义（热门在前？）——QA 那份是按站点枚举抓的，顺序未验证；若顺序是随机的，需要一次真人走查再定"是否按人口/热度排"（不在本轮）。
- 36px 行高在 Windows 触屏上的命中率；44 的切换成本已写明，等走查。

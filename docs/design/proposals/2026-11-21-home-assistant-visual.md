# 提案：新壳视觉与交互（Home 总览 + 全局助手）

- 日期：2026-11-21
- 提出：设计师
- 范围：助手悬浮组件的形态与三态、Home 三块的版面与层级、深浅色 / 窄窗 / 键盘 / 避让；**不含**产品职责（PM 提案 `2026-11-21-home-assistant-product.md`）与技术选型（开发提案）
- 配套静态稿：`docs/design/ui-drafts/11-home-assistant.html`（真尺寸画四帧 + 状态条，深浅主题用右上浮标切）
- 依据：现行令牌与控件全部来自 `packages/renderer/src/globals.css` + `ui/controls.tsx` + `ui/overlays.tsx`；不引入 UI 库、不新增顶级菜单

## 0. 一句话结论

**入口是一颗钉在顶栏最右的「助手」胶囊（永远同一点、任何页都在），面板是主区右沿的一块 420px 常驻挂载层，收起只改 `display`、最小化成 48px 的状态条。Home 是三块同高的读数区：4 格数字 + 一条状态行、一块趋势（柱 + 五级漏斗）、一列按状态排序的「接下来」，全部只读既有服务，空白处不画假坐标轴。**

## 1. 先定硬约束：入口为什么不在右下角

内嵌内核网页视图是原生层。按本项目既有实测（AGENTS.md §9 的「harness shot 截不到内核视图」那一族），DOM 永远盖不住它；`App.tsx` 也把站点全屏时的 `deskMain` 整个不渲染（`kernelExpanded ? null : deskMain`）。由此三条推论，直接决定形态：

1. **视口右下角的 FAB 不能用**：没开站点时它在，开了站点它要么被原生层吃掉（点击落进网页）、要么只活在 35% 的左栏里；站点全屏时左栏不存在，按钮跟着消失——恰好是最需要助手的时候。
2. **顶栏是唯一不变量**：站点全屏、窄窗（`--desk-nav-width` 56px）、七屏切换，顶栏都在，且它在原生视图矩形之外（11-06 就是这么把两颗键救回来的）。
3. **面板的定位父级只能是主区 `main`**，不能是视口：`main` 自带 `relative`，面板挂在它里面就天然不会伸进站点那一栏。

所以：**入口固定、面板贴主区右沿**。站点隐藏时二者在屏幕右侧竖直对齐；站点展开时面板落到「站点左侧」，读作"助手坐在它正在干活的那页旁边"。这个不对齐是硬约束换来的，不是审美取舍（开发 spike 若证明独立窗口可行，入口可平移到右下 44px 圆片，**面板规格一个字不用改**）。

## 2. 入口：顶栏「助手」胶囊

位置：顶栏右端最右一格，与 Theme / Language / Kernel / Privacy 同一排，用 1px 竖线隔开——它是这一排里唯一的主行动，其余四颗是系统公用键。

| 项           | 值                                                                                                                | 理由                                                                                                                        |
| ------------ | ----------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 尺寸         | 高 32px（`h-8`），左右内边距 10px，图标 14px + 文字 12px + 间距 6px                                               | 顶栏 41px 高，32 是能放下的最大整档；触屏 44px 的需求见 §8 待验证                                                           |
| 档位         | `solid`（`bg-ink-750` / 悬停 `ink-700`），展开时 `border-slate-600` + 一圈 `celadon-wash` 内描                    | 中性档；**不用 seal**——助手本身不危险，只有"被拦下"才是风险                                                                 |
| 窄窗 <1120px | `NarrowLabel` 收起文字，只留图标（沿用既有写法，不新做断点）                                                      | 与主题/语言/隐私四颗同一口径，标题栏不会被挤爆                                                                              |
| 进行中       | 角标位 8px 青瓷点（静态，无数字）；文案与宽度都不变                                                               | 助手=系统/进行中 → 青瓷；**不做脉冲**（无 `prefers-reduced-motion` 兜底，动效只在开合那一下）。三种角标同占一位，切换不跳版 |
| 需要你       | 角标位琥珀计数（`bg-amber` 10px 字、`h-4 min-w-4`、上限 `9+`），仅计「待确认计划 / 逐条批准 / 执行器待办」        | 与 PM §5.4 一致；普通未读不亮，否则会变成消息中心                                                                           |
| 被拦下       | 角标位朱砂圆点（8px，无数字），风控 / 验证码 / 闸门拒绝时亮                                                       | 朱砂在本项目只给"会离开这台机器"的风险，这里正是风险                                                                        |
| 无障碍       | `aria-expanded` + `aria-controls="assistant-panel"` + `aria-keyshortcuts="Control+J"`；tip 写全「助手（Ctrl+J）」 | 图标键必须有无障碍名；快捷键要在界面上说得出                                                                                |

快捷呼出：**`Ctrl+J`（macOS `⌘J`）**，全局监听，`preventDefault`，在输入框里也生效（带修饰键不会误触）。呼出后焦点直接落进输入卡——"点击就能对话"这件事在键盘上也要一步到位。收起后焦点回到胶囊。

## 3. 面板：三态与规格

面板**常驻挂载**（收起 / 最小化都只改 `display` 与高度，不卸载），与七屏「切换只改 `hidden`」同一口径。两条收益直接对应 PM 的约束：收起不丢输入草稿；正在跑的 run 的订阅不断、重开读的是同一份状态。

| 态     | 几何                                                                                                                            | 画法                                                                                | 进入方式                        |
| ------ | ------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------- |
| 收起   | 不占位（`hidden`）                                                                                                              | 只剩胶囊                                                                            | 胶囊再点一次 / `Esc` / `Ctrl+J` |
| 展开   | `absolute inset-y-3 right-3 w-[min(420px,calc(100%-1.5rem))]`，`rounded-xl`、`border-line-strong`、`bg-ink-850`、`shadow-sheet` | 顶栏即 ChatPanel 的 `ChatSessionBar`（不另加一条标题行），右侧两颗键：最小化、关闭  | 胶囊 / 快捷键                   |
| 最小化 | 同锚点、`h-12`、同宽                                                                                                            | 状态点 + 一行「正在生成第 2 份简历… / 等你确认 2 步 / 已暂停：验证码」+ 展开 + 关闭 | 顶栏那颗最小化键                |

**为什么最小化不直接等于收起**：无人值守的 run 可能跑几分钟，用户要一边看站点一边知道助手在干什么；只剩一颗点，信息量为零。48px 的条是"保留一句状态"的最小成本。

**为什么不做拖拽 / 缩放手柄**（不做项）：面板宽度一旦可拖，就长出第二份几何事实（要落盘、要避让、要跟站点分栏把手抢手势），而 420 已经能放下消息流 + 输入卡；站点分栏的把手就在 8px 外，两个手柄相邻是最典型的误拖现场。

**尺寸出处**：420 沿用抽屉的 420 档（`DRAWER_WIDTH`）——同一族的浮层用同一个宽度，用户不会觉得助手比设置抽屉"更胖"。`min(...)` 兜住主区被站点挤到 440px 时的情况，不需要容器查询。

**层级**：面板 `z-20`。既有层级是 toast 10 < 抽屉 20 < 弹窗 30（`LAYER_*`）；助手层取 20 但**不进焦点环**：它是非模态的（`role="dialog" aria-modal="false"`），背后页面必须还能用——Tab 不被吞、页面不禁滚、不再加一只遮罩。Esc 参与既有层级表（新增一档 `LAYER_ASSISTANT = 15`），只关最上面那只，与纪律表同一条。toast（`z-30`）压在面板之上，因为它是"你刚做的那个动作"的回执。

**面板内部不重画**：消息流、工具卡、计划卡、逐条批准、压缩提示、沉淀卡、档位胶囊、模型胶囊全部复用 `ChatPanel`；只给它一个 `chrome="dock"` 变体——去掉它自己的 `rounded-xl border bg-ink-900/60`（否则面板里套一只面板，出现双框双圆角），顶栏右侧补最小化/关闭两颗。任何"助手专用的新卡片"都不做。

**站点全屏时**：点胶囊 → 先把站点从全屏收回分栏（复用顶栏那颗既有键的同一动作），面板随即有落脚处，并给一条 toast「已把站点从全屏收回，助手需要主区」——状态变化要说得出来，不许静默抢画面；反向不自动回全屏（用户没让你把画面再切走一次）。

**避让规则**（逐条可判）：

- 不盖左轨导航、不盖顶栏、不盖底栏状态条；接管横幅挂在 `main` 之上时，面板 `top-3` 自然落在它下面。
- 不盖内核站点（由"父级是 main"保证，不靠 z-index）。
- 面板开着时页面仍可滚、可点；面板自身滚动，输入卡永远贴底。
- toast 在左下、面板在右上，窄主区时即使叠上，toast 也在面板之上（`z-30 > z-20`）。

## 4. Home：版面

保留左轨第一格的**位置与 key（`chat`）**，只改标签「首页」——harness / 冒烟脚本的凭据不拆（PM §3 已定，设计照此）。Home 自己拥有页首，不再套 `workspace()` 那条 `标题 + 一句话` 的通用头，避免两层标题。

```
┌ 页首（无卡片） ───────────────────────────────────────────────┐
│ 下午好                          [⟳] [问助手 ⌘J] [继续无人值守]        │
│ 近 7 天发出 6 次外发，1 个回复，0 个约面 · 无人值守已授权 1 岗       │
├ 4 格数字（88px） ─────────────────────────────────────────────┤
│ 今日外发 3 │ 待回复 1 │ 已约面 0 │ 今日剩余 7                     │
├ 趋势（8/12） ─────────────────────────┬ 接下来（4/12） ─────────┤
│ 柱：近 7 天每天外发成功数   [7天|30天] │ ① 导入简历 ✓ 已更新 3 天前 │
│ 五级漏斗：搜索 42 / 打招呼 4 / 回复 1  │ ② 搜一轮匹配岗位  ← 现在做 │
│ / 投递 2 / 约面 —（无数据源）          │ ③ 按 JD 定制并投递        │
│ 最近外发 · 3 笔（折叠，默认收起）       │ ④ 授权无人值守 · 1 岗     │
└───────────────────────────────────────┴──────────────────────────┘
```

- 容器：`max-w-[1180px] mx-auto`；块间距 16px（沿用 `gap-4`）；块 = `rounded-xl border border-line bg-ink-900/60 p-4`（与 ChatPanel 同一张卡）。
- 栅格：12 列，`gap-4`；数字行 4×3 列；第二行 8/4。**≥1120px 才分两栏**，窄于此：数字 2×2、趋势与「接下来」各占满一行（自然堆叠，不做第二种布局）。
- 层级：页首招呼 20px/700（宋体）→ 块标题 12.5px/600 → 数字 28px 等宽 → 格标签 11px → 口径 10.5px。只这五档，不再加。
- 数字一律**等宽字体**（`font-mono`），与底栏读数同一族——它让"3 次"和"30 次"不会左右跳。
- 页首右端一颗 icon-only 刷新（`rotate-cw`，30px）：进页读一次 + 既有事件推送已覆盖多数情况，这颗是「我想立刻看最新」的那只手；不加轮询。块级错误态另有自己的「重试」。
- 每格数字下面必须有口径（`近 7 天` / `打招呼 1 · 投递 2` / `日上限 10`），口径随 7/30 切换时跟着变，**不允许一个数字没有口径**。
- 颜色：只读数字 `slate-50`；"现在做这个"用青瓷左轨 + 青瓷图标；完成态 `jade`；等你表态 `amber`；被拦 `seal`。数字本身不上色（避免"红色数字=负数"的误读）。

**三块的分工与不做**

| 块              | 只回答               | 不做                                                                                             |
| --------------- | -------------------- | ------------------------------------------------------------------------------------------------ |
| 4 格 + 2 状态行 | 今天有多少、还剩多少 | 不做"目标完成度 / 转化率"（PM §4.2 已否决，设计同判：小样本比率会撒谎）                          |
| 趋势            | 往哪走、卡在哪一级   | 不叠第二张图（柱与漏斗同源同区间，画两张等于让用户自己对账）；不做悬停详情浮层，读数直接标在柱顶 |
| 接下来          | 下一步点哪           | 不做固定宫格、不做超过 4 条（PM 上限 6，设计收到 4 + 折叠「其余」：一屏能看完的选择才叫少）      |

**与 PM 提案的三处差异（请项目管理合并时裁）**

1. PM §4.1：页首三颗固定入口 + 问助手。设计改为**页首只留一颗动态主行动 + 问助手**，三颗固定入口下沉到「接下来」块。理由：同一页两个"从哪开始"的入口，新手会站在页首犹豫（选择负担），而「接下来」本来就是按状态排序的那一块。
2. PM §4.3：Summary 六格同形。设计改为**4 格数字 + 1 条状态行（无人值守 / 执行器）+ 阻断提示条（未登录 / 没简历 / 没配模型时出现）**；「最近外发」折进趋势块底部。理由：数字与状态不是同形的东西，硬塞进同一排卡片会长出两种卡高；阻断项本身就是入口，放进「接下来」会把"状态"和"动作"混在一起。
3. PM §4.2：趋势块要 7/30 两档 —— **采纳**，控件用 `DeskSegmented` 放块头右侧；数字格的口径文字随档位改（"近 7 天" / "近 30 天"），不做第二套状态。

## 5. 空 / 加载 / 错 / 不可用

空态**替换版面，不装饰版面**：`没有简历 && 没有岗位 && 账本 0 行` 时，Home 不画 4 个 0 与空坐标轴（那读起来像"坏了"），改画一张「三步开张」卡：① 导入简历 ② 搜第一轮岗位 ③ 授权一次投递，三行各带一步直达；底下 11px 一句"做完这些，这里会出现你的进展"。有部分数据时走正常版式，「接下来」的第一条高亮。

| 情形                | 画法                                                            | 禁止                                      |
| ------------------- | --------------------------------------------------------------- | ----------------------------------------- |
| 真的没有            | 该格 `—` + 一句"今天还没有投递" + 入口                          | 写成 `0` 却没有解释                       |
| 服务没挂载 / 读不到 | 该格 `—` + 原因原文（11px `slate-400`）+ 「重试」               | 降级成 0、整页白屏                        |
| 还没读到            | 骨架：数字行 88px、趋势 260px、接下来 3×56px 的**等高占位**     | 先显示 0 再跳变、骨架与终态不等高导致跳版 |
| 权限/前置缺失       | 阻断条（`amber` 描边、一行、右侧一颗直达键），最长同时在屏 1 条 | 堆三条红字                                |

错只坏一块：每块各自有 `Banner tone="amber"` + 重试；一块失败不影响另外两块（读数互相独立）。

## 6. 深浅 / 窄窗 / 放大

- **深浅**：只换 token，不换布局（`data-theme` 已在做）。面板用 `bg-ink-850`（抽屉同层），Home 卡片用 `bg-ink-900/60`（面板同层），线用 `line/line-strong`；浅色下不加重阴影（`shadow-sheet` 已按毡案减淡）。静态稿右上浮标可直接验两案。
- **窄窗**：<1120px 左轨 56px + 胶囊只留图标；面板宽 `min(420px, 100%-24px)`；Home 单列。不做"窄窗另一种布局"，只让同一套栅格重新换行。
- **放大 200%**：所有行高用 `min-h` + `py` 而不是写死 `h`（「接下来」行、数字格、面板顶栏），文字变大时行自己长高；面板宽度由 `min()` 兜住，纵向由 `inset-y` 兜住，消息流滚动、输入卡贴底。检查项：200% 下不出现横向滚动、不裁掉任何一颗键。

## 7. 键盘与读屏

| 项          | 规格                                                                                                                                                                                       |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 呼出 / 收起 | `Ctrl+J` / `⌘J`（全局）；`Esc` 收起（焦点回胶囊）                                                                                                                                          |
| 焦点        | 呼出后落输入卡；面板**不锁焦点**（非模态，背景可用）；关闭后回胶囊                                                                                                                         |
| Tab         | 按 DOM 序：页面 → 面板（面板挂在 main 末尾）。面板内自然顺序，不加 `tabindex`                                                                                                              |
| 读屏        | `role="dialog" aria-modal="false" aria-label="助手"`；胶囊 `aria-expanded` / `aria-controls`；状态点带 `aria-live="polite"`（只在"需要你 / 被拦下"两种变化时播报一句，不播每一段流式文本） |
| 焦点可见    | 两颗新键（最小化/关闭）走 `DeskButton` 的 `focus-visible:ring-2 ring-celadon/70`，不自绘                                                                                                   |
| 减少动效    | 开合只用既有 `animate-rise`（0.22s 一次），加 `motion-reduce:animate-none`；**没有循环动画**，所以不需要"关掉动效"的第二档开关                                                             |

## 8. 交付前自检（逐条）

1. 视觉：对齐靠 12 列栅格与 16px 节奏；层级只用 §4 的五档；正文用 `slate-400`（墨案 6.38:1、毡案 6.55:1，均过 4.5 墙），口径 10.5px 也用 `slate-400` 而不下沉到 `slate-500`（4.64:1 贴线，留给底栏读数）；数字 `slate-50`（16.23:1）。读数见 §10 的实算。
2. 一致性：颜色/圆角/阴影/间距全部用既有 token（`ink-*` / `line*` / `radius-sheet` / `shadow-sheet`）；新控件只有"胶囊"与"状态条"两种，其余全复用 `DeskButton` / `DeskSegmented` / `Banner` / `Card` 写法；状态齐全（默认/悬停/按下/聚焦/忙碌/需要你/被拦/空/加载/错）。
3. 人性化：每块给"下一步"；错说人话并给重试；外发仍在面板内的审批卡上，助手不新增一键确认；收起不丢草稿。
4. 人因：桌面点击区 32×32（顶栏高度所限，触屏 44 待验证）；消息行宽 ~420 内 15px/1.95（沿用既有，字符约 38 个）；柱图读数直接标在柱顶，不要求精细悬停；深浅、键盘、读屏、缩放 200% 都有画法。
5. 边界：超长会话名 `truncate`；空/慢/错/未挂载四态见 §5；多语言：胶囊用短词（zh「助手」/ en「Assistant」），`whitespace-nowrap`，长语言只在 tip 里出现。

## 9. 取舍与不做（汇总）

| 项                  | 决定                   | 理由                                                     |
| ------------------- | ---------------------- | -------------------------------------------------------- |
| 右下角 FAB          | 不做                   | 原生视图层叠 + 全屏时左栏消失（§1）                      |
| 面板可拖拽/缩放     | 不做                   | 第二份几何事实 + 与站点分栏把手抢手势                    |
| 面板遮罩 / 模态     | 不做                   | "在哪都能问、问了能干活"要求背景可用；遮罩等于又一次切页 |
| 助手专属卡片        | 不做                   | 复用 ChatPanel 的计划卡/审批卡，否则会长出第二套审批观感 |
| Home 区间选择器     | 只做趋势块的 7/30 两档 | 更多选择=更重的读前负担；自定义区间留在运行记录页        |
| 转化率 / 目标完成度 | 不做                   | 小样本比率会误导（与 PM 同判）                           |
| 落实习插画 / 渐变   | 不做                   | 与墨案/毡案的克制基调冲突，也不解决问题                  |
| 第二个发送通道      | 不做                   | 红线的视觉层同样不许出现"更快的确认"                     |

## 11. 需要开发注意的实现细节

1. `ChatPanel` 要一个 `chrome="dock"` 变体：去掉自身圆角/描边/底色，顶栏右侧接最小化/关闭两颗；消息流与输入卡**一行不改**。
2. 助手开合状态与「忙碌/需要你/被拦」读数：新建一支 `assistantDock.ts`，照 `deskToast.ts` / `deskStatus.ts` 的模块级 store + 订阅写；**由常驻挂载的 ChatPanel 上报**（它已经在订阅 `agent/run-progress`），胶囊只读。不新开事件通道、不加轮询。
3. `Esc` 复用 `ui/overlays.tsx` 的层级表，新增 `LAYER_ASSISTANT = 15` 且 `node` 传 `null`（只参与 Esc 排序，不接管焦点环）——不要为了助手复制一份键盘监听。
4. 面板必须挂在 `main` 内（`relative` 已有），**不要**改成 `fixed`：那是"被原生视图吃掉"的唯一触发器。
5. 站点全屏 + 呼出助手：走 `KernelCanvasControls` 同一个"退出全屏"动作，别直接改 state；提示走 `pushDeskToast`。
6. Home 的三块各自读、各自降级：不要一个 `Promise.all` 把三块绑成同生共死；读数不落渲染层缓存（`funnel.trend` 已经是主进程按天分好桶的）。
7. 柱图与漏斗条宽度：沿用 `MetricsPanel` 的"离散档类名"写法（`w-[10%]`…），**不许**动态拼 class、不许 `style={{width}}`（§5.1）。建议把现成的 `BAR_STEPS` / `barStepOf` 抽到 `ui/charts.tsx`，Home 与运行记录页共用一份（§2.2）；`MetricsPanel` 随之改为引用它。
8. i18n：新增命名空间 `home.*` 与 `assistant.*`，两种语言必须同批补齐；数字与单位用插值，不拼句。

## 12. 待验证（我没有证据的地方）

- **触屏 44×44**：顶栏 41px 装不下 44 的键。本机是桌面；Windows 触屏笔记本上的实际命中率未测，先按 32 交付，若无障碍走查要求，改成"胶囊下沿外扩 6px 的隐形 hitbox"（视觉不变）。
- **`Ctrl+J` 冲突**：未在真实用户键盘布局（输入法、终端习惯）上验证；待用户走查时确认是否换成 `Ctrl+Shift+J`。
- **12.5px / 28px 数字在 Windows 上的字重观感**：本项目只在 macOS 实测过同一批字号，Windows 未验（AGENTS.md §9 已登记同类 BLOCKED）。
- **面板 420 在主区被拖到 30% 时**（约 376px）是否读起来太窄：需要一次真人走查；当前 `min()` 保证不溢出，但没验可读性。
- **独立窗口兜底方案**下入口搬到右下圆片的观感：等开发 spike 结论再出第二版，不先画。

## 13. 我认为 QA 最可能挑的三点

1. **「站点开着时，顶栏胶囊和面板不在一条竖线上，点击位置和结果对不上」** —— 应对：面板顶栏第一颗就是会话名与状态，且展开时胶囊保持点亮（`aria-expanded`）；站点全屏时先退全屏并给 toast 说明。这条是原生层叠换来的必然结果，写进 §1 的取舍里，评审时要认这条。
2. **「最小化条上的状态是旧的/不动」** —— 应对：状态只从 `agent/run-progress` 与审批待办来，且**面板常驻挂载**所以订阅不断；最小化条不自己数步数、不自己算进度，只显示主进程给的那一句；另补一条反向证据：把面板收起 30s 再展开，消息流与状态连续（不断线）。
3. **「窄窗/放大 200% 下面板压住输入卡或出现横向滚动」** —— 应对：宽度用 `min(420px,100%-24px)`、高度 `inset-y-3`、行高全用 `min-h` + `py`；验收时在 1024×720 与 200% 两档各拍一张，判据是"不出现横向滚动条 + 发送键可见可点"。

**画的过程里逮到的两处**（都是"只有画了才知道"的那一类）：

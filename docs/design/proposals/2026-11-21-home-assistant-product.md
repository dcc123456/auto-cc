# 提案：Home 总览 + 全局智能助手（产品半边）

- 日期：2026-11-21
- 提出：顶尖的产品经理
- 范围：壳层信息架构、Home 三块内容与数据源、助手职责与边界、旧对话页信息安置；**不含**视觉形态、技术实现与排期（分别由设计师、开发出）
- 依据：用户 2026-11-21 方向（对话页实用性不足，改为全局助手；原对话页改为 Home，展示趋势/summary/关键入口）；既有服务口径见 plan §12、spec 10.6～10.10

## 0. 一句话结论

**Home 是「今天该干什么」的总览，助手是「在哪都能问、问了能干活」的入口；两者都不新造数据与执行通道——Home 只读既有 `funnel` / `funnel.trend` / 账本 / 追踪 / 授权 / 执行器的读数，助手只走既有 agent loop 的「计划 → 人确认 → 闸门放行」。**

## 1. 用户要什么（把方向拆成三层）

1. **打开就知道进展**：今天投了多少、还剩多少额度、有没有人在等我、下一步点哪。
2. **不离开当前页就能问**：任何页面能呼出助手，问「这页是什么」「我下一步干什么」，不用回首页。
3. **问了能干活**：让助手去搜岗、定制、准备投递，但**外发这件事仍然要人表态**——这是本项目从第一天起的红线，不因入口变方便而放松。

## 2. 前置与边界（技术未定不影响产品定义）

- 助手能不能盖住内嵌网页视图由开发 spike 实测（DOM 悬浮层 vs 独立窗口）；**产品只要求结果**：任何页面都呼得出、看得见、点得到，包括内核网页视图展开时。
- 助手**不是第二套执行通道**：它调用的每个动作仍走既有 agent loop 与 `entitlement.gate` / `outbound.authorization`；悬浮层只做入口与展示。
- 现有验收锚点不拆：导航第一项仍是同一个位置、同一个 key（`chat`），内容换成 Home；改名等于拆掉 harness 与冒烟脚本的凭据，收益为零。

## 3. 信息架构

| 位置       | 现在                                        | 改后                                                                |
| ---------- | ------------------------------------------- | ------------------------------------------------------------------- |
| 左轨第一项 | 对话                                        | **首页 Home**（同一位置、同一 key，标签改「首页」）                 |
| 其余六项   | 岗位 / 简历 / 流程 / 模型 / 运行记录 / 设置 | 不变（运行记录继续放详细审计与用量）                                |
| 助手的入口 | 无（对话即页面）                            | **全局悬浮**，不占导航项；Home 内再给一个「问助手」按钮作为显式入口 |
| 底栏状态条 | 运行 / 登录态 / 额度 / 档位                 | 不变，读数继续由各服务上报（Home 不重复播报）                       |

**取舍**：不把助手做成第八个导航项——用户要的是"任何页面都能呼出"，导航项必须切页，天然做不到；做成全局浮层则与页面解耦。不加新导航、不改既有六项，避免整壳重排。

## 4. Home：三块 + 顶部三入口

### 4.1 页首（回答「从哪开始」）

一行招呼语 + 三个按钮（与 10.10-05 的首屏三入口同一组，不另立一套）：**导入/更新简历**、**看匹配岗位**、**授权投递**。右侧一个「问助手」按钮（显式入口，和全局浮层是同一份会话）。

### 4.2 趋势块（回答「进展往哪走」）

- 内容：五级漏斗（搜索 / 打招呼 / 回复 / 投递 / 约面）按日趋势，7 天 / 30 天两档；同一图内给「外发成功数」与「失败原因 Top3」。
- 数据源：只读 `funnel.trend`（与 `funnel.query` 同源、同区间口径，按本地自然日切）。
- 空态与不可用：见 §6。
- **不显示任何比率**（转化率、回复率、约面率）：样本量不足时比率会误导，且 5.8 只保证计数口径；要比率等有真实样本后另立判据。

### 4.3 Summary 块（回答「今天能干什么、卡在哪」）

六格，全部只读既有读数、每格给「去哪」的跳转：

| 格         | 显示什么                                                                                             | 唯一数据源                                                     | 服务缺失时                                |
| ---------- | ---------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- | ----------------------------------------- |
| 今日额度   | 投递已用 / 上限 / 剩余（按动作，不合并）                                                             | `funnel.query` 的 `quota`                                      | 「额度服务没启动」+ 原因原文              |
| 无人值守   | 未授权 → 「只建议」；已授权 → 「无人值守：已授权 N 岗」（10.10-04 口径）；暂停 → 原因原文 + 恢复入口 | `outbound.authorization.current`                               | 「授权服务没启动」                        |
| 执行器     | `idle / running / paused / stopped` + 当前岗位 + 完成/待办数                                         | `journey.unattended.view`                                      | 「执行器没启动」                          |
| 岗位进度   | 八态各几岗（只给计数，不给比率）                                                                     | `journey.tracking.list`                                        | 「追踪服务没启动」                        |
| 最近外发   | 最近 5 笔：时间 / 平台 / 岗位 / 动作 / 结果                                                          | `usage.ledger.summary(5)`                                      | 「账本读取失败」+ 原因                    |
| 账号与依赖 | BOSS 登录态（active / expired / unknown）、简历待核对数、模型是否可用                                | `sessions.status`、`resume.parse.pending`、`llm.settings.read` | 各自「未登录 / 待核对 N 处 / 还没配模型」 |

**取舍**：不做「今日目标/计划完成度」这类新指标——没有阈值定义，也没有数据支撑；先用既有计数把事实说清。

### 4.4 关键入口块（回答「下一步点哪」）

按「阻断优先」排序，最多 6 个，每个直达对应页并带上下文（`viewTrail`）：

1. 未登录 → **去登录 BOSS**；2. 没有简历 → **导入简历**；3. 有简历无意向 → **生成求职意向**；4. 已授权未跑 → **继续无人值守**；5. 有失败/暂停 → **看原因**；6. 常规 → **看匹配岗位 / 追踪与统计**（按当前状态二选一）。助手浮层按钮常驻在页首与底栏上方（形态由设计师定）。

**取舍**：入口按状态动态排序，不做固定宫格——新手最缺的是"现在该点哪个"，固定宫格等于把选择题还给他。

### 4.5 刷新与性能

进页读一次 + 手动刷新 + 既有事件推送（外发成功、授权变更、执行器状态变化）时重读；**不加轮询定时器**（沿用「零条定时器」口径）。

## 5. 助手：职责、边界与审批关系

### 5.1 能做什么（六类）

| 类别         | 具体                                             | 落到哪                                                                |
| ------------ | ------------------------------------------------ | --------------------------------------------------------------------- |
| 解释与指路   | 解释 JD/母版/授权/回执等概念，说清「下一步点哪」 | 读同一份服务读数，纯文本回答                                          |
| 带去处的跳转 | 「带我去看这个岗位/这份简历」                    | `viewTrail` 跨视图推进                                                |
| 只读汇总     | 「今天投了几份、谁回了、还剩多少额度」           | 只读 `funnel` / 账本 / 追踪 / 授权                                    |
| 起草计划     | 「按这 3 个岗位准备一轮投递」→ 出计划卡          | `agent.loop.propose`；人确认才执行                                    |
| 执行既有动作 | 搜岗、入库、定制简历、生成招呼、准备投递         | 既有 agent 工具；外发经 `entitlement.gate` + `outbound.authorization` |
| 值守提醒     | 风控暂停、待办未跑、审批待确认、额度用尽         | 读执行器与授权读数，浮层角标提示                                      |

### 5.2 不能做什么（红线，逐条可判）

1. **不能绕过闸门外发**：助手没有第二套外发通道；任何外发都必须经 agent loop → 闸门 → 账本。
2. **不能代签**：计划确认、逐步批准、授权单开启与恢复，只能由人点；助手不得把「上次点过」当作本次许可。
3. **不能自己开/改授权单**：日限额、岗位范围、简历版本只能人设；助手只能把建议写进计划卡。
4. **不能编读数**：服务没挂载就说不可用，不许显示 0 或估计值。
5. **不能存第二份状态**：会话、run、审批、执行进度都归既有服务；浮层关闭不中断，重开读同一份。
6. **不能变成第二套会话/第二套 agent 循环**：复用同一个 chat session 与 agent run。
7. **不能访问真实平台**：自动化仍只打本地仿站，真实平台只由用户在场手验（AGENTS.md §7.2）。

### 5.3 与审批门禁的关系（助手永远比人低一档）

| 档位                 | 助手能做                             | 外发                                      | 备注                      |
| -------------------- | ------------------------------------ | ----------------------------------------- | ------------------------- |
| 只建议（新用户默认） | 解释、跳转、只读汇总、起草计划       | 无；计划卡只给人看                        | 10.10-04 口径             |
| 半自动               | 计划 → 人确认 → 执行；外发前逐步批准 | 人点批准才发                              | 助手不代点确认            |
| 全自动（无人值守）   | 只在**授权单范围内**执行已保存流程   | 受日限额/岗位范围/版本/频控/风控/停用约束 | 越权外发仍为 0（10.6-06） |

### 5.4 呼出与形态（产品约束，细节交设计师）

- 任何页面都在，默认收起；呼出不切页、不卸载当前内容、不打断正在跑的任务。
- 内核网页视图展开时也必须呼得出、看得见（技术方案由开发实测后定，产品不接受"网页开着时助手被盖住"）。
- 收起后不丢输入草稿；未读角标只在「需要你」（待审批、风控暂停、执行器待办）时亮，不做普通消息未读。
- 深色/浅色跟随主题；窄窗下可全屏展开再收回；键盘可呼出与收起（具体键位与 a11y 交设计师）。

### 5.5 取舍

- **为什么不做独立常驻桌面窗口**：先验 z-order；DOM 可行就用 DOM，独立窗口只作技术兜底——产品层的差别只在"是否跟随主窗口"，由开发实测后定。
- **为什么不保留双入口（旧对话页 + 浮层）**：两套入口必然长两套会话状态与两套审批视图，直接违反「不新增第二套」；对话迁移为助手本体。
- **为什么助手不做成万能命令框**：命令框只解决"跳转"，不解决"问了能干活"；干活必须走计划卡与审批。

## 6. 空态与不可用的写法（三态而不是两态）

| 情形                     | 写法                                              | 不允许           |
| ------------------------ | ------------------------------------------------- | ---------------- |
| 真的没有发生             | 「今天还没有投递」+ 下一步入口                    | 写成 0 却没解释  |
| 服务没挂载 / 读不到      | 「统计服务没启动」/「读数失败：<原因原文>」+ 刷新 | 降级成 0         |
| 还没读过                 | 「正在读取…」骨架                                 | 先显示 0 再跳变  |
| 未授权 / 未登录 / 未配置 | 状态 + 一句「要做什么」+ 直达按钮                 | 只给红字不给出口 |

## 7. 旧对话页的信息怎么安置（不丢、不重、不留死入口）

| 旧元素                                         | 新位置                                 | 理由                                                                |
| ---------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------- |
| 消息流、工具卡、运行卡、计划卡、逐步批准       | 助手面板内                             | 它们属于同一次对话与同一次 run，拆开就断上下文                      |
| 会话切换、历史抽屉                             | 助手面板顶部 + 历史入口                | 复用既有会话服务，不新建历史存储                                    |
| 全自动明示                                     | Home 顶部横幅 + 首次授权时提示         | 从「对话发送的前置条件」降为「风险说明」，10.10-01 已要求拆掉三重门 |
| 压缩提示                                       | 助手面板内                             | 与当前会话强相关                                                    |
| 沉淀卡                                         | 助手面板内                             | 属于对话产物                                                        |
| 接管横幅（页面在谁手里）                       | **全局顶栏下方**，任何页可见           | 跨页风险提示，收进 Home 等于在内核网页页看不到                      |
| 底栏状态条                                     | 不变（全局）                           | 已是最小信息密度                                                    |
| M1 求职主链演示原型                            | **退役入口**，实现片按 §2.4 清理死代码 | 10.1 已验收，留着就是死入口                                         |
| 运行记录页的详细审计（会话、指标、追踪、用量） | 保留                                   | Home 只给摘要，详细与审计仍在运行记录页，避免摘要页失守             |

## 8. 拟落的判据（实施时开 spec 10.11，本提案只给草案）

- Home 首屏三入口可点且各到对应页；趋势与 summary 的每个数字都能指回唯一服务口（`funnel.trend` / `funnel.query` / `usage.ledger.summary` / `journey.tracking.list` / `outbound.authorization.current` / `journey.unattended.view` / `sessions.status`），渲染层零自算。
- 三态文案：0 / 不可用（原因原文）/ 未读取，逐格可判。
- 任意页呼出助手：不切页、不卸载、不打断；内核网页视图展开时仍可见可点。
- 助手的每次动作都有计划卡与人的确认记录；越权外发 0（复用 10.6-06 负对照）。
- 旧对话页元素逐项有去处：消息流/审批/工具卡进助手，接管横幅全局，原型退役，运行记录页保留审计。
- 关闭浮层再打开，会话与 run 不丢（读同一份状态）。

## 9. 不做项（汇总，写清理由）

| 不做                       | 理由                                       |
| -------------------------- | ------------------------------------------ |
| 新统计口径 / 新建统计表    | 违反单读数纪律；Home 只读既有服务          |
| 可拖拽/可配置 dashboard    | 无证据需求，成本高，还会让新手面对更多选择 |
| 显示转化率等派生比率       | 样本不足会误导；先给计数                   |
| 助手免审批执行             | 直接踩「未授权外发为 0」红线               |
| 助手作为第八个导航项       | 导航必须切页，与"任何页可呼出"矛盾         |
| 双入口（旧对话页 + 浮层）  | 会长出第二套会话与审批状态                 |
| 万能的自由命令框           | 只解决跳转，不解决"能干活"；且绕过计划卡   |
| Home 展示简历正文/个人信息 | 隐私与脱敏要求；首页不需要                 |
| 首页直接画工作流图         | 流程页已存在，重复且劝退新手               |
| 移动端/窄窗新布局          | 沿用 620px 口径，不做响应式重构            |
| 保留 M1 演示原型入口       | 已完成验收，属死入口                       |

## 10. 需要用户拍板的三处（都有推荐）

1. **Home 是否显示最近 5 笔外发流水**：推荐显示（可审计性对用户是信任来源，且数据已有）。若嫌乱，可折叠成「最近活动」一行 + 展开。
2. **助手角标默认**：推荐只在「需要你」时亮（待审批/风控/待办），不做普通未读——避免变成消息中心。
3. **运行记录页是否保留详细审计**：推荐保留（Home 摘要 + 详细页各司其职），不把审计搬进 Home。
